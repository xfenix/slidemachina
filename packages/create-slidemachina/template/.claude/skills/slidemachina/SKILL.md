# Презентация на slidemachina

Справочник по API: `node_modules/slidemachina/llms.txt`. Прочитай его до первой правки.
Правила подачи с примерами: `references/learning-principles.md`.

## Новый доклад

1. Узнай у пользователя тему, слушателей, длительность и главную мысль. Если чего-то нет, предложи сам и скажи об этом.
2. Набросай тезисы: одна мысль — один слайд. Слайдов примерно столько, сколько минут доклада.
3. Разбей тезисы на 3–7 разделов (`Machina.Section`). Раздел сам даёт обложку с номером.
4. Сделай обложку доклада: `<Machina.Slide cover>` с `h1` и `machina-lead`.
5. Сверстай слайды. Для каждой мысли выбери форму:

| Мысль | Форма |
|---|---|
| Одно утверждение | тезис: `machina-thesis` на `background="var(--accent-soft-color)"` |
| Число или результат | `machina-big-number`, до трёх в ряд в `machina-columns` |
| Перечень | список с `data-steps`, 3–5 пунктов |
| Связи, архитектура, процесс | `Machina.Diagram`, по шагам или с `Focus` |
| Обмен сообщениями во времени | `Machina.Sequence` |
| Было и стало | два слайда с одинаковым заголовком: морфинг покажет разницу сам |
| Код | `Machina.Code` с `lines` по шагам |
| Сравнение решений | `table className="machina-compare"` |
| Пример из жизни, эмоция | картинка `Machina.Image full` или мем `Machina.Meme` |

6. Всё, что докладчик скажет вслух, положи в `<Machina.Notes>`. Заметки к шагу — `<Machina.Notes step={2}>`.

## Правка слайда

- Найди слайд по заголовку в `index.tsx`. Номер слайда для `shot` и адреса — из `npx slidemachina check --json` или по порядку в браузере.
- Меняй только то, что просили. Не переписывай соседние слайды.

## Оформление под бренд

Всё оформление — в `style.css` рядом с `index.tsx`, разметку слайдов не трогай.

1. Цвета: `--accent-color`, `--second-accent-color`, `--text-color`, `--muted-color`, `--slide-background`, `--dark-background`, `--section-background`. Берутся из бренда пользователя: гайдлайна, сайта или логотипа. Если цвета не дали, спроси.
2. Шрифт: файл в `fonts/`, `@font-face`, затем `--font-text`, `--font-heading`, `--heading-weight`.
3. Логотип: `logo={{ light, dark }}` у `Presentation`, место — `logo` у `Slide`.
4. Заголовки, маркеры списка, обложки разделов — обычный CSS. Примеры в `llms.txt`, раздел «Тема».
5. Движение: `transition`, `stepEffect`, `speed` у `Presentation`. Строгому докладу подходят `fade` и `rise`, яркому — `glitch`.
6. Сними обложку, обложку раздела и слайд со списком через `shot` и проверь контраст: текст на фоне должен читаться с дальнего ряда.

## Проверка перед сдачей

1. `npm run check` — без замечаний. Если правило нарушено сознательно, скажи пользователю почему.
2. `npx slidemachina shot <номер>` для каждого изменённого слайда. Посмотри на снимок: ничего не налезает, схема читается, текст не мельче подписей.
3. Покажи пользователю снимки ключевых слайдов и назови, что поменялось.
4. Сборку (`npm run build`) запускай, только если о ней попросили.
