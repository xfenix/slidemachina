# slidemachina vs reveal.js vs Slidev vs open-slide

Measured on October 30, 2026. The scripts are not in the repository yet.

One talk — cover, 3 sections, 18 content slides (21 with section wrappers in reveal), stepped lists, one 15-line code block, one PNG picture, speaker notes — in all four tools. Same text everywhere, generated by `scripts/gen-content.mjs` + `scripts/gen-sources.mjs`.

## Method

- Machine: macOS (Darwin 25.6.0), Node v26.10.0, npm 11.19.1. Nothing else running.
- **install**: `npm install` with a warm npm cache, 3 runs (`rm -rf node_modules` between runs), median. Because the registry was flaky (ECONNRESET / EIDLETIMEOUT), installs used `--prefer-offline --fetch-timeout=600000 --fetch-retries=5` — same flags for all four.
- **dev server**: dev command spawned, page opened in one shared headless Chrome (CDP, `chromium.connectOverCDP`), time from spawn to the cover heading "Slidemachina benchmark" visible. 3 runs, median.
- **build**: production build command, time from spawn to exit code 0. 3 runs, median.
- **output**: total size of the built folder (`du -sm`) and gzip of all `.js` files in it.
- **load**: built output served by a local static server, time to the cover heading visible, and `performance.memory.usedJSHeapSize` right after. 3 runs, median.
- Tools used as their docs recommend: slidemachina (`npm create slidemachina`, JSX in `index.tsx`), reveal.js (plain HTML + `reveal.js` package, bundled with Vite), Slidev (`slides.md` + `@slidev/cli` + `@slidev/theme-default`), open-slide (`npx @open-slide/cli init`, React pages in `slides/benchmark/index.tsx`).

## Notes on fairness and skips

- **slidemachina build** used `slidemachina build --folder` — plain `build` prompts interactively; `--folder` is the documented CI form. The single-file `--html` build was not measured.
- **open-slide dev** starts on a deck-list home page; the measurement navigated directly to `/s/benchmark` (the deck slide), so its dev time is comparable to the others landing on the cover.
- **open-slide has no code highlighting** — the code block is a plain `<pre>` with inline styles. The other three highlight (Shiki at build time for slidemachina, highlight.js for reveal.js, Shiki for Slidev).
- **Slidev** required `@slidev/theme-default` as an extra dependency (the CLI does not bundle a theme); its install time includes it.
- **JS heap** was read right after the first heading became visible; lazy chunks (e.g. Slidev's Shiki, 224 KB) may load after that, so heap numbers are a lower bound.
- **JS gzip** counts all `.js` files in the built folder — a first-slide visitor downloads most of it in every tool, since all four ship one entry chunk plus a few async chunks.
- slidemachina compresses the PNG to WebP in the build; the others ship the PNG as is.
- Slide counts: verified in reveal.js built HTML (21 `<section>`); for the three React tools verified by the load check (cover heading renders) rather than a full slide-by-slide pass.
- Registry flakiness made raw `npm install` fail intermittently; the retry flags above were needed for Slidev and open-slide and applied to all four for fairness.
- Chrome ran as one headless instance for the whole run (`--headless=new --remote-debugging-port=9334 --enable-precise-memory-info`), killed at the end.
