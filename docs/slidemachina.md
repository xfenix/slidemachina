# slidemachina

Движок HTML-презентаций на React. Заменяет reveal.js 4 в презентациях `~/web/private-presentations` и `~/web/conference-presentations/revealjs`.

Этот документ заменяет файлы стадий `docs/stage1.md` … `docs/stage10.md`. Их копии лежат в снимках `/tmp/slidemachina-snapshots/`.

## Что это и для кого

Презентация — один файл `index.tsx` с JSX-разметкой. Рядом `style.css` с темой и папка `images/`.

Движок для тех, кто пишет доклады в редакторе кода и хранит их в git: разработчиков, аналитиков, докладчиков на конференциях. Агент тоже пишет такие презентации: разметка простая, всё в одном файле.

Что умеет:
- разделы, хлебные крошки, навигатор с миниатюрами;
- шаги: списки, таблицы, колонки, части схем и сцен появляются по одному;
- переходы и морфинг: общие элементы соседних слайдов перетекают сами, по словам и по кускам кода;
- код с подсветкой Shiki, строки по шагам, код из файла;
- схемы с автораскладкой ELK и диаграммы обмена сообщениями;
- 3D-сцены на three.js;
- печать в PDF, один HTML-файл, папка, zip, файл под паролем;
- типограф для русского и английского;
- редактор в браузере: текст, картинки и блоки схем правятся на слайде и пишутся в `index.tsx`;
- мемы: шаблоны memegen с подписями-текстом, GIF из GIPHY, вставка по ссылке — с панели, командой или руками;
- репозиторий презентаций с общей темой и списком.

Чего нет: заметок и окна докладчика. В текущих презентациях пользователя нет ни одной заметки.

Название `slidemachina`: в нём есть и слайд, и движок, а через deus ex machina оно связано с театром. На момент выбора имя было свободно в npm и PyPI, на GitHub совпадений не было.

## Как начать

```bash
npm create slidemachina        # спросит: презентация или репозиторий
cd my-talk && npm install
npm run dev                    # то же, что npx slidemachina dev
npm run build                  # то же, что npx slidemachina build: спросит, что собрать
```

Шаблон — 10 слайдов: обложка, раздел, список по шагам, код по шагам, схема, два слайда морфинга, картинка на весь слайд, финал. Тексты шаблона на русском.

### `slidemachina dev`

```bash
slidemachina dev [папка] [--port 5173]
```

- Папка с `index.tsx` — одна презентация на `/`.
- Папка с презентациями — репозиторий: список на `/`, презентация на `/<папка>/`.
- Браузер открывается сам, только если команда запущена в терминале.
- Правка `index.tsx` и любого `.tsx` обновляет слайд без перезагрузки, слайд и шаг остаются прежними.
- Позиция в адресе: `#7` — слайд 7, `#7.2` — слайд 7 после двух шагов.

### `slidemachina build`

Без флагов спрашивает, что собрать. Флаги для CI складываются: `--html --folder --pdf` соберёт три варианта за раз.

| Флаг | Что получится | Файл в `dist/` |
|---|---|---|
| `--html` | Один HTML-файл: скрипты, стили, картинки, шрифты, воркер ELK внутри | `<папка>.html` |
| `--protected` | Тот же файл под паролем | `<папка>-protected.html` |
| `--folder` | Папка для сайта | `<папка>/` |
| `--zip` | Та же папка в zip | `<папка>.zip` |
| `--pdf` | PDF, страница на слайд | `<папка>.pdf` |
| `--steps` | PDF, страница на каждый шаг. Можно без `--pdf` | `<папка>-steps.pdf` |
| `--out <папка>` | Куда положить результат, по умолчанию `dist` | |

- Пароль берётся из `SLIDEMACHINA_PASSWORD` или спрашивается в терминале. Флага `--password` нет: пароль в командной строке виден в списке процессов и в истории.
- Папка работает только с веб-сервера. Для просмотра с диска есть один файл.
- Сборка не пишет в папку, где лежит `index.tsx`: такая папка — исходники, сборка остановится.
- Для PDF и обложек нужен установленный Chrome. Без него сборка пишет, что его нужно поставить.

### `slidemachina meme`

```bash
slidemachina meme "this is fine"           # найти шаблоны memegen, а с ключом GIPHY — и GIF
slidemachina meme --template fine [папка]  # скачать шаблон в images/memes/fine/ и напечатать разметку
slidemachina meme --template fine --animated
slidemachina meme --gif <id> [папка]       # GIF из GIPHY в MP4
slidemachina meme --url <ссылка> [папка]   # картинка, GIF или видео по ссылке, в том числе со страницы
```

- Команда для агентов и терминала. Каждая находка печатается с командой, которая её берёт.
- Скачанное ложится в `images/memes/` презентации. Команда печатает строку импорта, если она нужна, и разметку: блок и `<Source>` со ссылкой на источник. Имена компонентов — как в `index.tsx`: `Machina.Meme` или `Meme`.
- Поиск шаблонов — по id, английскому названию и ключевым словам memegen. Русский запрос шаблонов не найдёт, но GIPHY ищет и по-русски: кириллица в запросе — `lang=ru`.
- Без `SLIDEMACHINA_GIPHY_KEY` поиска GIF нет, команда так и пишет. С ключом рядом с GIF стоит «Powered by GIPHY», как требует GIPHY.
- Ссылка на страницу, а не на картинку, ведёт к картинке из `og:image` или `twitter:image`. Так работают ссылки на Reddit, Imgur и Know Your Meme.
- Тексты — на языке системы, как у остальных команд. Подпись источника — на языке презентации.

## Разметка

Все компоненты берутся одним импортом: `import * as Machina from "slidemachina"`, дальше `<Machina.Slide>`, `<Machina.Image>` и так далее. В таблицах ниже приставка `Machina.` опущена. Именованный импорт `import { Slide } from "slidemachina"` тоже работает.

```tsx
import * as Machina from "slidemachina";
import logoPicture from "./images/logo.svg";
import logoOnDarkPicture from "./images/logo-on-dark.svg";

export default (
  <Machina.Presentation title="Доклад" lang="ru" logo={{ light: logoPicture, dark: logoOnDarkPicture }}>
    <Machina.Slide cover>
      <h1>Доклад</h1>
    </Machina.Slide>
    <Machina.Section title="Раздел">
      <Machina.Slide>
        <h2>Заголовок</h2>
        <ul data-steps>
          <li>Первый пункт</li>
          <li>Второй пункт: <span data-step data-step-effect="highlight">выделено</span></li>
        </ul>
      </Machina.Slide>
    </Machina.Section>
  </Machina.Presentation>
);
```

`index.tsx` экспортирует готовый элемент, функция-компонент не нужна. Большой слайд можно вынести в свой файл и импортировать: настройки `lang` и `typography` он берёт из `index.tsx` своей презентации.

### Каркас

| Компонент | Пропсы |
|---|---|
| `Presentation` | `title`; `lang` (по умолчанию `en`); `align` (`left`, `center` или `right`, по умолчанию `left`); `logo` — строка, `{ light, dark }` или компонент с пропом `dark`; `transition`; `speed`; `breadcrumbsSeparator` — разделитель раздела и подраздела в крошках и навигаторе, по умолчанию `›`; `typography={false}` выключает типограф; `date` (`"2026-10-16"`) — для списка в репозитории; `aspectRatio` — формат слайдов, по умолчанию `"16:9"` |
| `Section` | `title`; `cover={false}` убирает слайд раздела, `cover={<Slide>…</Slide>}` ставит свой слайд вместо стандартного, крошки и навигатор остаются. Вложенный `Section` — подраздел |
| `Slide` | `align` — `left`, `center`, `right`; `valign` — `top`, `center`, `bottom`; `cover`; `background` — цвет или картинка; `tone` (`dark` или `light`); `transition`; `speed`; `plain`; `logo` — `false` или место: `"top-right"` (по умолчанию), `"top"`, `"center"` над заголовком, `"bottom"`; `breadcrumbs={false}` или свой текст; `number={false}`; `className` |

- `Section` сам ставит первым слайд раздела: тёмный фон `--section-background`, крупный номер раздела цвета акцента («02», «02.1»), свечение и зерно. `cover={<Slide>…</Slide>}` ставит свой слайд вместо стандартного.
- `<Slide cover>` — обложка: контент по центру, крупный `h1`, без крошек и номера.
- `align` ставит текст по горизонтали, `valign` — по вертикали. Без `valign` обложка и слайд с `align="center"` стоят посередине, остальные — сверху. Обложка снизу слева: `<Slide cover align="left" valign="bottom">`.
- Посередине контент стоит по буквам: от верха заглавных первой строки до базовой линии последней. Поля сверху и снизу равны, 88 px. Если внизу нет крошек, номера и нижнего логотипа, контент доходит до нижней линии рамки, 64 px.
- Текст справа сверху уходит под логотип: иначе они бы наложились.
- `<Image>` прямо в обложке занимает половину слайда, текст — другую. Картинка перед текстом в разметке стоит слева, после текста — справа. Зазор между ними 64 px, как между колонками. Картинка в натуральную величину, но не больше своей половины. Она прижата к краю рамки и стоит на той же высоте, что и текст: сверху, посередине или снизу. Картинка справа обходит логотип в углу.
- Тон фона движок считает сам по цвету или средней яркости картинки. На тёмном слайде светлый текст и логотип `dark`. Если `dark` не задан, светлый логотип белеет фильтром `--logo-filter-on-dark`.
- `plain` прячет логотип, крошки и номер сразу. Нужен для мема или фото.
- `logo` у слайда — `false` или место: `"top-right"` (по умолчанию), `"top"`, `"center"` над заголовком, `"bottom"`. Нижний стоит на одной линии с крошками и номером, центральный — в потоке контента высотой 96 px.
- `aspectRatio` — пропорция `ширина:высота`: `"4:3"`, `"16:10"`, `"21:9"`, `"9:16"`, `"32:9"`. Формат один на всю презентацию: показ, навигатор, обложка в репозитории, печать и PDF. У отдельного слайда своего формата нет. Тип в TypeScript — `` `${number}:${number}` ``, экспортирован как `AspectRatio`.
- Обе части `aspectRatio` — конечные числа больше нуля. Иначе сборка и `slidemachina dev` останавливаются с сообщением: строку в `index.tsx` проверяет плагин исходников, значение из выражения — сам `Presentation`. Слайды под новый формат движок не перекомпоновывает.
- Публичные имена — простые английские слова. Правило «имена от 8 символов» действует только внутри движка.

### Шаги

- Шаг без номера идёт следующим после всех шагов выше. `step={3}` и `data-step={3}` ставят шаг ровно на номер 3.
- Эффекты: `rise` (по умолчанию: появляется и чуть поднимается), `fade`, `scale`, `highlight`, `dim`.
- Шагом становится любой тег с атрибутом `data-step`: `<li data-step>`, `<p data-step={3} data-step-effect="fade">`. Часть строки — `<span data-step>`.
- `data-steps` на `<ul>`, `<ol>`, `<table>` или `<div className="machina-columns">` делает шагом каждый пункт, строку `<tbody>` или колонку. `data-steps={3}` ставит их на шаги 3, 4, 5. `data-step-effect` рядом задаёт эффект всем пунктам, сам список остаётся видимым.
- Свои `data-step` и `data-step-effect` у пункта сильнее, чем у списка. Можно и не ставить `data-steps`, а расставить `data-step` по пунктам руками.
- `data-steps` раскрывает `markReachedSteps` в `slide-steps/step-visibility.ts`: пункты получают обычные `data-step`, поэтому печать, морфинг и схемы ничего не знают о списках. Записанные атрибуты движок помечает `data-sequence-step` и снимает при каждой разметке: правка `data-steps` без перезагрузки не оставляет старых шагов.
- Строчные теги вроде `span`, `b`, `em`, `a` с шагом получают `inline-block`, иначе не работают `rise` и `scale`.
- TypeScript проверяет значение `data-step-effect` и подсказывает эффекты, `data-steps` принимает `true` или номер.
- При возврате на прошлый слайд он открывается на последнем шаге.

### Блоки

Оформление пишется обычными тегами и классами `machina-…`. Компоненты остались только у блоков с поведением: подгонкой, загрузкой, раскладкой, шагами внутри.

```tsx
<Slide>
  <h2>Числа</h2>
  <div className="machina-columns" data-steps>
    <figure className="machina-big-number">
      <p>8</p>
      <figcaption>переходов между слайдами</figcaption>
    </figure>
    <figure className="machina-big-number">
      <p>1</p>
      <figcaption>файл на всю презентацию</figcaption>
    </figure>
  </div>
  <Source>Источник: замер в октябре 2026</Source>
</Slide>
```

| Компонент | Пропсы |
|---|---|
| `Image` | `src`, `alt`, `stretch`, `full`, `fit` (`contain` или `cover`), `float` (`left` или `right`); внутри — `<figcaption>` |
| `Video` | `src`, `poster`, `stretch`, `full`, `fit`, `loop` (по умолчанию `true`), `controls`; внутри — `<figcaption>` |
| `Source` | только текст внутри |
| `QR` | `value` — ссылка или текст; `logo` — картинка в середине; `correction` (`L`, `M`, `Q`, `H`, по умолчанию `M`); `color`; внутри — `<figcaption>` |
| `Meme` | `template` — id шаблона memegen (`drake`, `fine`, `jd`); `animated` — версия в GIF; внутри — подписи по порядку полей шаблона, каждая своим тегом (`<p>`), и `<figcaption>` |

| Разметка | Что это |
|---|---|
| `<ul>`, `<ol>` | Список. Маркер — шестилучевая звёздочка, вырезанная `clip-path: shape()`, размер 0,5 em. Маркеры и номера висят в поле слева. Их правый край в `--hanging-marker-gap` (0,3 em) от текста |
| `<table>` | Таблица. Шапка — `<thead>`, строки — `<tbody>`. `<th>` в строке — заголовок строки цветом `--table-heading-color` |
| `<table className="machina-compare">` | Сравнение двух–четырёх решений. Первая колонка — критерии, решения делят остальное поровну и стоят по центру, их названия жирные. Отметки — `<td className="machina-yes" />` (галочка цвета акцента) и `<td className="machina-no" />` (серый прочерк) |
| `<div className="machina-columns">` | Колонки. Каждый прямой потомок — колонка |
| `<figure><blockquote>…</blockquote><figcaption>Автор</figcaption></figure>` | Цитата с автором. `<blockquote>` без `figure` — цитата без автора |
| `<figure className="machina-big-number"><p>42</p><figcaption>…</figcaption></figure>` | Большое число с подписью |
| `<figcaption>` вне `figure` | Подпись блока над ней |
| `<p className="machina-lead">` | Вводная фраза: кегль текста, приглушённый цвет |
| `<p>` | Основной текст |
| `<p className="machina-note">` | Пометка мелким шрифтом: кегль и цвет подписи |

- Набор классов взят из старых презентаций: там повторялись подпись (`caption`, 125 раз), источник (`source`, 67), колонки (`two-col`, `raif-columns`), большое число (`bignum`). Кегли — из шкалы темы, новых нет.
- `Image` без пропсов — в натуральную величину, но не больше места на слайде.
- `stretch` — на всё свободное место под заголовком, по центру. По умолчанию `fit="contain"`: видно целиком, скругление и тень обнимают саму картинку.
- `full` — на весь слайд под текстом и рамкой. По умолчанию `fit="cover"`.
- `float="left"` или `"right"` — текст после картинки обтекает её. Картинка не шире `--float-max-width` (40 %). Верх картинки — на линии заглавных букв первой строки рядом. До текста сбоку `--float-gap` (40 px). Снизу столько же, до заглавных букв следующей строки. Маркеры списка висят в этом зазоре, текст сдвигается на их вынос, как в колонках. Блоки после картинки, кроме `p`, `ul`, `ol`, `h3`, встают под неё.
- `<figcaption>` внутри `Image`, `Video` или `QR` — подпись картинки: сразу под ней, от её левого края. С `stretch` картинка уменьшается, чтобы подпись в одну строку встала на нижнюю линию контента.
- `<figcaption>` сразу после `Scene`, `Diagram`, `Sequence`, `Code`, `<table>` или `<figure>` — подпись этого блока: стоит на `--caption-gap` от его края, выровнена по нему. Под сценой подпись по центру: сцена рисует объекты в середине холста.
- `<figcaption>` после другого блока — подпись по левому краю контента. `machina-note` выглядит так же, но не прилипает к блоку над ней.
- `Video` играет без звука и по кругу, пока его слайд на экране. Грузится, когда до слайда два слайда или меньше.
- Колонка — `<div>`, в нём что угодно: несколько блоков встают друг под другом. Один список, абзац или большое число можно ставить колонкой без `<div>`. Блок движка (`Code`, `Diagram`, `Scene`, `QR`, `Image`) кладут в `<div>`: он меряет место по своей колонке.
- Между колонками `--columns-gap` (96 px), полтора поля: соседние колонки читаются отдельно, и маркер или плашка кода, висящие в зазор, оставляют до соседа целое поле.
- Колонки равной ширины. Свои доли — обычным CSS: `style={{ gridTemplateColumns: "3fr 2fr" }}`. У колонок нет минимальной ширины по содержимому, поэтому длинный код не ломает доли.
- `machina-big-number` занимает всю колонку. Число шире колонки уменьшает кегль, но не ниже 64 px. Подгонку делает слайд: `useBigNumberFitting` в `presentation-core/width-fitting.ts` находит числа по классу.
- `Source` — сноска к блокам над ним: стоит сразу под ними, над ним тонкая линия шириной в его текст.
- Кавычки у `<blockquote>` ставит CSS по языку страницы: «…» для ru, “…” для en.
- QR и картинку ставят в левую колонку, текст — в правую. Долю колонки с QR подбирают так, чтобы код занял её по ширине, иначе между кодом и текстом остаётся дыра. В демо — `gridTemplateColumns: "1fr 2fr"`: верх кода на линии заглавных первого пункта, до маркеров 64 px.
- `QR` занимает всё свободное место, как `Image stretch`, и остаётся квадратным. На слайде с `align="left"` стоит от левого края текста, на центрированном — по центру. Колонка с кодом растёт до низа контента.
- Плотность точек задаёт `correction` — уровень коррекции ошибок. Чем он выше, тем больше точек и тем больше повреждений код переживает. Движок берёт самый маленький код для этого уровня и поднимает коррекцию, пока код не растёт: точки крупные, их видно с дальних рядов.
- С `logo` коррекция всегда `H`. Середина кода под логотипом очищается: около 6 % площади.
- Цвет точек — `color` или `--qr-color` в теме. По умолчанию — цвет текста: на тёмном слайде код светлый. Фон прозрачный, рамки и тени нет.

```tsx
<Meme template="jd">
  <p>Извольте вставить мем</p>
  <p>не покидая слайдов</p>
</Meme>
<Source>Шаблон: Joseph Ducreux, knowyourmeme.com/memes/joseph-ducreux-archaic-rap</Source>
```

- Шаблон лежит в `images/memes/<template>/`: `config.yml` и `default.jpg`, `.png` или `.gif`, как в репозитории memegen. Нет папки — `slidemachina dev` и сборка скачивают её сами. Дальше шаблон работает без сети. Свой шаблон — своя папка с такими же файлами.
- Подписи — обычный текст поверх картинки, в полях из `config.yml`: место, размер, поворот, цвет, регистр, выравнивание. Их правит редактор (E), проходит типограф, печать оставляет их вектором.
- Кегль подписи — самый крупный, при котором текст влезает в поле, но не больше девятой части высоты картинки. Так считает и memegen. Подгонка повторяется при наборе в редакторе и после загрузки шрифта.
- Шрифт — Oswald 700, капслок, чёрная обводка под заливкой. Толщина обводки — двенадцатая часть кегля, от 1 до 3 пикселей картинки, как в memegen. У чёрного текста обводки нет, у `font: thin` — Oswald 500.
- Мем занимает свободное место, как `Image stretch`, скругление и тень — как у картинки.
- `animated` берёт `default.gif`. Если GIF у шаблона нет или сети нет, остаётся картинка. Подписи у GIF видны всё время.

### Код

```tsx
<Code src="./agent.py" lines="10-13 | 27-30" numbers />
<Code lang="ts" title="app.ts">{`const answer = 42;`}</Code>
```

| Проп | Что делает |
|---|---|
| `lang` | Язык. Без него — по расширению файла из `src` |
| `src` | Код из файла. Правка файла обновляет слайд без перезагрузки |
| `lines` | Строки по шагам: `"1 | 3-4 | 6"`. Первая часть видна сразу, каждая следующая — шаг. Пустая часть — все строки без приглушения |
| `numbers` | Номера строк слева от кода |
| `title` | Заголовок над кодом. У кода из файла — имя файла |

- Подсветка — Shiki при сборке. В браузер уходят только куски с двумя цветами: для светлого и тёмного слайда. Темы `github-light-high-contrast` и `github-dark-default`.
- Метка в комментарии `# [!code highlight]` подсвечивает строку на весь слайд и не съезжает при правке кода.
- Остальные строки приглушены (`--code-dim-opacity`). Длинный код на шаге плавно прокручивается к подсвеченным строкам, края растворяются.
- Длинная строка уменьшает кегль под ширину, но не ниже 20 px. Дальше строки переносятся с отступом. Горизонтальной прокрутки нет.
- Однострочный код без заголовка — крупная команда 40 px без плашки. У `bash` со знаком `$`, он висит в поле, как маркер списка. Правый край `$` на одной линии с маркерами и номерами списка под командой.
- Номера в `lines` и `numbers` — номера строк исходника. У кода из файла это номера строк файла: файл показывается с первой строки, пустые строки в начале не срезаются. Строка, где была только метка `[!code …]`, пропадает, но номера следующих строк не сдвигаются.
- Номера строк приглушены, у подсвеченных строк — цвет текста. Номера мельче кода: `--code-number-scale` (0,6). Номер рисует CSS (`::before` с `attr(data-code-line)`), поэтому при копировании кода номеров нет. Номер стоит в строке, а не поверх неё: его базовая линия совпадает с кодом при любом кегле.
- Плашка кода висит, как кавычка: её фон и отступ выходят в поле слева, символы кода стоят на линии текста. Правый край плашки — на правой линии рамки. Номера тоже висят в поле. Плашка с номерами стоит в `--code-numbered-edge-gap` (12 px) от края слайда, внутри неё до номеров ещё 12–13 px. От номера до кода `--code-number-gap` (19 px): больше зазора у маркера списка, номера читаются отдельной колонкой. Трёхзначные номера сдвигают код вправо.
- Код задан переменной, а не строкой — плагин его не видит, `Code` покажет текст без цветов.

### Схемы

```tsx
<Diagram>
  <Box id="slides">index.tsx<small>слайды</small></Box>
  <Group id="build" title="Сборка" step>
    <Box id="vite">Vite</Box>
    <Box id="shiki">Shiki</Box>
    <Arrow from="vite" to="shiki" />
  </Group>
  <Arrow from="slides" to="vite" label="HTTP" step />
  <Focus on={["build"]} step />
</Diagram>
```

| Компонент | Пропсы |
|---|---|
| `Diagram` | `direction` (`right` или `down`, по умолчанию `right`) |
| `Box` | `id`, `column`, `first`, `last`, `step`, `effect`; текст внутри, вторая строка — в `<small>` |
| `Group` | `id`, `title`, `step`, `effect`; блоки и стрелки внутри |
| `Arrow` | `from`, `to`, `label`, `id`, `step`, `effect` |
| `Focus` | `on` — список `id`; `step`. Без `on` фокус снимается |

- Раскладку считает ELK в воркере. Порядок блоков в разметке — порядок на схеме. Блок стоит на колонку правее тех, кто на него указывает. `column={n}`, `first`, `last` ставят блок в нужную колонку. В группе колонки считаются от её рамки. Блок не встаёт в колонку блока, который на него указывает: стрелку внутри колонки ELK не рисует. Такой блок уходит на колонку правее.
- Скрытые шаги держат место: раскладка одна на все шаги, блоки не прыгают.
- Стрелка может идти от группы: `from="build"`. Подпись стрелки встаёт над её самым длинным отрезком.
- Фокус приглушает остальное. Выбранный блок получает рамку цвета акцента. Стрелка горит, если выбрана она или оба её конца.
- Схема занимает свободное место: растёт до `--diagram-max-scale` (1,6) и вписывается по ширине и высоте.
- Эффект шага по умолчанию: у блоков `rise`, у групп и стрелок `fade`. Стрелка рисуется от начала, наконечник появляется последним.

### Диаграмма обмена

```tsx
<Sequence>
  <Actor id="vite">Vite</Actor>
  <Actor id="react">React</Actor>
  <Message id="request" from="react" to="vite" label="GET /index.tsx" step />
  <Message from="vite" to="react" label="код" reply step />
  <Focus on={["request"]} step />
</Sequence>
```

| Компонент | Пропсы |
|---|---|
| `Sequence` | только части внутри |
| `Actor` | `id`, `step`, `effect`; имя внутри |
| `Message` | `from`, `to`, `label`, `reply` (пунктир), `id`, `step`, `effect` |

- Участники — колонки, сообщения — строки. ELK здесь не нужен, раскладка на CSS Grid.
- Сообщение самому себе рисуется петлёй.
- Блок схемы перетекает в участника с тем же `id`.

### 3D-сцены

```tsx
<Scene>
  <Cube id="cube" size={1.3} position={[0, 0.65, 0]} material="glossy" />
  <Sphere size={1.1} position={[1.7, 0.55, 0]} color="#F2B8A0" step />
  <Move on="cube" position={[-1.7, 0.65, 0]} rotation={[0, 70, 0]} step />
  <Camera position={[5.5, 3.2, 6.5]} target={[0, 0.8, 0]} step />
  <Text position={[0, 2.2, 0]} size={0.6} step>Готово</Text>
</Scene>
```

| Компонент | Пропсы |
|---|---|
| `Scene` | `orbit` (`true` или градусы в секунду, по умолчанию 8); `floor={false}` убирает тень на полу; `full` — на весь слайд под текстом |
| `Cube` | `size` — число или `[ширина, высота, глубина]`, по умолчанию 1 |
| `Sphere` | `size` — диаметр, по умолчанию 1 |
| `Text` | `size` — высота шрифта, по умолчанию 0,5; текст внутри |
| `Light` | `position`, `color`, `intensity` (по умолчанию 1,6), `step` |
| `Camera` | `position`, `target`, `fov` (по умолчанию 30), `step` |
| `Move` | `on` — `id` объекта; `position`, `rotation`, `scale`, `color`, `step` |

- Общие пропсы объектов: `id`, `position` (`[x, y, z]`), `rotation` (градусы), `scale`, `color` (любой цвет CSS, в том числе `var(--accent-color)`), `material` (`matte`, `glossy`, `metal`), `spin`, `step`.
- Без `<Light>` в сцене один мягкий свет сверху слева. С `<Light>` — только заданные, тень отбрасывает первый.
- Камера без `position` подбирает кадр сама: в кадр входят все места, где объект бывает на любом шаге.
- Объект на своём шаге вырастает из точки. Всё, что движется, плавно догоняет цель.
- При уменьшении движения в системе нет вращения и облёта, шаги переключаются сразу.
- three.js грузится отдельным файлом и только если в презентации есть сцена.

### Морфинг

Два элемента соседних слайдов перетекают друг в друга, если совпали:
- атрибут `morph="имя"` на обоих — работает на любом теге;
- тег и текст у `h1–h6, p, li, blockquote, figcaption`;
- `src` у `img, video, iframe`;
- текст `pre`.

Тексты с общими словами (не меньше половины слов более длинного текста) морфятся по словам: общие слова едут на новое место, ушедшие гаснут, новые проявляются. Блоки `Code` морфятся по кускам кода: сначала совпадают строки, потом куски в изменённых строках. Номера строк не едут, они гаснут и проявляются вместе с остальным текстом блока. Блок схемы морфится в блок или участника с тем же `id`.

Простую фигуру рисует сам слой перехода: фон, рамку, скругление, тень и прозрачность. Так скругление не растягивается вместе со снимком, а плавно меняется от старого к новому. Простая фигура — элемент, у которого всё содержимое морфится своими слоями, например карточка с подписью и столбиками или блок схемы. Остальные элементы морфятся снимком.

## Переходы

`transition` у `Presentation` или `Slide`: `auto` (по умолчанию), `morph`, `slide`, `fade`, `zoom`, `cube`, `flip`, `none`.

- `auto`: если у соседних слайдов есть общие элементы — `morph`, иначе `slide`.
- При листании вперёд берётся переход входящего слайда, назад — уходящего, то есть более позднего из двух.
- `slide`, `zoom`, `cube`, `flip` двигают слайд целиком: с фоном, логотипом, крошками и номером. За слайдами видна сцена `--transition-stage-background`. Сцена занимает только холст: поля по краям окна во время перехода не меняют цвет. `slide` и `zoom` идут внутри холста, как на экране: на 4:3 в широком окне слайд не ждёт в поле и не обрывается на его краю.
- `morph` и `fade` двигают только содержимое. Фон, логотип, крошки и номер стоят на месте. Новый фон с логотипом и номером проявляется поверх старого с 30 до 70 % перехода.
- Стрелка схемы с `morph="diagram-arrow:from:to"` морфится парой с такой же стрелкой на соседнем слайде. Стрелки без пары гаснут и проявляются отдельно. Слой стрелки — её линия с наконечником и подписью, а не вся схема.
- Шаги внутри слайда идут без перехода.
- `speed` у `Presentation` или `Slide` — скорость переходов и шагов: `fast`, `normal` (по умолчанию) или `slow`. Число — во сколько раз быстрее `normal`: `speed={2}` вдвое быстрее, `speed={0.5}` вдвое медленнее. `fast` — 1,5, `slow` — 0,7.
- Как и с `transition`, при листании вперёд берётся скорость входящего слайда, назад — уходящего. Шаги идут со скоростью своего слайда.
- Длительности при `normal`: `--transition-duration` 0,4 с, `--morph-duration` 0,55 с, `--rotation-duration` 0,6 с для куба и переворота, `--step-duration` 0,3 с. Тема меняет их, `speed` делит.
- Если в системе включено уменьшение движения, перехода нет.
- Быстрые нажатия не теряются: прерванный переход доигрывает свой слайд, следующий начинается с него.

## Клавиши и панель

| Клавиша | Что делает |
|---|---|
| →, ↓, PageDown, пробел | дальше |
| ←, ↑, PageUp, Shift+пробел | назад |
| Home, End | первый и последний слайд |
| Esc или O | навигатор |
| цифры и Enter | слайд с этим номером |
| B или . | чёрный экран |
| F | полный экран |
| H | спрятать панель |
| E | редактор, только в `slidemachina dev` |
| Cmd+P или Ctrl+P | печать, когда все схемы и сцены готовы |

Адрес с `?overview` открывает презентацию сразу в навигаторе. Так демо работает витриной всех компонентов. Навигатор сам ставит и убирает `?overview` в адресе, когда его открывают и закрывают, так что ссылку на витрину можно просто скопировать.

- Буквы узнаются по физической клавише, поэтому работают в русской раскладке.
- Клавиши с Cmd, Ctrl и Alt движок не трогает, кроме Cmd+P.
- Мышь не листает. На телефоне и планшете листает свайп.
- Enter без набранного номера работает как обычно, например открывает ссылку в фокусе.

Навигатор — сетка миниатюр по разделам. На 16:9 шесть колонок по 268 px, на 4:3 — четыре, на 9:16 — три. Миниатюры в формате презентации. Выбранная миниатюра обведена `--accent-color-on-dark`: навигатор всегда тёмный. Стрелки двигают выбор по экрану, Enter или клик открывает слайд.

Панель управления — тёмная капсула снизу по центру, на нижней линии рамки. Не масштабируется: кнопки по 44 px на любом экране, подсветка круглых кнопок — диск 36 px внутри. Кнопки:
- «Все презентации» — только у презентации из репозитория;
- навигатор;
- полный экран;
- печать с меню: «Распечатать», «Печатная версия» и переключатель «Раскадровка»;
- в `slidemachina dev`: карандаш редактора, смайлик панели «Мем» и кнопка Agentation;
- скрыть панель.

Панель гаснет сама через 2 с без движения мыши и возвращается при движении или касании. Панель не гаснет, пока мышь над ней, открыто меню печати или окно «Мем», пишется заметка. H прячет панель совсем, на её месте остаётся тёмный кружок со стрелкой. Выбор хранится в `localStorage`.

Agentation гаснет и прячется вместе с панелью: при автоскрытии, после H и на чёрном экране.

### Agentation

[Agentation](https://www.npmjs.com/package/agentation) работает только в `slidemachina dev`. Кликаешь на элемент слайда, пишешь замечание, оно уходит в Claude Code через MCP-сервер `agentation-mcp` на порту 4747. В заметке есть место в файле: `index.tsx:42:7`.

- Страница один раз спрашивает dev-сервер, отвечает ли порт 4747. Сервера нет — заметки хранятся в браузере.
- Кнопка Agentation живёт вне панели, в корне страницы. Движок ставит её над пустым местом в панели и прячет через `visibility`: `opacity` не доходит до её частей в shadow DOM и верхнем слое.
- `SLIDEMACHINA_AGENTATION=off` выключает Agentation. Так запускаются тесты.
- В сборку Agentation не попадает.

## Номер слайда в редакторе кода

Курсор на `<Slide>` или `<Section>` в `index.tsx` — редактор показывает номер слайда и адрес. Презентацию запускать не нужно.

| Курсор на | Подсказка |
|---|---|
| `<Slide>` или другом слайде, например `<BigSlide />` | «Слайд 39 · #39» |
| `<Section>` | «Раздел 07 · слайд 39 · #39»: номер раздела и его первый слайд |
| своём слайде раздела в `cover={<Slide>…</Slide>}` | номер этого слайда |

- Номера те же, что на экране. Движок и подсказка считают по одним правилам: `shared-between-runtimes/slide-outline-rules.ts`.
- Язык подсказки — `lang` у `Presentation`: русский для `ru`, английский для остальных.
- Слайды из выражения `{…}` — условия, массива, переменной — движок считает только при показе. Ниже такого места подсказка пишет, что номер виден только при показе. Слайд из другого файла лучше ставить компонентом `<BigSlide />`: он считается как обычный слайд.
- В файле вынесенного слайда подсказки нет.
- Подсказку даёт плагин TypeScript из пакета `slidemachina`. Шаблон подключает его в `tsconfig.json` строкой `"plugins": [{ "name": "slidemachina" }]` и ставит TypeScript 6 в `devDependencies`.
- VS Code: шаблон кладёт `.vscode/settings.json` с путём к TypeScript проекта. При первом открытии папки VS Code спрашивает, брать ли его. Ответ — «Allow». Встроенный TypeScript VS Code не ищет плагины в `node_modules` проекта.
- Zed: шаблон кладёт `.zed/settings.json`. Zed работает через vtsls, а тот берёт TypeScript проекта, только если заданы `typescript.tsdk` и `vtsls.autoUseWorkspaceTsdk`. Без них vtsls поднимает свой TypeScript и плагина не видит. Проверено запуском vtsls без окна: подсказка «Слайд 1 · #1».
- WebStorm и typescript-language-server в Neovim берут TypeScript из `node_modules` сами. Руками не проверяли.
- В этом репозитории корневой TypeScript — 7, на нём `npm run check`. TypeScript 6 для подсказки и теста лежит в `packages/slidemachina/node_modules/typescript`. На него указывают `.vscode/settings.json` и `.zed/settings.json` в корне репозитория.

## Печать и PDF

- Cmd+P печатает слайд на страницу. Страница — размер холста: 1920×1080 на 16:9, 1440×1080 на 4:3, 1080×1920 на 9:16. `@page size` пишет `<Presentation>` в свой `<style>`: в CSS-файле переменные в `@page` не работают. Фоны печатаются без галочки «Фон».
- Страница печати изолирована `contain: strict`. Без этого несжатая сцена схемы шире вертикальной страницы, и Chrome уменьшал все страницы PDF под неё.
- Диалог печати открывается, когда схемы разложены, сцены нарисованы, а шрифты и картинки загружены.
- «Раскадровка» в меню печати — страница на каждый шаг. Выбор запоминается и работает для Cmd+P и печатной версии.
- Печатная версия — все страницы столбиком в браузере, как в reveal.js. Открывается из меню печати или по адресу `?print`, с раскадровкой — `?print=steps`. Внизу панель: назад к слайдам (Esc), число страниц, «Раскадровка» и «Распечатать».
- `slidemachina build --pdf` печатает печатную версию через Chrome без окна. `--steps` — страница на шаг.
- Не печатаются панель, навигатор, чёрный экран и Agentation.
- В печати нет мягких масок: Preview на macOS рисует их плашками. Блоки схем и картинки печатаются без тени, с контуром. Обрезанный код гаснет под липкими полосами цвета блока кода. Номер раздела — SVG с `linearGradient`. Звёздочку списка вырезает `clip-path`, а не маска: контур в PDF остаётся векторным. Зерна на слайдах-разделах в печати нет: фон слегка осветлён серым, имитирующим зерно.
- Диалог печати и пункт меню браузера ждут метку `data-print-ready`: схемы разложены, сцены нарисованы, шрифты и картинки загружены. Пункт «Печать» в меню браузера даёт только `beforeprint` и может не дождаться трёхмерных сцен.
- Холсты сцен в печати — `image-rendering: pixelated`, чтобы Chrome печатал готовую картинку, а не стирал фон слайда.
- Свечение слайдов-разделов в печати — плотный градиент без прозрачности. Тема хранит отдельные переменные для печати: `--section-printed-background`, `--section-glow-shape`, `--section-glow-strength`, `--section-glow-reach`.

## Сборка

- Один файл: JS и CSS встраивает vite-plugin-singlefile, картинки, шрифты, видео и воркер ELK — data URL.
- Картинки PNG, JPEG и GIF пережимаются в WebP, не больше 3840×2160, качество 82. GIF становится анимированным WebP со всеми кадрами: на GIF демо это 1,2 МБ → 0,3 МБ. Если WebP вышел больше оригинала, остаётся оригинал. Кэш — `~/.cache/slidemachina/pictures`.
- Видео не пережимается. Сборка пишет размер каждого видео, файл больше 50 МБ получает совет собрать папку или zip.
- Шрифты Onest и JetBrains Mono — только латиница и кириллица. Oswald для подписей мемов попадает только в презентацию с `<Meme>`: его подключает плагин исходников в файл с мемом.
- zip: картинки, видео и шрифты без сжатия, файлы в корне архива.
- Файл под паролем шифрует staticrypt. Страница ввода пароля своя, в цветах движка. Зашифрованный файл вдвое больше обычного. Если пароль короче 14 знаков, сборка предупредит.

## Редактор в браузере

В `slidemachina dev` нажать E или карандаш на панели.

| Что | Как |
|---|---|
| Текст | Нажать на текст и печатать. Enter или уход фокуса сохраняет, Esc отменяет |
| Картинка | Перетащить файл на картинку или нажать на неё и выбрать файл |
| Блок схемы | Тянуть мышью в другую колонку или на другое место в колонке |
| Выключить | E или карандаш ещё раз |

- Под курсором — контур и плашка «Текст index.tsx:40». Над панелью — строка состояния: подсказка, «Сохраняю…», «Сохранено», ошибка.
- Правится текст без вложенных тегов. В тексте с вложенной разметкой правится каждый вложенный тег с одним текстом внутри, например `<code>` в ячейке.
- Картинка ложится в `images/` своей презентации, имя латиницей: `My Photo.png` → `images/my-photo.png`. До 80 МБ.
- Блок схемы: в файл пишется `column={n}`, строка блока переезжает на нужное место в разметке.
- Если файл изменили в редакторе кода, правка не запишется: на экране «Файл изменили в редакторе кода».
- Правки встают в очередь: следующая уходит, когда страница получила файл после предыдущей.
- Редактор не попадает в сборку.

### Панель «Мем»

В `slidemachina dev` — кнопка со смайликом на панели. Над ней открывается окно:
- поиск по шаблонам memegen, вкладки «Шаблоны memegen» и «GIF»;
- без ключа GIPHY вкладка GIF пишет, где взять ключ;
- поле для ссылки на картинку, GIF или страницу с ней.

- Выбранный мем встаёт на новый слайд сразу после текущего. Презентация переходит на него. Под мемом — `<Source>` со ссылкой на источник.
- После слайда раздела из `cover={<Slide>}` новый слайд встаёт первым в разделе. На стандартном слайде раздела панель просит открыть обычный слайд.
- Шаблон вставляется с примерами подписей из memegen: по ним видно, какое поле за что отвечает. Подписи правятся на слайде (E).
- Запись — через тот же endpoint правок, что и у редактора, с проверкой версии файла. Скачивание идёт до записи, после него версия проверяется ещё раз.
- Если в `index.tsx` именованный импорт, недостающие `Meme`, `Image`, `Video`, `Source`, `Slide` добавляются в него.
- Миниатюры шаблонов браузер берёт прямо с api.memegen.link, с их водяным знаком. Поиск идёт через dev-сервер: ключ GIPHY не попадает в браузер, страницы с других адресов искать не могут.

- Репозиторий — папка без `index.tsx`, где есть `theme/style.css` или папка с `index.tsx`. Папки на `.` и `_`, `node_modules`, `dist`, `theme` в список не идут.
- CSS по порядку: движок, `theme/style.css`, `style.css` презентации.
- Список в разработке: на карточке живой первый слайд в `iframe`. В сборке — картинка `cover.webp` шириной 960 px. Карточка в формате презентации: сервер читает `aspectRatio` из `index.tsx`, Chrome снимает обложку в окне размером с холст.
- Карточка разворачивается в слайд и сворачивается обратно (cross-document View Transitions). С диска переходов нет.
- Список сортируется по `<Presentation date>`: новые первыми, без даты — в конце по названию.
- Язык списка — язык большинства презентаций.
- `--html`, `--protected` и `--folder` в репозитории вместе нельзя: у каждой презентации один `index.html`.
- Под паролем обложки нет, на карточке «Под паролем».
- Список оформлен как навигатор по слайдам: фон `--navigator-background`, поля рамки (сверху 88 px, по бокам 64 px), заголовок кеглем `--heading-size`, число презентаций приглушённым текстом. Обложки скруглены на `--block-radius`, выбранная карточка обведена цветом акцента, как выбранный слайд в навигаторе. Список всегда тёмный, поэтому рамка — `--accent-color-on-dark`: у темы с тёмным акцентом она не пропадает. Цвета списка задаёт `theme/style.css` репозитория. В `examples/` своего акцента у общей темы нет, рамка фиолетовая, как у движка.
- Под названием карточки — дата, формат, если он не 16:9, и папка: «16 октября 2026 · 4:3 · team-sync». Презентацию 4:3 или 9:16 видно до того, как её откроют.

| Флаг | Файл в `dist/` |
|---|---|
| `--html`, `--protected`, `--folder` | `<папка>/index.html`, у папки рядом `assets/` |
| `--zip` | `<папка>/<папка>.zip` |
| `--pdf`, `--steps` | `<папка>/<папка>.pdf`, `<папка>/<папка>-steps.pdf` |

## Сетка

- Размер холста задаёт `aspectRatio`. Короткая сторона всегда 1080 логических пикселей: 16:9 — 1920×1080, 4:3 — 1440×1080, 16:10 — 1728×1080, 9:16 — 1080×1920. Так кегли и сетка рамки одинаковы в любом формате, в том числе вертикальном: на 9:16 текст 40 px на ширине 1080, как сторис.
- Окно меняет только масштаб. Если пропорции окна и презентации не совпадают, по краям поля цвета `--letterbox-background`. Телефон не переводит горизонтальную презентацию в вертикальную.
- Холст центрируется только через `translate`. Если поставить `left` и `top` в 50 %, Chrome округляет полпикселя, и у края слайда появляется серая линия.
- Поля: бока и низ 64 px, верх 88 px. Поля меряются до видимых знаков: у первого элемента контента и у крошек обрезан интерлиньяж (`text-box`).
- Верх заголовка на линии верха логотипа. Крошки и номер стоят базовой линией в 64 px от низа.
- Логотип справа сверху, крошки слева снизу, номер справа снизу. Логотип `slidemachina` — знак со стопкой слайдов и буквой S в просвете, градиент `#7000d1` → `#007a33`.
- Рамка логотипа — его `viewBox`. У логотипов движка, шаблона и примеров `viewBox` ровно по рисунку, текст переведён в контуры. Поэтому правый край рисунка стоит на линии рамки, верх — на линии верха заголовка. Пустые поля в чужом SVG движок не видит: их убирают в самом файле.
- Текст пунктов списка на линии заголовка, маркеры и номера висят в поле слева. Вложенные списки с отступом.
- Звёздочка, номер списка и `$` команды стоят правым краем на одной линии, в 14 px от текста при кегле 40 px.
- Код тоже на линии заголовка: плашка, её отступ и номера строк висят в поле. На слайде с `align="center"` плашка не висит: линии текста там нет, плашка стоит по центру целиком, номера внутри неё.

## Типограф

Библиотека typograf при сборке: неразрывные пробелы после предлогов и перед тире, тире из дефиса, кавычки, многоточие. Для `lang="ru"` правила `ru` и `en-US`, для остальных — `en-US`.

- Правит текст JSX и строковые пропсы `title`, `label`, `breadcrumbs`.
- Не трогает `Code`, `code`, `pre`, `kbd`, `samp` и строки в `{…}`.
- Номера строк в файле не сдвигаются.
- В браузер typograf не попадает.
- Висячая пунктуация: открывающие кавычки и скобки в начале строки выходят за левый край текста. Буквы остаются на линии сетки. Работает для «, „, ", ' и (. У знака нулевая ширина, он выступает влево. В пробеле перед ним — невидимая копия знака, она возвращает ширину в середине строки. Маркеры и номера списков тоже висят: у списка отрицательный отступ слева, текст пунктов встаёт на линию заголовка. Так же висят плашка кода, номера строк и `$` команды. Колонка со списком или кодом сдвигает содержимое вправо на самый глубокий вынос: маркера или плашки. Зазор до соседней колонки меряется до маркеров и края плашки. Выключает `--hanging-punctuation: 0` в теме, типограф при этом работает.
- `<Presentation typography={false}>` выключает.

```
    code-block/, qr-block/,     компоненты со своими модулями: компонент, его стили и модули, нужные только ему;

  diagram-blocks/               <Diagram> с <Box>, <Arrow>, <Group>, <Focus>; <Sequence> с <Actor>, <Message>; ELK в воркере
  scene-blocks/                 <Scene> с <Cube>, <Sphere>, <Text>, <Light>, <Camera>, <Move> на three.js
  slide-printing/               страницы печати
  source-editor/                редактор в браузере и панель «Мем» (только dev)
  visual-theme/                 порядок слоёв CSS, сетка, тема по умолчанию, шрифты
editor-runtime/                 всё, что работает в редакторе кода: плагин TypeScript с номером слайда
server-runtime/                 всё, что работает в Node
  command-line/                 команда slidemachina: разбор аргументов, выбор варианта сборки, тексты CLI
  development-server/           настройки Vite, модули входа, маршруты, зависимости из установки движка,
                                приём, проверка и точечная запись правок редактора, сохранение файлов в images/, поиск мемов
  meme-sources/                 memegen, GIPHY и ссылки: поиск, скачивание в images/memes/, разбор config.yml, разметка мема
  source-transforms/            проход по .tsx: Shiki, типограф, метки, настройки <Presentation>, шаблоны <Meme>
  presentation-build/           сборка: один файл, пароль, папка, zip, PDF, картинки, обложки
  presentation-repository/      репозиторий презентаций и страница-список
shared-between-runtimes/        чистый JS без зависимостей: общие константы, выбор ru/en и русские формы чисел, размер холста по aspectRatio,
                                правила нумерации слайдов и разделов, типы мемов
```

Публичный компонент — файл `<имя>-component.tsx` (`code-component.tsx` — это `<Code>`) и стили `<имя>-component.css` рядом. Своя папка `<имя>-block/` нужна, только когда у компонента есть свои модули и папка группы без неё разрослась бы: так устроены `code-block/` и `qr-block/`. Остальные компоненты и общие модули лежат прямо в папке группы. Папок из одного-двух файлов и папок с единственной подпапкой нет. Индексных файлов в папках нет.

Правила проверяет dependency-cruiser в `npm run check`, конфиг — `.dependency-cruiser.cjs`. Он же запрещает циклы и модули, которые никто не импортирует:
- `browser-runtime` не берёт код из `server-runtime` и модули `node:*`, а `server-runtime` — модули `browser-runtime`;
- `shared-between-runtimes` не зависит ни от остального движка, ни от пакетов;
- `presentation-core` не зависит от блоков;
- блоки (`content-blocks`, `diagram-blocks`, `scene-blocks`) не зависят друг от друга.

### Как всё устроено

1. `server-runtime/command-line/slidemachina.ts` разбирает команду и описание сайта: одна презентация или репозиторий.
2. Vite получает настройки из `server-runtime/development-server/vite-configuration.ts`. Страницы `index.html` на диске нет: плагин `slidemachina` отдаёт её dev-серверу и сборке.
3. Страница грузит виртуальный модуль входа `/@slidemachina/entry.js` (в репозитории — `/@slidemachina/entry/<папка>.js`). Он подключает CSS движка: сначала `engine-layout.css` и `default-theme.css`, потом все `.css` из `browser-runtime/` (сначала мельче по вложенности, внутри — по алфавиту), потом `theme/style.css`, потом `style.css` презентации, потом `index.tsx`. Стили редактора — только в dev.
4. Плагин `slidemachina-slide-source` из `source-transforms/` проходит по каждому `.tsx` сайта до React: подсвечивает `<Code>` Shiki, типографирует текст, в dev ставит метки `data-source-location`. `<Meme>` получает импорт картинки шаблона и поля из `config.yml`, а файл — импорт шрифта Oswald.
5. `mountPresentation` из `presentation-core/presentation-mounting.tsx` рендерит элемент из `index.tsx`. Горячая замена рендерит новый элемент в тот же корень, слайд и шаг остаются.
6. `<Presentation>` разворачивает разделы в плоский список слайдов, рисует все слайды сразу и ведёт позицию в адресе. Неактивные скрыты через `visibility: hidden` и `inert`: так у элементов есть размеры, а шаги можно посчитать по DOM.
7. Шаги — атрибуты `data-step` в DOM. Слайд размечает достигнутые шаги и шлёт событие `slidemachina-steps`. Код, схемы и сцены по нему ставят подсветку, фокус и позы прямо в DOM, без перерисовки React.
8. Переход — View Transitions API. Движок перед снимком старого слайда и внутри обновления раздаёт элементам имена слоёв, после перехода снимает.

Код Node написан на TypeScript без стёртых типов: Node 26 запускает .ts напрямую, `npm run check` проверяет его тем же `tsc`.

### Ключевые решения

- **Vite 8 внутри CLI.** Собирает на Rolldown и Lightning CSS, 793 млн загрузок в месяц на октябрь 2026 — больше, чем у Rspack и Rsbuild. Пользователь не видит ни `index.html`, ни конфигурации Vite.
- **Пакет публикуется исходниками TypeScript.** Все подключают движок через CLI, а значит через Vite. Шага сборки нет, ошибки показывают на исходник. Цена: `tsc` в проекте пользователя проверяет и движок.
- **Одна папка — одна презентация, вся разметка в `index.tsx`.** Структура папок и есть конфигурация. Репозиторий — те же папки рядом и `theme/`.
- **Все слайды в DOM.** Шаги считаются по DOM, схемы меряют текст, миниатюры и страницы печати — копии тех же слайдов.
- **Шаги, фокус, подсветка строк и позы сцены — атрибуты в DOM, а не состояние React.** Иначе View Transitions снимал бы кадр до прокрутки или подсветки.
- **Переходы на View Transitions без запасного пути на JS.** Браузеры — последние две версии Chrome, Edge, Safari, Firefox. Морфинг по словам — обёртки слов в `span` на время перехода: браузер снимает настоящие слова, без копий шрифта и цвета.
- **Морфинг кода — своё решение на View Transitions**, не shiki-magic-move: блоки лежат на разных слайдах.
- **Подсветка кода и типограф — при сборке, в Vite-плагине.** Shiki, грамматики и typograf остаются в Node. Правки через magic-string, карта исходников точная.
- **ELK лениво и в воркере.** Основной бандл несёт только адрес воркера. Схема просит раскладку, когда до её слайда два слайда или меньше; остальные — через 5 с простоя. Порядок и колонки задаёт разметка, ELK работает в режиме `INTERACTIVE`. ELK всегда раскладывает вправо, `down` получается поворотом координат.
- **Сцены на чистом three.js**, без @react-three/fiber. Один WebGL-контекст на все сцены: браузер сбрасывает контексты сверх ~16. Кадр копируется в 2D-холст сцены, не в `bitmaprenderer`: Chrome печатает только 2D. Тон-маппинг Neutral: ACES и AgX сдвигают насыщенные цвета бренда. Живой только текущий слайд, копии получают один кадр.
- **Печать — копии слайдов.** Кнопка и Cmd+P рисуют копии и ждут метку `data-print-ready`. Пункт «Печать» в меню браузера даёт только `beforeprint`, тогда копии рисуются синхронно. Страницы убираются после печати, по первому нажатию. В печатной версии копии видны, а сами слайды скрыты, но остаются в DOM и считают шаги.
- **Редактор пишет точечно.** Сервер разбирает файл тем же парсером и меняет только нужный кусок. Версия файла защищает правки из редактора кода (ответ 409). Endpoint принимает правки только со своей страницы и только в `.tsx` и `.jsx` сайта, не из `node_modules`, путь через `realpath`.
- **Agentation и редактор не попадают в сборку**: условие `import.meta.env.DEV` стоит внутри `lazy`.
- **Стили движка — только CSS-переменные и `data-*`-атрибуты**, без Tailwind внутри.
- **Пароль только на один файл**: staticrypt шифрует HTML, картинки в папке остались бы открытыми.
- **React Compiler на Rust** (`oxc-transform-react`), для dev и сборки. Версия на Babel заставила бы каждого ставить `@babel/core`. `@vitejs/plugin-react` и `oxc-transform-react` обновляем вместе. Компонент с нарушением правил React компилятор молча пропускает: найти их помогает `react({ compiler: { logDiagnostics: true } })`. `useSlideEnvironments` намеренно исключён через `"use no memo"`: кэш окружений растёт во время рендера.
- **`noUncheckedIndexedAccess` в `tsconfig.json`** вместе с `typescript/no-unnecessary-condition`. Где индекс гарантирован, ставим `!`, иначе проверяем элемент.
- **Оформление — нативные теги и классы `machina-…`, компоненты — только у блоков с поведением.** `List`, `Table`, `Columns`, `Quote`, `BigNumber`, `Caption` убрали: они только рисовали разметку. Подгонку большого числа делает слайд, шаги списков — `data-steps`, правку текста в редакторе и типограф нативные теги получают сами. Цена: колонка с блоком движка требует `<div>`, а доли колонок пишутся CSS.
- **Формат презентации фиксированный, ширина за экраном не следует.** Раньше ширина холста менялась от 4:3 до 21:9 по окну, а PDF был 16:9: на экране и на бумаге слайд выглядел по-разному. Теперь показ, миниатюры, обложки и PDF одинаковые. Режим «ширина по экрану» оставлять не стали: с ним нельзя гарантировать, что автор видит то же, что зал и PDF.
- **Переход целиком идёт внутри холста.** Раньше сцена заливала всё окно, а `slide` двигал слайд на его ширину. На 4:3 в широком окне поля вспыхивали серым, новый слайд с первого кадра стоял в правом поле, а старый в конце пропадал из левого. Теперь сцена — фон холста, у `slide` и `zoom` слой обрезан по холсту. Куб и переворот не обрезаны: им нужна глубина.
- **Код висит в поле, как пунктуация.** Символы кода — на линии заголовка и абзацев, плашка с отступом и номера — в поле. Справа плашка кончается на линии рамки, а не выходит в поле симметрично: у кода с рваным правым краем нет своей линии справа. Опорой служит рамка, на ней же логотип, номер слайда, широкие картинки и таблицы.
- **Простую фигуру при морфинге рисует слой перехода.** View Transitions растягивает снимок по размеру слоя, и скругление растягивается с ним: у столбика 80 → 300 px углы становились овальными и прыгали при смене снимка. Снимки простой фигуры скрыты, фон, рамка, скругление и тень анимируются на `::view-transition-group` с таймингом браузерного ресайза. Элемент с текстом или картинкой внутри так не нарисовать, он морфится снимком.
- **Отметки в таблице сравнения нарисованы CSS, а не набраны символами.** В Onest галочка лежит в подмножестве символов, движок его не грузит: браузер взял бы галочку из другого шрифта. Рамка, повёрнутая на 45°, и полоска печатаются вектором и одинаковы в любой теме.
- **Висячие знаки ровняются по правому краю.** Звёздочка, номер и `$` разной ширины: по центру зазор до текста плясал бы, а «10.» и «9.» и так стоят правым краем. Номер списка рисует `:before`, а не `::marker`: зазор у `::marker` — ширина пробела шрифта, его не задать. Кавычки висят вплотную, без зазора: они часть слова.
- **Стрелка важнее `column`.** Если `column` ставит блок в колонку того, кто на него указывает, ELK сам сдвигает блок вправо. Ширины блоков в колонке тогда считаются по старой колонке, и схема разъезжается. Поэтому движок сдвигает такой блок сам, до ELK.
- **Номера строк мельче кода.** Двузначные номера кегля кода с зазором занимают 50 px из 64 px поля: на отступ плашки и зазор до края слайда остаётся 14 px. Номера в 0,75 кегля оставляют по 12–14 px на зазор до края, отступ плашки и зазор до кода. Плашка без номеров висит на 32 px, ровно на половину поля.
- **Одно скругление на все блоки.** `--block-radius` 12 px у кода, картинок, видео, блоков и групп схем. Раньше было 16, 20 и 24 px, и скругление менялось от слайда к слайду. Группа схемы и блоки в ней скруглены одинаково: отступ группы 24 px больше радиуса, вложенное скругление «внешний минус отступ» тут не работает. Миниатюры в навигаторе и обложки в списке презентаций — тоже слайды, они скруглены на `--block-radius`. Панель и редактор — интерфейс, у них свои скругления.
- **Номер строки — псевдоэлемент, а не текст.** Его не выделяет мышь, его нет при копировании. При морфинге номер не становится куском кода, который переезжает: номера привязаны к строкам, а не к словам. Номер 3 на новом слайде — другая строка, поэтому номера гаснут и проявляются со всем блоком.
- **Номер слайда — подсказка при наведении из плагина TypeScript.** Плагин работает в любом редакторе на tsserver: VS Code, Zed, WebStorm, Neovim. Подсказки в строке (inlay hints) VS Code запрашивает, только если включена одна из настроек `inlayHints`, а по умолчанию они выключены. Наведение работает сразу, поэтому только оно.
- **Плагин лежит в пакете движка, на него указывает `main`.** tsserver грузит плагин через `require` и не читает `exports`, поэтому в `tsconfig.json` хватает имени пакета. Vite и TypeScript берут движок по `exports`, `main` им не мешает.
- **Правила нумерации общие и написаны на TypeScript, плагин компилирует их сам.** Node в редакторе не запускает `.ts`, а файл `.js` в `shared-between-runtimes` потребовал бы `allowJs` в проектах пользователей. Плагин прогоняет `slide-outline-rules.ts` и `text-language.ts` через `transpileModule` TypeScript редактора.
- **TypeScript 6 в шаблоне.** TypeScript 7 нативный и на октябрь 2026 плагинов не поддерживает. 6.0 — последняя версия на JavaScript, её же встраивает VS Code 1.141.
- **Вертикаль — отдельный проп `valign`.** `align` уже значит горизонталь у `Presentation` и `Slide`. Пара `align` + `valign` знакома по HTML и не требует составных значений вроде `"bottom-left"`.
- **Картинку на обложке ставит порядок в разметке, а не проп.** `<Image>` до текста — слева, после — справа: что видно в коде, то видно на слайде. Картинка вынута из потока (`position: absolute` в своей колонке сетки), поэтому не растягивает строки текста.
- **С `float` содержимое слайда переходит в блочную раскладку.** Во flex-колонке `float` не работает. Поля между блоками только нижние, поэтому отступы не меняются.
- **Мемы — memegen, подписи — HTML-текст.** У memegen 211 шаблонов с координатами полей в `config.yml`, код под MIT, ключ не нужен. Готовую картинку с подписью мы не берём: её нельзя править на слайде, типографировать, печатать вектором. Поэтому подписи рисует слайд по полям шаблона.
- **Другие источники отвергли.** Tenor API закрыт 30 июня 2026. Klipy запрещает хранить файлы у себя. У Imgflip поиск платный, а подписи с водяным знаком. Reddit, r/ProgrammerHumor и Мемепедию поддерживает вставка по ссылке, своего поиска по ним нет.
- **Шаблоны не лежат в пакете.** 211 картинок весят десятки мегабайт, а нужны единицы. Шаблон скачивается по запросу в папку презентации и дальше живёт в git вместе со слайдами. Картинка — с GitHub memegen, без водяного знака, список — с api.memegen.link. Тесты подменяют оба адреса через `SLIDEMACHINA_MEMEGEN_ADDRESS`, GIPHY — через `SLIDEMACHINA_GIPHY_ADDRESS`.
- **`config.yml` читается без библиотеки YAML.** У всех 211 файлов одна плоская форма: ключ и список пунктов. Своё чтение — около 40 строк, сверено с PyYAML на всех шаблонах. Библиотека добавила бы зависимость ради одного файла.
- **Подписи — дочерние элементы, а не проп `text={[…]}`.** Тег с текстом редактор правит сам, типограф обрабатывает, `<figcaption>` рядом работает как у картинки. Строки в массиве не прошли бы ни через то, ни через другое.
- **Oswald вместо Impact.** Impact — шрифт Microsoft, положить его в пакет нельзя. Oswald — такой же узкий и жирный, под SIL Open Font License, есть в `@fontsource-variable`. Шрифт memegen по умолчанию кириллицы не знает.
- **GIF из GIPHY — MP4 через `<Video>`.** MP4 в разы легче GIF, а у `Video` уже есть пауза вне слайда и печать. GIPHY — только с ключом: без него API не отвечает, бесплатный ключ даёт 100 запросов в час. Повторный запрос берётся из памяти dev-сервера.
- **Мем встаёт новым слайдом.** Встроить его в чужую раскладку слайда панель не может, а пустой слайд с мемом сразу выглядит готовым. Поэтому `Slide` получил метку места в исходнике, как блок схемы.
- **GIF печатается первым кадром**, отдельный `poster` у `Image` не делали: Chrome сам берёт первый кадр, этого хватает.
- **Нативные теги вместо ролей**: навигатор — `<dialog open>`, статус редактора — `<output>`. Навигатор открывается без `showModal()`: верхний слой вышел бы из-под масштаба холста. Esc и O закрывают его своим обработчиком.

### Тесты

Юнит-тестов нет. Четыре интеграционных теста, по одному (`workers: 1`):
- `tests/presentation-core.spec.ts` — демо целиком: листание, шаги, навигатор, переходы, морфинг, схемы, код, сцены, подписи мема в полях шаблона, панель и Agentation, правка файлов, формат 16:9 по умолчанию и 9:16 с полями, вёрстка демо на 4:3. Ещё он поднимает tsserver на настоящем `index.tsx` демо и проверяет, что подсказка редактора называет тот же номер, что угол слайда.
- `tests/presentation-build.spec.ts` — все варианты сборки, PDF, что в бандл не попали ELK, three.js, Agentation и редактор, что GIF стал анимированным WebP.
- `tests/source-editor.spec.ts` — редактор на копии демо. Там же мемы: тест поднимает локальную подмену memegen и страницу с GIF. Без шаблона в копии dev-сервер скачивает его сам. Панель вставляет слайд с шаблоном и слайд с картинкой со страницы. Команда `meme` ищет шаблон и печатает разметку.
- `tests/presentation-repository.spec.ts` — репозиторий на копии `examples/`: список из трёх презентаций, обложки, тема, сборка. `team-sync` в формате 4:3: тест проверяет подпись «4:3» на карточке, обложку 960×720, страницы PDF 1080×810 pt и ошибку сборки на `aspectRatio="4:0"`.

Тесты поднимают свои dev-серверы на копиях во временной папке: 5199 для демо (копию всей папки `examples/` делает `playwright.config.ts`), 5198 для редактора, 5197 для репозитория. Настоящие файлы демо тесты не правят. Общие помощники — `tests/test-helpers.ts` и `tests/scene-sampling.ts`. `npm run check` — `tsc --noEmit` с `noUnusedLocals` и `noUnusedParameters`, Oxlint с проверкой по типам и проверка правил раскладки.

## Ограничения и что осталось

Движок и слайды:
- Нет заметок и окна докладчика.
- Нет точных координат `x/y` у блоков схемы.
- Нет морфинга по буквам: «3.14» → «3.15» перетекает словом целиком.
- У `Code` нет явной пары для морфинга, `Code` не морфится с обычным `<pre>`.
- У `Group` нет своей `direction`.
- Стрелка морфится в стрелку с теми же `from` и `to` целиком: при новом маршруте старая гаснет, новая проявляется. `Message` не морфится.
- Нет двусторонних и пунктирных стрелок в `Diagram`.
- Подпись стрелки может задеть соседнюю стрелку.
- Ошибка ELK видна только в консоли, схема остаётся пустой.
- Схема не растёт больше своего размера: текст в ней всегда 28 px. Широкие схемы на 4:3 и 9:16 уменьшаются, на 9:16 сильно: схема сама не меняет направление на вертикальное.
- Кавычки, разорванные элементом (`"<b>слово</b>"`), typograf не исправит.
- `$` команды в правой колонке висит в зазор между колонками: колонка сдвигается на вынос плашки и маркеров, но не команды.
- Номера строк из трёх цифр не помещаются в поле: код с ними сдвигается вправо от линии текста на 12 px.
- Висят символьные ячейки, а не глифы. Глифы JetBrains Mono стоят посередине ячейки, поэтому видимый край кода правее видимого края абзаца на 0–2 px, в зависимости от буквы. У заголовка разброс от буквы к букве больше: от 0,5 до 4 px.
- 3D: нет стекла, точечного света и прожектора. Объекты сцены не морфятся между слайдами. Текст сцены всегда смотрит вдоль оси z и не отбрасывает тень. Потерю WebGL-контекста движок не обрабатывает.
- Где нет `view-transition-class`, ушедшие и новые слова гаснут и проявляются одновременно.
- При переходе между светлым и тёмным слайдом фон в середине на мгновение серый.
- Полосы над обрезанным кодом на тёмном слайде считаются от `--dark-background`. На тёмном слайде с другим фоном они чуть другого цвета.
- Вертикальный формат 9:16 не перекомпоновывает слайды: колонки, широкий код и схемы остаются горизонтальными и сжимаются.

Сборка и шаблоны:
- Пакеты не опубликованы в npm. `create-slidemachina` ставит `slidemachina@^0.1.0`.
- Видео не пережимается. Картинки из `url()` в `style.css` тоже.
- Предел картинок в сборке — 3840×2160. Для вертикальной презентации картинка на весь слайд выходит 2160 px в высоту, а не вдвое больше холста (3840).
- Папка сборки не открывается с диска, только с веб-сервера.
- Шаблон `npm create slidemachina` только на русском.
- Подсказка номера слайда не работает на TypeScript 7 и с `js/ts.experimental.useTsgo` в VS Code: нативный TypeScript не грузит плагины. VS Code один раз спрашивает разрешение на TypeScript проекта.
- Подсказка не видит номер слайда в его собственном файле и после выражения `{…}` среди слайдов. Число шагов слайда она не показывает.
- `style.css` или `theme/style.css`, созданный при запущенном `slidemachina dev`, подключится после перезапуска. После обновления `server-runtime/` dev-сервер тоже нужно перезапустить.
- Изменённые `lang` и `typography` применяются к слайдам из других файлов после их следующей правки.
- `.tsx` из `theme/` типографируется по правилам английского.
- Удалённые презентации остаются в `dist/` до ручной очистки.
- Презентация в папке `assets` столкнётся со стилями списка.
- Обложкам и PDF нужен Chrome. Без него в списке только названия.

Редактор:
- Строковые пропсы (`title`, `label`, подпись стрелки) не правятся.
- Текст с вложенной разметкой целиком не правится.
- Блок нельзя перенести в другую группу, из группы наружу и левее первой колонки.
- Блок можно бросить в колонку блока, который на него указывает. В файл запишется `column`, но блок останется правее.
- Видео не меняется, только картинки. Части сцены не правятся.
- Нет отмены через Cmd+Z: отменяет редактор кода или git.
- «Ёлочки» и длинное тире типографа попадают в исходник при правке текста.
- Перетаскивание на сенсорном экране не проверяли.

Проверки:
- Safari и Firefox руками не проверяли: Cmd+P, сцены, `view-transition-class`.
- Сцена на 4:3 и `full` на тёмном слайде тестом не покрыты.
- Тест сцены проверяет пиксели холстов печати, а не картинки в PDF.

Перенос с reveal.js — план без конвертера. Агент переносит по одной презентации в папку репозитория:
- `class="fragment"` → `data-step`;
- `data-line-numbers` → `lines`;
- Mermaid → `Diagram` или `Sequence`;
- копии слайдов для шагов схемы → один слайд со `step`;
- `data-background-color` → `background`.

Тему `generic-raif.css` переносят в `theme/style.css`, шрифты ALS Hauss и Navigo — в `theme/fonts/`. Шрифты бренда платные и в npm не попадают.

Мемы:
- Картинки шаблонов принадлежат их авторам: лицензия MIT memegen касается кода, а не картинок. В демо — шаблон `jd`: автопортрет Жозефа Дюкре конца XVIII века, это общественное достояние. Остальные шаблоны в демо не кладём.
- Нет оверлеев memegen: картинок, которые шаблон вклеивает поверх.
- Подписи GIF-шаблонов видны всё время: тайминги `start` и `stop` из `config.yml` не поддержаны.
- Стили `default` (заглавная первая буква) и `mock` (рЕгИсТр через букву) не поддержаны: текст остаётся как написан.
- В PDF обводка подписи — второй проход того же текста. При копировании из PDF буквы подписи удваиваются.
- Поиск шаблонов — только по английским названиям memegen. Перевода запросов нет.
- Миниатюры в панели грузятся с api.memegen.link: без сети панель шаблоны не найдёт, а вставленные раньше мемы работают.
- GIPHY проверен на подмене API по документации, с настоящим ключом — нет. «Powered by GIPHY» — текстом, не официальным логотипом.
- Видео со ссылки и из GIPHY не пережимается, как и любое видео.

Прочее:
- Имя `slidemachina` не занято в npm публикацией. Домен и товарный знак не проверены у регистратора. Папка проекта называется `presentation-engine`.
- Знак не копия, но мотив стопки слайдов есть у Slideshare, а название близко к `harmsm/slidemachine` (генератор reveal.js). Срочно менять знак не нужно. Для большей самостоятельности менять силуэт, а не цвет.
- `<figcaption>` вне `<figure>` — подпись блока. Браузеры его показывают, но валидатор HTML на него ругается. Обернуть блок в `<figure>` нельзя: блоки растут внутри `[data-content]`, лишний уровень сломает подгонку.
- Картинка с `float` в колонке: если она выше текста, колонка растёт на её нижний отступ. На уровне слайда отступ ничего не раздвигает: высота области контента задана.
- `valign` не работает на слайде с `float`: содержимое там в блочной раскладке.
- Картинка на обложке — только `<Image>` или `<Video>` без `stretch` и подписи. Подпись встанет в колонку текста.
- `align="right"` рассчитан на текст и обложки. Код, схемы и сцены под него не настраивали.
- Элемент с текстом, картинкой или своим фоном внутри морфится снимком: его скругление при морфинге растягивается.
- Таблица сравнения не ограничивает число решений: пять и больше колонок сжимаются.
- Блок движка прямо в `machina-columns`, без `<div>`, раскладывается неверно: код меряет место по родителю, схема и сцена растут во flex-колонке.
