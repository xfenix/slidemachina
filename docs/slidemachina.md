# slidemachina

Движок HTML-презентаций на React. Заменяет reveal.js 4 в презентациях `~/web/private-presentations` и `~/web/conference-presentations/revealjs`.

В документе итог стадий 1–44 и 46, в том числе вторых 36 (переносы) и 37 (скрытые слайды). Файлы стадий удалены, их история — в git.

## Что это и для кого

Презентация — один файл `index.tsx` с JSX-разметкой, рядом `style.css` с темой и папка `images/`.
Движок для тех, кто пишет доклады в редакторе кода и хранит их в git. Агенту такие презентации тоже писать просто: всё в одном файле.

Что умеет:
- разделы, хлебные крошки, обзор слайдов с миниатюрами, полоса прогресса;
- шаги: пункты списков, строки таблиц, колонки, части схем и сцен появляются по одному;
- переходы и морфинг: общие элементы соседних слайдов перетекают сами, по словам и кускам кода;
- код с подсветкой Shiki, строки по шагам, код из файла;
- блок-схемы с автоматической раскладкой ELK и sequence-диаграммы;
- 3D-сцены на three.js;
- один HTML-файл, файл под паролем, папка, zip, PDF, PowerPoint;
- типограф для русского и английского;
- слайд-тезис в одну фразу, фон из видео, GIF или веб-страницы, блок поверх вёрстки;
- хуки для своего кода: `useSlide()`, `onEnter`, `onLeave`, `onChange`;
- свайп и касание на телефоне и планшете;
- редактор в браузере: текст, картинки, блоки схем и слайды правятся на слайде и пишутся в `index.tsx`; мини-карта слайдов;
- мемы: шаблоны memegen, GIF из GIPHY, картинка по ссылке — с панели, командой или руками;
- репозиторий презентаций с общей темой и списком.

Название — от слайда и deus ex machina.

## Как начать

```bash
npm create slidemachina        # спросит: презентация или репозиторий
cd my-talk && npm install
npm run dev                    # то же, что npx slidemachina dev
npm run build                  # то же, что npx slidemachina build: спросит, что собрать
```

Шаблон — 10 слайдов на русском: обложка, раздел, список по шагам, код по шагам, схема, два слайда морфинга, картинка на весь слайд, финал.

### `slidemachina dev`

```bash
slidemachina dev [папка] [--port 5173]
```

- Папка с `index.tsx` — одна презентация на `/`. Папка с презентациями — репозиторий: список на `/`, презентация на `/<папка>/`.
- Браузер открывается сам, только если команда запущена в терминале.
- Правка любого `.tsx` обновляет слайд без перезагрузки, слайд и шаг остаются.
- Адрес: `#7` — слайд 7, `#7.2` — слайд 7 после двух шагов.

### `slidemachina build`

Без флагов спрашивает, что собрать. Флаги для CI складываются: `--html --folder --pdf` соберёт три варианта.

| Флаг | Что получится | Файл в `dist/` |
|---|---|---|
| `--html` | Один HTML-файл: скрипты, стили, картинки, шрифты, воркер ELK внутри. В `<noscript>` — снимки слайдов для Quick Look | `<папка>.html` |
| `--protected` | Тот же файл под паролем | `<папка>-protected.html` |
| `--folder` | Папка для сайта | `<папка>/` |
| `--zip` | Та же папка в zip | `<папка>.zip` |
| `--pdf` | PDF, страница на слайд | `<папка>.pdf` |
| `--hidden` | Добавить скрытые слайды в `--pdf`, `--steps`, `--pptx` | |
| `--steps` | PDF, страница на шаг. Можно без `--pdf` | `<папка>-steps.pdf` |
| `--pptx` | PowerPoint: текст, фигуры, стрелки — объекты, шаги — анимации по щелчку | `<папка>.pptx` |
| `--out <папка>` | Куда положить результат, по умолчанию `dist` | |

- Пароль берётся из `SLIDEMACHINA_PASSWORD` или спрашивается в терминале. Флага `--password` нет: пароль в командной строке виден в списке процессов и в истории.
- Папка работает только с веб-сервера. С диска открывается один файл.
- В папку с `index.tsx` сборка не пишет: это исходники.
- PDF и обложкам нужен установленный Chrome. Без него сборка так и пишет.

### `slidemachina meme`

```bash
slidemachina meme "this is fine"           # найти шаблоны memegen, а с ключом GIPHY — и GIF
slidemachina meme --template fine [папка]  # разметка мема с картинкой шаблона по ссылке
slidemachina meme --template fine --local  # то же, картинка сохранится в images/memes/fine.jpg
slidemachina meme --template fine --animated
slidemachina meme --gif <id> [папка]       # GIF из GIPHY в MP4
slidemachina meme --url <ссылка> [папка]   # картинка, GIF или видео по ссылке, в том числе со страницы
```

- По умолчанию мем ссылается на картинку в интернете: `src="https://…"`. `slidemachina dev` берёт её оттуда, сборка скачивает и встраивает. `--local` кладёт файл в `images/memes/` и пишет импорт.
- Команда для агентов и терминала: каждая находка печатается с командой, которая её вставит. Разметка — блок с `<figcaption>`-ссылкой на источник, имена компонентов как в `index.tsx`: `Machina.Meme` или `Meme`.
- Шаблоны ищутся по id, английскому названию и ключевым словам memegen. GIPHY ищет и по-русски: кириллица в запросе — `lang=ru`.
- Без `SLIDEMACHINA_GIPHY_KEY` поиска GIF нет, команда так и пишет. С ключом рядом с GIF стоит «Powered by GIPHY»: этого требует GIPHY.
- Ссылка на страницу ведёт к картинке из `og:image` или `twitter:image`. Так работают ссылки на Reddit, Imgur и Know Your Meme.
- Сообщения — на языке системы, подпись источника — на языке презентации.

## Разметка

Компоненты берутся одним импортом: `import * as Machina from "slidemachina"`, дальше `<Machina.Slide>`, `<Machina.Image>` и так далее. В таблицах приставка `Machina.` опущена. Именованный импорт `import { Slide } from "slidemachina"` тоже работает.

```tsx
import * as Machina from "slidemachina";
import logoPicture from "./images/logo.svg";
import logoOnDarkPicture from "./images/logo-on-dark.svg";

export default (
  <Machina.Presentation title="Доклад" lang="ru" logo={{ light: logoPicture, dark: logoOnDarkPicture }}>
    <Machina.Slide cover>
      <h1>Доклад</h1>
    </Machina.Slide>
    <Machina.Section title="Раздел">
      <Machina.Slide>
        <h2>Заголовок</h2>
        <ul data-steps>
          <li>Первый пункт</li>
          <li>Второй пункт: <span data-step data-step-effect="highlight">выделено</span></li>
        </ul>
      </Machina.Slide>
    </Machina.Section>
  </Machina.Presentation>
);
```

`index.tsx` экспортирует готовый элемент, функция-компонент не нужна. Большой слайд можно вынести в свой файл: `lang` и `typography` он берёт из `index.tsx` своей презентации.

### Каркас

| Компонент | Пропсы |
|---|---|
| `Presentation` | `title` (по умолчанию `h1` первого `<Slide cover>`); `lang` (по умолчанию `en`); `align` (`left`, `center`, `right`, по умолчанию `left`); `logo` — строка, `{ light, dark }` или компонент с пропом `dark`; `transition`; `speed`; `breadcrumbsSeparator` (по умолчанию `›`); `typography={false}` выключает типограф; `date` (`"2026-10-16"`) для списка в репозитории; `aspectRatio` (по умолчанию `"16:9"`); `progress={false}` убирает полосу прогресса; `onChange` |
| `Section` | `title` (необязателен, если раздел начинается своим `<Slide cover>`: название берётся из его `h1`); `cover={false}` убирает слайд раздела. Вложенный `Section` — подраздел |
| `Slide` | `align` — `left`, `center`, `right`; `valign` — `top`, `center`, `bottom`; `cover`; `background` — цвет, картинка, GIF, видео или `{ iframe: "https://…" }`; `tone` (`dark`, `light`); `transition`; `speed`; `plain`; `logo` — `false`, `"top-right"` (по умолчанию), `"top"`, `"center"`, `"bottom"`; `breadcrumbs={false}` или свой текст; `number={false}`; `className`; `onEnter`, `onLeave`; `hidden` — скрытый слайд |

- Обложки на обоих уровнях подчиняются одному правилу: первый слайд контейнера, если это `<Slide cover>`, даёт заголовок. В `Presentation` это заголовок доклада и вкладки, в `Section` — обложка вместо стандартной. Только первый: раздел, который кончается слайдом «Итоги» с `cover`, номерную обложку не теряет. Сервер считает заголовок той же функцией для списка презентаций и страницы пароля.
- Стандартная обложка раздела: фон `--section-background`, крупный номер («02», «02.1») градиентом от акцента к `--second-accent-color`, как в логотипе. `cover={<Slide>…</Slide>}` ставит свой слайд.
- `<Slide cover>` — контент по центру, крупный `h1`, без крошек и номера.
- `align` — выравнивание по горизонтали, `valign` — по вертикали. Без `valign` обложка и слайд с `align="center"` стоят посередине, остальные — сверху.
- Середина считается по буквам: от верха заглавных первой строки до базовой линии последней. Если внизу есть крошки, номер или логотип, сверху остаётся такое же поле.
- При тексте справа сверху от низа логотипа до заголовка — `--heading-gap`.
- `<Image>` в обложке занимает половину слайда: перед текстом в разметке — слева, после — справа. Зазор `--columns-gap` (96 px).
- Тон фона движок считает сам: по цвету, средней яркости картинки или первому кадру видео. На тёмном слайде светлый текст и логотип `dark`. Без `dark` логотип белеет фильтром `--logo-filter-on-dark`.
- Тёмный слайд сам держит цвета темы, версии `-on-dark` получают его дети. Поэтому `background="var(--accent-color)"` — акцент темы, а не его версия для тёмного фона.
- Видео в фоне узнаётся по расширению (`.mp4`, `.webm`, `.mov`, `.m4v`, `.ogv`) или `data:video/`. Играет без звука по кругу, пока слайд на экране, грузится за два слайда. GIF — обычная картинка.
- `background={{ iframe: "https://…" }}` — страница под контентом. Клики и фокус она не принимает, клавиши остаются у презентации. Тон страницы не измерить: слайд берёт тон своего цвета или `tone`. В миниатюрах и печати страницы нет.
- `plain` прячет логотип, крошки и номер. Для мема или фото.
- Нижний логотип стоит на линии крошек и номера, центральный — в потоке контента высотой 96 px.
- `aspectRatio` — `ширина:высота`: `"4:3"`, `"16:10"`, `"21:9"`, `"9:16"`, `"32:9"`. Формат один на презентацию: обзор, мини-карта, обложка в репозитории, печать. Своего формата у слайда нет, под новый формат слайды не перекомпоновываются. Тип — `AspectRatio` (`` `${number}:${number}` ``). Обе части — конечные числа больше нуля, иначе сборка и `slidemachina dev` останавливаются с сообщением: строку проверяет плагин исходников, выражение — сам `Presentation`.
- Публичные имена — простые английские слова. Правило «имена от 8 символов» действует только внутри движка.

### Шаги

- Шаг без номера идёт после всех шагов выше. `step={3}` и `data-step={3}` ставят шаг на номер 3.
- Эффекты: `rise` (по умолчанию: появляется и чуть поднимается), `fade`, `scale`, `highlight`, `dim`.
- Шаг — любой тег с `data-step`: `<li data-step>`, `<p data-step={3} data-step-effect="fade">`, часть строки — `<span data-step>`.
- `data-steps` на `<ul>`, `<ol>`, `<table>` или `machina-columns` делает шагом каждый пункт, строку `<tbody>` или колонку. `data-steps={3}` — с шага 3. `data-step-effect` рядом задаёт эффект всем пунктам. Свои атрибуты пункта сильнее.
- `data-steps` раскрывает `markReachedSteps` в `slide-steps/step-visibility.ts` в обычные `data-step`, поэтому печать, морфинг и схемы о списках не знают. Записанные атрибуты помечены `data-sequence-step` и снимаются при каждой разметке, чтобы правка без перезагрузки не оставляла старых шагов.
- Строчные теги (`span`, `b`, `em`, `a`) с шагом получают `inline-block`, иначе не работают `rise` и `scale`.
- TypeScript подсказывает эффекты, `data-steps` принимает `true` или номер.
- Прошлый слайд открывается на последнем шаге.

### Блоки

Оформление — обычные теги и классы `machina-…`. Компоненты есть только у блоков с поведением: подгонкой, загрузкой, раскладкой, шагами внутри.

```tsx
<Slide>
  <h2>Числа</h2>
  <div className="machina-columns" data-steps>
    <figure className="machina-big-number">
      <p>13</p>
      <figcaption>переходов между слайдами</figcaption>
    </figure>
    <figure className="machina-big-number">
      <p>1</p>
      <figcaption>файл на всю презентацию</figcaption>
    </figure>
  </div>
  <p className="machina-source">Источник: замер в октябре 2026</p>
</Slide>
```

| Компонент | Пропсы |
|---|---|
| `Image` | `src`, `alt`, `stretch`, `full`, `fit` (`contain` или `cover`), `float` (`left` или `right`); внутри — `<figcaption>` |
| `Video` | `src`, `poster`, `stretch`, `full`, `fit`, `loop` (по умолчанию `true`), `controls`; внутри — `<figcaption>` |
| `QR` | `value` — ссылка или текст; `logo` — картинка в середине; `correction` (`L`, `M`, `Q`, `H`, по умолчанию `M`); `color`; внутри — `<figcaption>` |
| `Meme` | `src`, `alt`, `stretch` (по умолчанию, если нет `float`), `float` (`left` или `right`); внутри — подписи, каждая своим тегом (`<p>`), и `<figcaption>` |

| Разметка | Что это |
|---|---|
| `<ul>`, `<ol>` | Список. Маркер — шестилучевая звёздочка (`clip-path: shape()`, 0,5 em). Маркеры и номера висят слева от текста, их правый край в `--hanging-marker-gap` (0,3 em) от текста |
| `<table>` | Таблица: шапка — `<thead>`, строки — `<tbody>`. Один шрифт и размер `--table-text-size`, шапка приглушена |
| `<table className="machina-compare">` | Сравнение двух–четырёх решений. Первая колонка — критерии, решения делят остальное поровну. Отметки: `<td className="machina-yes" />` (галочка цвета акцента) и `<td className="machina-no" />` (серый прочерк) |
| `<div className="machina-columns">` | Колонки: каждый прямой потомок — колонка |
| `<figure><blockquote>…</blockquote><figcaption>Автор</figcaption></figure>` | Цитата с автором. До автора `--quote-author-gap` (по умолчанию `--heading-gap`, 80 px): при меньшем зазоре автор читается последней строкой цитаты. `<blockquote>` без `figure` — цитата без автора |
| `<figure className="machina-big-number"><p>42</p><figcaption>…</figcaption></figure>` | Большое число с подписью |
| `<div className="machina-card">` | Карточка: фон, скругление, отступы. `machina-card-stretch` — на всё свободное место |
| `<ul className="machina-bars">` с `<li style={{ height: "30%" }} />` | Столбики графика, высота — `height` в процентах |
| `<figcaption>` вне `figure` | Подпись блока над ней |
| `<p className="machina-lead">` | Вводная фраза приглушённым цветом. Сразу под заголовком — подзаголовок: от заголовка `--block-gap`, до контента `--heading-gap` |
| `<p>` | Основной текст |
| `<p className="machina-note">` | Примечание: размер и цвет подписи, от текста над ним `--block-gap` |
| `<p className="machina-thesis">` | Тезис: одна фраза в центре слайда размером `--display-size`, без заголовка. `machina-thesis-small` — размером `--heading-size`, для фразы длиннее. Цвет — `background` слайда, в теме есть мягкие `--accent-soft-color` и `--second-accent-soft-color` |
| `<div className="machina-pin">` | Блок поверх контента, вне потока. `machina-pin-top`, `-bottom`, `-left`, `-right` прижимают его к краю слайда. Сдвиг Tailwind (`translate-x-1/3`) выносит его за край экрана, размер от слайда — `cqh` и `cqw` (`h-[50cqh]`). `-bottom`, `-left` и `-right` сразу — полоса, контент встаёт над ней |
| `<div className="machina-freeform">` | Свободная вёрстка под заголовком: остаток области контента без правил потока. Дети ставятся `absolute`. Заголовок, логотип, крошки и номер остаются |
| `<div className="machina-freeform-full">` на `<Slide plain>` | Свободная вёрстка на весь слайд, без полей |
| `<code>`, `<kbd>` в тексте | Код и клавиша: плоский фон вокруг заглавных, строку не раздвигает. У клавиши ещё тонкая рамка. В начале строки фон выходит за левый край текста, буквы стоят на линии текста |

- `Image` без пропсов — в натуральную величину, но не больше места на слайде.
- Картинки, видео и мемы плоские, без рамки и тени. На тёмном слайде вокруг них тонкая линия `--media-edge-on-dark`, чтобы тёмная картинка не сливалась с фоном.
- `stretch` — на всё свободное место под заголовком, по центру, по умолчанию `fit="contain"`. `full` — на весь слайд под текстом, по умолчанию `fit="cover"`.
- `float="left"` или `"right"` — текст после картинки обтекает её. Ширина до `--float-max-width` (40 %), зазор `--float-gap` (40 px). Блоки, кроме `p`, `ul`, `ol`, `h3`, встают под картинку.
- `<figcaption>` внутри `Image`, `Video` или `QR` — подпись под картинкой. С `stretch` картинка уменьшается, чтобы подпись поместилась.
- `<figcaption>` сразу после `Scene`, `Diagram`, `Sequence`, `Code`, `<table>` или `<figure>` — подпись этого блока на `--caption-gap` от него. Под сценой подпись по центру. После другого блока — по левому краю контента. `machina-note` выглядит так же, но к блоку не прилипает.
- `Video` играет без звука по кругу, пока слайд на экране, и грузится за два слайда.
- Колонка — `<div>` с любыми блоками. Один список, абзац или число можно ставить колонкой без `<div>`. Блок движка (`Code`, `Diagram`, `Scene`, `QR`, `Image`) кладут в `<div>`: он меряет место по колонке. Колонки с `Image stretch`, `Meme`, `Scene` или `QR` растут до низа контента.
- Колонки равной ширины, между ними `--columns-gap` (96 px). Свои доли — CSS: `style={{ gridTemplateColumns: "3fr 2fr" }}`.
- `machina-big-number` занимает колонку. Широкое число уменьшается, но не ниже 64 px: это делает `useBigNumberFitting` в `presentation-core/width-fitting.ts`. Подпись — в `--caption-gap` под числом.
- `<p className="machina-source">` — сноска к блокам выше: в `--block-gap` под ними, над ней линия на всю ширину. Под картинкой, мемом или видео — шириной в картинку. Длинная ссылка переносится.
- Колонки таблицы, кроме последней, — по содержимому без переноса, последняя забирает остальное.
- Кавычки у `<blockquote>` ставит CSS по языку: «…» для ru, “…” для en.
- `QR` занимает всё свободное место, как `Image stretch`, и остаётся квадратным. Его ставят в левую колонку, в демо — `gridTemplateColumns: "3fr 7fr"`.
- `correction` — уровень коррекции ошибок: чем выше, тем больше точек и тем больше повреждений код переживает. Движок берёт самый маленький код и поднимает коррекцию, пока код не растёт: точки крупные, их видно с дальних рядов. С `logo` коррекция всегда `H`, середина под логотипом (около 6 % площади) очищается.
- Цвет точек — `color` или `--qr-color`, по умолчанию цвет текста. Фон прозрачный.

```tsx
<Meme src={jdPicture} alt="Жозеф Дюкре">
  <p>Извольте вставить мем</p>
  <p data-place="50 80 50 20" style={{ color: "black" }}>не покидая слайдов</p>
  <figcaption>Шаблон: Joseph Ducreux, knowyourmeme.com/memes/joseph-ducreux-archaic-rap</figcaption>
</Meme>
```

- Мем настраивается в теге. Первая подпись сверху, вторая снизу, остальные посередине, в полосах по пятой части картинки, как у memegen.
- `data-place` двигает подпись: `top`, `bottom`, `center` или `"left top width height"` в процентах. Цвет, поворот, регистр — `style` или классы.
- Подписи — обычный текст: их правит редактор, обрабатывает типограф, печать оставляет вектором.
- Размер подписи — самый крупный, при котором текст влезает, но не больше девятой части высоты картинки, как у memegen. Шрифт — Oswald 700, капслок, белый с чёрной обводкой. Тёмная подпись — без обводки.
- Мем занимает свободное место, как `Image stretch`. `float` — обтекание. `stretch={false}` — размер картинки: так мем ставят в `machina-pin`.
- `src` — импорт или адрес в интернете. Адрес сборка скачивает в `~/.cache/slidemachina/remote-media` и встраивает.

### Код

```tsx
<Code src="./agent.py" lines="10-13 | 27-30" numbers />
<Code lang="ts" title="app.ts">{`const answer = 42;`}</Code>
```

| Проп | Что делает |
|---|---|
| `lang` | Язык. Без него — по расширению файла из `src` |
| `src` | Код из файла. Правка файла обновляет слайд без перезагрузки |
| `lines` | Строки по шагам: `"1 | 3-4 | 6"`. Первая часть видна сразу, каждая следующая — шаг. Пустая часть — все строки без приглушения |
| `numbers` | Номера строк |
| `title` | Заголовок над кодом. У кода из файла — имя файла |

- Подсветка — Shiki при сборке: `github-light-high-contrast` на светлых слайдах, `github-dark-default` на тёмных. В браузер уходят слова с двумя цветами: `[текст, цвет на светлом, цвет на тёмном]`. Тема из трёх цветов бренда гасила код, поэтому подсветка полная.
- `# [!code highlight]` в комментарии подсвечивает строку на весь слайд и не съезжает при правке.
- Остальные строки приглушены (`--code-dim-opacity`). Длинный код на шаге плавно прокручивается к подсвеченным строкам.
- Длинная строка уменьшает шрифт до 20 px, дальше переносится. Горизонтальной прокрутки нет.
- Однострочный код без заголовка — крупная команда 40 px без фона. У `bash` знак `$` висит слева, как маркер списка.
- Номера в `lines` и `numbers` — номера строк исходника или файла. Их рисует CSS через `attr(data-code-line)`, мельче кода (`--code-number-scale`, 0,6), при копировании их нет.
- Фон кода выходит за левый край текста, как висячая кавычка, символы стоят на линии текста. С номерами фон стоит в `--code-numbered-edge-gap` (12 px) от края слайда, от номера до кода `--code-number-gap` (19 px).
- Код в переменной, а не строкой, плагин не видит: `Code` покажет его без цветов.

### Схемы

```tsx
<Diagram>
  <Box id="slides">index.tsx<small>слайды</small></Box>
  <Group id="build" title="Сборка" step>
    <Box id="vite">Vite</Box>
    <Box id="shiki">Shiki</Box>
    <Arrow from="vite" to="shiki" />
  </Group>
  <Arrow from="slides" to="vite" label="HTTP" step />
  <Focus on={["build"]} step />
</Diagram>
```

| Компонент | Пропсы |
|---|---|
| `Diagram` | `direction` (`right` или `down`, по умолчанию `right`) |
| `Box` | `id`, `column`, `first`, `last`, `step`, `effect`; текст внутри, вторая строка — в `<small>` |
| `Group` | `id`, `title`, `step`, `effect`; блоки и стрелки внутри |
| `Arrow` | `from`, `to`, `label`, `id`, `step`, `effect` |
| `Focus` | `on` — список `id`; `step`. Без `on` фокус снимается |

- Раскладку считает ELK в воркере. Порядок в разметке — порядок на схеме. Блок стоит на колонку правее тех, кто на него указывает. `column={n}`, `first`, `last` ставят блок в нужную колонку, в группе колонки считаются внутри неё. В колонку блока, который на него указывает, блок не встаёт: такую стрелку ELK не рисует.
- Скрытые шаги держат место: раскладка одна на все шаги, блоки не прыгают.
- Стрелка может идти от группы: `from="build"`. Подпись встаёт над самым длинным отрезком стрелки, излом — посередине между блоками.
- Блок — белый прямоугольник с тонкой рамкой. `Focus` приглушает остальное, выбранный блок получает рамку цвета акцента. Стрелка горит, если выбрана она или оба её конца.
- Соседние группы начинаются на одной линии.
- Схема растёт до `--diagram-max-scale` и вписывается в свободное место. Если до правой границы не хватает до 3 %, дотягивается до неё. Маленькой схеме в колонке дают расти: `className="[--diagram-max-scale:1.5]"`.
- Межстрочный интервал — `--secondary-line-height`.
- Эффект шага по умолчанию: у блоков `rise`, у групп и стрелок `fade`. Стрелка рисуется от начала, наконечник появляется последним.

### Sequence-диаграмма

```tsx
<Sequence>
  <Actor id="vite">Vite</Actor>
  <Actor id="react">React</Actor>
  <Message id="request" from="react" to="vite" label="GET /index.tsx" step />
  <Message from="vite" to="react" label="код" reply step />
  <Focus on={["request"]} step />
</Sequence>
```

| Компонент | Пропсы |
|---|---|
| `Sequence` | только части внутри |
| `Actor` | `id`, `step`, `effect`; имя внутри |
| `Message` | `from`, `to`, `label`, `reply` (пунктир), `id`, `step`, `effect` |

- Участники — колонки на всю ширину контента, сообщения — строки. Раскладка на CSS Grid, ELK не нужен.
- Сообщение самому себе — петля. У последнего участника петля идёт влево.
- Блок схемы перетекает в участника с тем же `id`.

### 3D-сцены

```tsx
<Scene>
  <Cube id="cube" size={1.3} position={[0, 0.65, 0]} material="glossy" />
  <Sphere size={1.1} position={[1.7, 0.55, 0]} color="#F2B8A0" step />
  <Move on="cube" position={[-1.7, 0.65, 0]} rotation={[0, 70, 0]} step />
  <Camera position={[5.5, 3.2, 6.5]} target={[0, 0.8, 0]} step />
  <Text position={[0, 2.2, 0]} size={0.6} step>Готово</Text>
</Scene>
```

| Компонент | Пропсы |
|---|---|
| `Scene` | `orbit` (`true` или градусы в секунду, по умолчанию 8); `floor={false}` убирает тень на полу; `full` — на весь слайд под текстом |
| `Cube` | `size` — число или `[ширина, высота, глубина]`, по умолчанию 1 |
| `Sphere` | `size` — диаметр, по умолчанию 1 |
| `Text` | `size` — высота шрифта, по умолчанию 0,5; текст внутри |
| `Light` | `position`, `color`, `intensity` (по умолчанию 1,6), `step` |
| `Camera` | `position`, `target`, `fov` (по умолчанию 30), `step` |
| `Move` | `on` — `id` объекта; `position`, `rotation`, `scale`, `color`, `step` |

- Общие пропсы объектов: `id`, `position` (`[x, y, z]`), `rotation` (градусы), `scale`, `color` (любой цвет CSS, в том числе `var(--accent-color)`), `material` (`matte`, `glossy`, `metal`), `spin`, `step`.
- Без `<Light>` — один мягкий свет сверху слева. С `<Light>` — только заданные, тень отбрасывает первый.
- Камера без `position` подбирает кадр сама: в него входят все положения объектов на всех шагах и тени. По ширине объекты по центру, по высоте — от верха, как текст рядом. С `orbit` кадр подобран для всего облёта. `Camera` с `position` ставит камеру точно туда.
- Сцена `full` лежит под текстом, объекты встают на свободное место под ним. Объект на своём шаге вырастает из точки.
- При уменьшении движения в системе нет вращения и облёта, шаги переключаются сразу.
- three.js грузится отдельным файлом и только если в презентации есть сцена.

### Морфинг

Два элемента соседних слайдов перетекают друг в друга, если совпали:
- `morph="имя"` на обоих — любой тег;
- тег и текст у `h1–h6, p, li, blockquote, figcaption`;
- `src` у `img, video, iframe`;
- текст `pre`.

Блоки движка без пары связываются по порядку на слайде: `machina-card`, число и подпись `machina-big-number`, столбики `machina-bars`. Лишние столбики проявляются, недостающие гаснут. Обычные `div`, заголовки и картинки по порядку не связываются: иначе `auto` морфил бы почти любые соседние слайды. Элемент с `morph` в автоматические пары не попадает. Роли — в `orderedBlockRoles` в `morph-matching.ts`.

Тексты, у которых общих слов не меньше половины, морфятся по словам: общие едут, ушедшие гаснут, новые проявляются. Ушедшее слово едет с ближайшим общим, строка не рвётся. Одинаковые тексты тоже морфятся по словам, поэтому число не двоится. `Code` морфится по кускам: сначала совпавшие строки, потом куски изменённых. Номера строк не едут, а гаснут и проявляются. Блок схемы морфится в блок или участника с тем же `id`.

Контейнер — элемент, всё содержимое которого морфится своими слоями: карточка с подписью и столбиками, блок схемы. Его фон, рамку, скругление и тень рисует сам слой перехода, поэтому скругление не растягивается, а плавно меняется. Картинку и видео слой обрезает своим скруглением. Новый блок схемы без пары проявляется во второй половине перехода. Остальные элементы морфятся снимком.

## Переходы

`transition` у `Presentation` или `Slide`: `auto` (по умолчанию), `morph`, `slide`, `fade`, `zoom`, `cube`, `flip`, `wipe`, `iris`, `blinds`, `mosaic`, `glitch`, `none`.

- `auto`: если у соседних слайдов есть общие элементы — `morph`, иначе `slide`.
- `slide`, `zoom`, `cube`, `flip`, `wipe`, `iris`, `blinds`, `mosaic` двигают слайд целиком: с фоном, логотипом, крошками и номером. За ними видна сцена `--transition-stage-background` в пределах холста: поля окна цвет не меняют.
- `morph`, `fade`, `glitch` двигают только содержимое. Новый фон с логотипом проявляется поверх старого с 30 до 70 % перехода. Между светлым и тёмным слайдом фон меняется сразу на середине, иначе вышел бы серый кадр. Старые номер, крошки и логотип гаснут в первой половине, новый номер проявляется во второй.
- `zoom` уносит старое содержимое к зрителю за первую четверть, новое проявляется после.
- `flip` поворачивает слайд в перспективе 7,4 полуширины, чтобы ближний край не выходил за окно.
- `wipe` — новый слайд наезжает справа с мягким краем. `iris` — раскрывается кругом из центра. `blinds` — 8 горизонтальных полос волной сверху вниз. `mosaic` — сетка 8 × 5, плитки диагональной волной. `glitch` — текст дёргается вбок, расслаивается на красный и голубой.
- Маски плиток строит `tile-masks.ts`. Летящих осколков нет: клон слайда на каждую плитку показал бы 3D-сцены пустыми и перезапустил видео.
- Стрелка с `morph="diagram-arrow:from:to"` морфится в такую же стрелку на соседнем слайде, без пары — гаснет и проявляется.
- Вперёд берутся переход и скорость входящего слайда, назад — уходящего. Шаги идут без перехода, со скоростью своего слайда.
- `speed` у `Presentation` или `Slide`: `fast` (1,5), `normal` (по умолчанию), `slow` (0,7) или число — во сколько раз быстрее `normal`.
- Длительности при `normal`: `--transition-duration` 0,4 с, `--morph-duration` 0,55 с, `--rotation-duration` 0,6 с (куб, переворот, `iris`, `blinds`, `mosaic`), `--step-duration` 0,3 с. Тема их меняет, `speed` делит.
- При уменьшении движения в системе перехода нет.
- Быстрые нажатия не теряются.

## Клавиши и панель

| Клавиша | Что делает |
|---|---|
| →, ↓, PageDown, пробел | дальше |
| ←, ↑, PageUp, Shift+пробел | назад |
| Home, End | первый и последний слайд |
| Esc или O | обзор слайдов |
| цифры и Enter | слайд с этим номером |
| B или . | пауза: чёрный экран и кнопка «Вернуться к слайду · B» |
| F | полный экран |
| H | спрятать панель |
| P | окно докладчика |
| E | редактор, только в `slidemachina dev` |
| M | мини-карта, только в `slidemachina dev` |
| Cmd+P или Ctrl+P | печать, когда все схемы и сцены готовы |

- Адрес с `?overview` открывает сразу обзор слайдов. Обзор сам ставит и убирает `?overview`, поэтому ссылку можно просто скопировать.
- Буквы узнаются по физической клавише и работают в русской раскладке. Клавиши с Cmd, Ctrl и Alt движок не трогает, кроме Cmd+P. Enter без номера работает как обычно.
- Мышь не листает. На телефоне и планшете листает свайп или касание: левая треть — назад, остальное — дальше. Ссылки, кнопки, видео, панель и обзор работают как обычно, в редакторе касание не листает.
- В паузе клавиши, свайп и касание только возвращают слайд: зал не видит, как он меняется. Весь чёрный экран — кнопка возврата.
- Полоса прогресса — линия `--progress-height` (6 px) внизу холста, градиентом от акцента ко второму акценту. У полосы и мини-карты свои слои перехода, при `slide` и `cube` они не пропадают.
- Заметки — `<Notes>` внутри `Slide`: абзацы, списки, `em`, `strong`, `code`, `kbd`. `<Notes step={2}>` — заметка к шагу 2. На слайде, в миниатюрах и печати заметок нет, в PowerPoint они идут в заметки слайда. `<Presentation duration={20}>` — длительность доклада в минутах.
- Окно докладчика — P или кнопка на панели: та же страница с `?presenter` в окне 1280×800. В нём текущий слайд, превью следующего шага (клик — дальше), заметки, «Слайд 12 из 48 · шаг 2 из 3», крошки, часы, таймер и темп. Заметки 32 px, − и + меняют размер от 16 до 72, выбор запоминается. Заметки непоказанных шагов приглушены. Таймер ждёт первого движения, его можно остановить и сбросить, он переживает перезагрузку. С `duration` видно запас или отставание. Клавиши листания, B и номер работают в обоих окнах.
- Окна общаются через `BroadcastChannel` с именем по пути страницы: работает в `slidemachina dev`, из папки и из файла с диска. Главное — окно слайдов: оно шлёт позицию и паузу, клавиши окна докладчика уходят ему командами. Окно докладчика не вызывает `onChange`, `onEnter`, `onLeave`.
- Хуки: `<Presentation onChange={({ slide, step }) => …}>` — после каждого движения и при загрузке, слайд с 1, шаг с 0. `<Slide onEnter onLeave>` — слайд пришёл и ушёл. `useSlide()` — `{ number, step, isCurrent, isCopy }`, на пройденных слайдах `step` — `Infinity`. Миниатюры и печать хуки не вызывают. Компонент в `index.tsx` при правке теряет `useState`, компонент в своём файле — нет.

Обзор слайдов — тёмная сетка миниатюр по разделам на всё окно: на 16:9 шесть колонок, на 4:3 — четыре, на 9:16 — три. Открытие уменьшает текущий слайд в миниатюру, закрытие увеличивает выбранную (View Transitions). Выбранная миниатюра обведена `--accent-color-on-dark`. Стрелки двигают выбор, Enter или клик открывает слайд.

Панель управления — тёмная капсула `--dark-background` снизу по центру. Кнопки 44 px на любом экране, фокус клавиатуры — кольцо `--accent-color-on-dark`. Кнопки:
- «Все презентации» — только в репозитории;
- обзор слайдов;
- полный экран (нет там, где браузер его не умеет, например на iPhone);
- печать с меню: «Распечатать», «Печатная версия», переключатель «По шагам»;
- в `slidemachina dev`: мини-карта, карандаш редактора и кнопки слайда, смайлик панели «Мем», Agentation;
- скрыть панель.

Панель гаснет через 2 с без движения мыши, если над ней нет мыши и не открыто меню. H прячет её совсем, остаётся кружок со стрелкой, выбор хранится в `localStorage`. Если под холстом есть 76 px, панель встаёт под слайд.

Мини-карта — только в `slidemachina dev`: полоса 168 px со всеми слайдами поверх правого края окна, как в редакторе кода. Включают кнопка и M, выбор хранится в `localStorage`. В полном экране и под обзором её нет. Миниатюры рисуются, только когда они рядом с видимой частью полосы, текущий слайд — в середине.

### Agentation

[Agentation](https://www.npmjs.com/package/agentation) работает только в `slidemachina dev`. Нажимаешь на элемент слайда, пишешь замечание, оно уходит в Claude Code через MCP-сервер `agentation-mcp` на порту 4747. В замечании есть место в файле: `index.tsx:42:7`.

- Нет сервера на 4747 — замечания хранятся в браузере.
- Кнопка Agentation гаснет и прячется вместе с панелью. Она живёт вне панели, поэтому движок прячет её через `visibility`: `opacity` не доходит до её частей в shadow DOM.
- `SLIDEMACHINA_AGENTATION=off` выключает Agentation, так запускаются тесты. В сборку он не попадает.

## Печать и PDF

- Cmd+P печатает слайд на страницу. Страница — размер холста: 1920×1080 на 16:9, 1440×1080 на 4:3, 1080×1920 на 9:16. `@page size` пишет `<Presentation>` в свой `<style>`: переменные в `@page` из CSS-файла не работают. Фоны печатаются без галочки «Фон».
- Страница печати изолирована `contain: strict`, иначе широкая схема заставляла Chrome уменьшать все страницы.
- Диалог печати и пункт меню браузера ждут метку `data-print-ready`: схемы разложены, сцены нарисованы, шрифты и картинки загружены. Пункт меню браузера даёт только `beforeprint` и может не дождаться 3D-сцен.
- Скрытый слайд — `<Slide hidden>`. Стрелки, Home и End его пропускают, номера, полоса прогресса и `onChange` его не считают. Адрес — `#12+1`: первый скрытый после слайда 12, `#12+1.2` — после двух шагов. Из скрытого стрелки ведут к соседу, так запасные слайды после «Спасибо» листаются подряд. В обзоре и мини-карте скрытые приглушены (`--hidden-thumbnail-opacity`) и подписаны `12+1`. Окно докладчика пишет «Скрытый слайд 12+1», темп считает только показанные. `useSlide().number` на скрытом — номер показанного перед ним.
- Печать, PDF и PowerPoint скрытые слайды пропускают. Вернуть: переключатель «Скрытые слайды» в меню печати (есть, только если они есть), адрес `?print&hidden`, флаг `--hidden`. Значения `hidden="print"` нет: скрывать решает автор, печатать ли скрытое — тот, кто выгружает.
- «По шагам» в меню печати — страница на каждый шаг, для Cmd+P и печатной версии. Выбор запоминается.
- Печатная версия — все страницы столбиком, как в reveal.js. Открывается из меню печати или по адресу `?print`, по шагам — `?print=steps`. Внизу панель: назад (Esc), число страниц, «По шагам», «Распечатать».
- `slidemachina build --pdf` печатает печатную версию через Chrome без окна, `--steps` — страница на шаг.
- Не печатаются панель, обзор, мини-карта, пауза и Agentation.
- Что меняется в печати и почему:
  - мягких масок нет: Preview на macOS рисует их сплошными прямоугольниками. Обрезанный код гаснет под непрозрачными полосами цвета блока кода;
  - номер раздела — стопка сплошных копий вместо градиента на тексте: просмотрщик PDF в Chrome (PDFium) такой градиент не умеет;
  - звёздочку списка вырезает `clip-path`, а не маска: контур остаётся векторным;
  - зерна на разделах нет, градиент плотный. Переменные темы: `--section-printed-background`, `--section-glow-start-color`, `--section-glow-end-color`, `--section-glow-direction`, `--section-glow-strength`;
  - холсты сцен — `image-rendering: pixelated`, чтобы Chrome печатал картинку, а не стирал фон слайда.

## Сборка

- PowerPoint (`--pptx`) собирается из печатной версии в Chrome без окна: обход DOM каждого слайда, файл пишет pptxgenjs.
  - Отдельные объекты: текст с переносами как в браузере, заливки и рамки со скруглением, блоки и группы схем, участники sequence-диаграмм, стрелки — кривые PowerPoint.
  - Картинки, 3D-сцены и номер раздела — картинки, MP4 и MOV — видео, GIF остаётся GIF. Маркеры, номера строк, `$`, градиенты и тени — снимок поверх, свой на каждый шаг.
  - Шаги `rise`, `fade`, `scale` — анимации появления по щелчку. Слайд с `lines` — слайд на каждый шаг, как в печати по шагам.
  - Фон `code` и `kbd` в строке — подсветка текста. Полупрозрачный фон смешивается с цветом под ним.
  - Подписи мема — Impact, две копии: снизу с обводкой, сверху белая. Impact есть в macOS и Windows, а у Arial другие пропорции.
  - Вместо загружаемых шрифтов — Arial и Courier New.
  - Короткая сторона слайда — 7,5 дюйма, 1 px холста — 0,5 pt.
- Один файл: JS и CSS встраивает vite-plugin-singlefile, картинки, шрифты, видео и воркер ELK — data URL.
- Quick Look на macOS не выполняет скрипты, но показывает `<noscript>`. Поэтому `--html` кладёт туда снимки слайдов в WebP: около 17 КБ на слайд. HTML больше 10 МиБ Quick Look не открывает, тогда снимков нет, сборка пишет почему. Без Chrome файл собирается без них. В файле под паролем снимков нет: они раскрыли бы слайды.
- Фавиконка — знак slidemachina в SVG, запасные PNG для Apple, всё в data URL. `<Presentation favicon={file}>` ставит свою. За `logo` фавиконка не следует: надпись в 16 px превращается в пятно.
- PNG, JPEG и GIF пережимаются в WebP: не больше 3840×2160, качество 82, GIF — анимированный WebP. Если WebP больше оригинала, остаётся оригинал. Кэш — `~/.cache/slidemachina/pictures`.
- Видео не пережимается. Сборка пишет размер каждого видео, при файле больше 50 МБ советует папку или zip.
- Шрифты Onest и JetBrains Mono — только латиница и кириллица. Oswald для мемов попадает только в презентацию с `<Meme>`.
- zip: картинки, видео и шрифты без сжатия, файлы в корне архива.
- Файл под паролем шифрует staticrypt, страница ввода пароля своя. Файл вдвое больше обычного. Пароль короче 14 знаков — сборка предупредит.

## Редактор в браузере

В `slidemachina dev` — E или карандаш на панели.

| Что | Как |
|---|---|
| Текст | Нажать и печатать. Enter или уход фокуса сохраняет, Esc отменяет |
| Картинка | Перетащить файл на картинку или нажать и выбрать файл |
| Блок схемы | Тянуть мышью в другую колонку или на другое место |
| Слайд | Кнопки на панели: новый слайд после текущего, копия, раньше, позже, удалить |
| Выключить | E или карандаш ещё раз |

- Под курсором — контур и ярлык «Текст index.tsx:40», над панелью — строка состояния.
- Правится текст без вложенных тегов. В тексте с разметкой — каждый вложенный тег с одним текстом внутри, например `<code>` в ячейке.
- Картинка ложится в `images/` с именем латиницей: `My Photo.png` → `images/my-photo.png`. До 80 МБ.
- Блок схемы: в файл пишется `column={n}`, строка блока переезжает на нужное место.
- Слайд меняется местами с соседом того же уровня, раздел перешагивает целиком. Страница переходит к новому месту слайда. Стандартный слайд раздела не двигается: в файле его нет.
- Цвет редактора — середина между `--accent-color` и `--accent-color-on-dark`: читается на светлом и тёмном слайде.
- Если файл изменили в редакторе кода, правка не запишется, на экране — «Файл изменили в редакторе кода». Правки идут по очереди.
- В сборку редактор не попадает.

### Панель «Мем»

В `slidemachina dev` — кнопка со смайликом. Окно над ней: поиск, вкладки «Шаблоны memegen» и «GIF», поле для ссылки на картинку, GIF или страницу. Без ключа GIPHY вкладка GIF пишет, где его взять.

- Мем встаёт на новый слайд после текущего, презентация переходит на него. Источник — `<figcaption>` под картинкой.
- Картинка остаётся по ссылке, сборка её встроит. Галочка «Сохранить картинку в images/memes» кладёт файл рядом, выбор хранится в `localStorage`.
- На стандартном слайде раздела панель просит открыть обычный слайд.
- Шаблон вставляется с примерами подписей memegen, чтобы было видно, какое поле за что. Поля из `config.yml` шаблона становятся `data-place` и `style` подписей.
- Запись идёт через тот же endpoint, что у редактора, с проверкой версии файла до и после скачивания.
- При именованном импорте недостающие `Meme`, `Image`, `Video`, `Slide` добавляются в него.
- Миниатюры шаблонов браузер берёт с api.memegen.link. Поиск идёт через dev-сервер: ключ GIPHY не попадает в браузер.

## Сетка

- Короткая сторона холста всегда 1080 логических пикселей: 16:9 — 1920×1080, 4:3 — 1440×1080, 16:10 — 1728×1080, 9:16 — 1080×1920. Поэтому размеры шрифта и поля одинаковы в любом формате.
- Формат вписывается в окно, а холст растёт по свободной стороне не больше чем на треть: 16:9 — до 21:9 в широком окне и до 4:3 в высоком. Фон доходит до края экрана, размер шрифта не меняется, растёт место. `--canvas-width` и `--canvas-height` — холст слайда: на экране живой, в миниатюрах и печати — формат (`--format-width`, `--format-height`).
- Дальше трети по краям — поля цвета текущего слайда, у тёмной картинки — `--dark-background`. `--letterbox-background` задаёт один цвет. Телефон не переводит горизонтальную презентацию в вертикальную.
- Холст центрируется через `translate`: с `left` и `top` 50 % у края появлялась серая линия.
- Поля: бока и низ 64 px, верх 88 px. Отступы меряются до видимого края: заглавных первой строки, базовой линии последней или края фона блока (`text-box: trim-both cap alphabetic`). Под заголовком — `--heading-gap`, между блоками — `--block-gap`, между пунктами — `--item-gap`, до подписи — `--caption-gap`. Отступ у блока только снизу, у последнего блока его нет.
- В колонках первые видимые края на одной линии.
- Верх заголовка на линии верха логотипа. Крошки и номер стоят базовой линией в 64 px от низа.
- Логотип справа сверху, крошки слева снизу, номер справа снизу. Логотип `slidemachina` — градиент `#7000d1` → `#007a33`, на тёмном слайде `#a779fd` → `#62c378`.
- Границы логотипа — его `viewBox`: пустые поля в чужом SVG убирают в самом файле.
- Текст пунктов на линии заголовка, маркеры и номера висят слева. Звёздочка, номер и `$` стоят правым краем на одной линии, в 14 px от текста при размере 40 px.
- Код тоже на линии заголовка: фон и номера строк выходят за левый край. На слайде с `align="center"` фон кода не выходит, номера внутри.

## Типограф

Библиотека typograf при сборке: неразрывные пробелы после предлогов и перед тире, тире из дефиса, кавычки, многоточие. Для `lang="ru"` правила `ru` и `en-US`, для остальных — `en-US`.

- Правит текст JSX и строковые пропсы `title`, `label`, `breadcrumbs`.
- Не трогает `Code`, `code`, `pre`, `kbd`, `samp` и строки в `{…}`. Не трогает технические слова: `align="center"`, слова с `?`, `#` или `/` в начале (`?print`, `#3.2`, `/docs`), слова с двоеточием перед цифрой (`index.tsx:42:7`, `12:30`).
- `<code>` и `<kbd>` в начале строки получают `data-hanging-box`: фон выходит за левый край, как кавычка. В пункте списка — нет, там маркер.
- Номера строк в файле не сдвигаются. В браузер typograf не попадает. `<Presentation typography={false}>` выключает.
- Висячая пунктуация: «, „, ", ' и ( в начале строки выходят за левый край, буквы остаются на линии. У знака нулевая ширина, а невидимая копия в пробеле перед ним возвращает ширину в середине строки. Так же висят маркеры, номера списков, фон кода, номера строк и `$`. Колонка сдвигает содержимое на самый глубокий вынос. Выключает `--hanging-punctuation: 0`, на одном слайде — `className="[--hanging-punctuation:0]"`.
- Переносы ставит браузер: `hyphens: auto` у абзацев, пунктов, подписей и `machina-note`. Заголовки, тезис, цитата, большое число, источник и подписи мема не переносятся: в крупном тексте с `text-wrap: balance` перенос бросается в глаза. В `code`, `kbd`, `samp`, `pre` — `hyphens: manual`. Мягких переносов в тексте нет, поэтому копирование чистое. `typography={false}` переносы не выключает. В PowerPoint строка с переносом кончается дефисом.

Картинки демо — снимки самого движка в WebP без потерь, после заметной правки вида их переснимают в Playwright.

README показывает слайды демо из `docs/readme/` и снимки инструментов из `images/` демо. После правки демо их переснимает `npm run readme-media` (`tests/readme-media-recording.ts`), около полутора минут:
- Слайды ищутся по заголовку: новые слайды список не ломают. Переименовали заголовок — поправьте его в начале скрипта.
- Ролики — анимированный WebP: видео из репозитория GitHub в README не проигрывает. Кадры пишет `Page.startScreencast` по CDP, не больше 30 в секунду, `img2webp` склеивает их с настоящими паузами.
- Плоские слайды — без потерь: с потерями на ровном фоне и мелком тексте видны артефакты. 3D-сцена — `-mixed -q 95`.
- У кадра серая рамка в 1 px, чтобы белый слайд не сливался со страницей GitHub.
- Логотип в шапке README переключают метки `#gh-light-mode-only` и `#gh-dark-mode-only`: они следуют теме GitHub, а `<picture>` с `prefers-color-scheme` — теме системы.
- Нужен `img2webp` из libwebp (`brew install webp`). Chrome скрипт запускает сам, `SLIDEMACHINA_CHROME_ENDPOINT` подключает его к уже запущенному Chrome с `--remote-debugging-port`.

Видео и GIF-мем в демо — облёт одной сцены, снятый в Playwright с подменой `requestAnimationFrame` и `performance.now`.

В тексте демо имена из кода (атрибуты, пропсы, классы, компоненты, пути, команды) — в `<code>`, клавиши — в `<kbd>`. Названия продуктов (Chrome, Agentation, ELK) — текстом.

Пакет движка публикуется исходниками TypeScript: CLI запускает Vite 8, Vite компилирует движок вместе с презентацией. Node 26 запускает .ts напрямую, но не стирает типы в node_modules: опубликованному пакету понадобится шаг сборки.

Публичный компонент — файл `<имя>-component.tsx` (`code-component.tsx` — это `<Code>`) и стили `<имя>-component.css` рядом. Своя папка `<имя>-block/` — только когда у компонента есть свои модули, как у `code-block/` и `qr-block/`. Остальное лежит прямо в папке группы. Папок из одного-двух файлов, папок с единственной подпапкой и индексных файлов нет.

dependency-cruiser в `npm run check` (`.dependency-cruiser.cjs`) запрещает циклы, модули, которые никто не импортирует, и такие связи:
- `browser-runtime` не берёт код из `server-runtime` и модули `node:*`, а `server-runtime` — модули `browser-runtime`;
- `shared-between-runtimes` не зависит ни от остального движка, ни от пакетов;
- `presentation-core` не зависит от блоков;
- блоки (`content-blocks`, `diagram-blocks`, `scene-blocks`) не зависят друг от друга.

### Как всё устроено

1. `server-runtime/command-line/slidemachina.ts` разбирает команду и понимает, что перед ним: одна презентация или репозиторий.
2. Vite получает настройки из `server-runtime/development-server/vite-configuration.ts`. Файла `index.html` на диске нет: его отдаёт плагин `slidemachina`.
3. Страница грузит модуль входа `/@slidemachina/entry.js` (в репозитории — `/@slidemachina/entry/<папка>.js`). Порядок CSS: `engine-layout.css`, `default-theme.css`, остальные `.css` из `browser-runtime/` (по вложенности, потом по алфавиту), `theme/style.css`, `index.tsx` с его импортами, `style.css` презентации. Стили редактора — только в dev.
4. Плагин `slidemachina-slide-source` из `source-transforms/` проходит по каждому `.tsx` до React: подсвечивает `<Code>`, типографирует текст, в dev ставит метки `data-source-location`. Файл с `<Meme>` получает импорт шрифта Oswald. В сборке адреса `https://…` у `Image`, `Video`, `Meme` и `background` скачиваются в кэш и становятся импортом файла.
5. `mountPresentation` из `presentation-core/presentation-mounting.tsx` рендерит элемент из `index.tsx`. Горячая замена рендерит новый элемент в тот же корень, слайд и шаг остаются.
6. `<Presentation>` разворачивает разделы в плоский список, рисует все слайды сразу и ведёт позицию в адресе. Неактивные скрыты через `visibility: hidden` и `inert`: у элементов есть размеры, шаги считаются по DOM.
7. Шаги — атрибуты `data-step` в DOM. Слайд размечает достигнутые шаги и шлёт событие `slidemachina-steps`. Код, схемы и сцены по нему меняют подсветку, фокус и позы прямо в DOM, без перерисовки React.
8. Переход — View Transitions API. Движок раздаёт элементам имена слоёв перед снимком и снимает после перехода.

Код Node — TypeScript без стёртых типов: Node 26 запускает .ts напрямую, `npm run check` проверяет его тем же `tsc`.

### Ключевые решения

Сборка и платформа:
- **Vite 8 внутри CLI.** Rolldown и Lightning CSS, самый популярный сборщик на октябрь 2026. Пользователь не видит ни `index.html`, ни конфигурации Vite.
- **Пакет — исходники TypeScript.** Движок всегда подключается через CLI, значит через Vite: шага сборки нет, ошибки указывают на исходник. Цена: `tsc` в проекте пользователя проверяет и движок.
- **Одна папка — одна презентация, разметка в `index.tsx`.** Структура папок и есть конфигурация. Репозиторий — те же папки рядом и `theme/`.
- **Один TypeScript — 7**, в репозитории и в шаблоне. Подсказку номера слайда через плагин tsserver убрали вместе с TypeScript 6: второй TypeScript ради неё не окупался.
- **React Compiler на Rust** (`oxc-transform-react`): версия на Babel требовала бы `@babel/core`. Обновляется вместе с `@vitejs/plugin-react`. Компоненты с нарушениями правил компилятор молча пропускает, их показывает `react({ compiler: { logDiagnostics: true } })`. `useSlideEnvironments` исключён через `"use no memo"`.
- **`noUncheckedIndexedAccess`** вместе с `typescript/no-unnecessary-condition`. Где индекс гарантирован — `!`, иначе проверка.
- **Подсветка кода и типограф — при сборке, в плагине Vite.** Shiki, грамматики и typograf остаются в Node. Правки через magic-string, карта исходников точная.
- **Скорость.** Слайды дальше двух от текущего не рисуются (`data-distant`, `content-visibility: hidden`). Скрыть все нетекущие нельзя: шаги переигрывались бы после прыжка. Сборка держит один Chrome с четырьмя вкладками для Quick Look, PDF и PowerPoint. Все цели демо собираются за 21 с.
- **Agentation и редактор не попадают в сборку**: `import.meta.env.DEV` стоит внутри `lazy`.
- **Стили движка — CSS-переменные и `data-*`-атрибуты**, без Tailwind внутри.
- **Пароль только на один файл**: staticrypt шифрует HTML, картинки в папке остались бы открытыми.
- **Тема из `index.tsx` — обычный импорт CSS**, привычно для React и Vite. Поэтому `style.css` презентации подключается после `index.tsx`, иначе импортированная тема перекрыла бы его.

Слайды в браузере:
- **Все слайды в DOM.** Шаги считаются по DOM, схемы меряют текст, миниатюры и страницы печати — копии тех же слайдов.
- **Шаги, фокус, подсветка строк и позы сцены — атрибуты в DOM, а не состояние React.** Иначе View Transitions снимал бы кадр до прокрутки или подсветки.
- **Горячая замена рисует синхронно** (`flushSync`): иначе редактор искал слайд в старом DOM.
- **`index.tsx` — без Fast Refresh.** Он экспортирует элемент, а не компонент, и Fast Refresh перезагружал бы страницу. plugin-react и React Compiler в dev `index.tsx` не обрабатывают, правка рисуется в тот же корень синхронно.
- **Хуков три.** `onChange` — для аналитики и синхронизации, `onEnter`/`onLeave` — для таймеров и звука, `useSlide()` — для своих компонентов. Для чужих скриптов есть событие `slidemachina-steps`.
- **Нативные теги вместо ролей**: обзор — `<dialog open>`, статус редактора — `<output>`. Обзор открывается без `showModal()`, иначе верхний слой вышел бы из-под масштаба холста.
- **Редактор пишет точечно.** Сервер разбирает файл тем же парсером и меняет только нужный кусок. Версия файла защищает правки из редактора кода (ответ 409). Правки принимаются только со своей страницы и только в `.tsx` и `.jsx` сайта, не из `node_modules`, путь через `realpath`.
- **Печать — копии слайдов.** Кнопка и Cmd+P рисуют копии и ждут `data-print-ready`, пункт меню браузера — синхронно по `beforeprint`. Страницы убираются после печати. Сами слайды остаются в DOM и считают шаги.

Разметка:
- **Оформление — нативные теги и классы `machina-…`, компоненты — только у блоков с поведением.** `List`, `Table`, `Columns`, `Quote`, `BigNumber`, `Caption` убрали: они только рисовали разметку. Цена: блок движка в колонке требует `<div>`, доли колонок пишутся CSS.
- **Тезис, блок поверх вёрстки, карточка, график, сноска, свободная вёрстка — классы.** Поведения у них нет. Центр тезиса держит CSS (`:has`), края `machina-pin` — отрицательные отступы от полей. `<Bars values>` не делали. Ширину сноски под картинкой меряет слайд (`source-width-fitting.ts`): соседу ширина картинки в CSS недоступна.
- **`machina-freeform` — так свободный холст называют Figma, tldraw и Apple Freeform.** Слово `canvas` путалось бы с тегом `<canvas>`.
- **`Slide cover` — проп, а не класс.** Обложку нужно найти до отрисовки, в браузере и на сервере: она задаёт заголовок доклада и раздела.
- **Вертикаль — отдельный проп `valign`.** `align` уже значит горизонталь. Пара `align` + `valign` знакома по HTML.
- **Картинку на обложке ставит порядок в разметке:** что видно в коде, то и на слайде. Картинка вынута из потока и не растягивает строки текста.
- **С `float` содержимое слайда переходит в блочную раскладку:** во flex-колонке `float` не работает.

Сетка и типографика:
- **Холст растёт под окно, копии — в формате.** С фиксированным холстом всё у края слайда обрывалось на полях окна. Как в reveal.js, фон доходит до края экрана. Миниатюры, обложки и PDF — в формате презентации. Рост ограничен третью, иначе телефон растягивал бы горизонтальный слайд в полосу 1920×4000.
- **Одна шкала типографики:** два начертания текста, четыре размера, три цвета. Таблица одним начертанием, шапка только приглушена. У примечания нет линии сверху: линия — знак источника.
- **Каждый блок обрезан по буквам с обеих сторон, отступ только снизу.** Раньше правила обрезки перебивали друг друга, и отступы плавали.
- **Пункты списка ближе, чем блоки:** `--item-gap` (32 px) больше строки внутри пункта (26 px) и меньше `--block-gap`, иначе абзац под списком читался ещё одним пунктом.
- **Центрированный слайд стоит посередине слайда**, как разделы и обложки: иначе при листании контент прыгал.
- **Полоса внизу — отступ области контента, а не её граница.** Слайд меряет полосу (`bottom-band-room.ts`) и даёт нижний отступ: высота полосы плюс `--heading-gap`. Верхней полосы нет: её отступ столкнулся бы с отступом под логотип.
- **Логотип на каждом слайде.** `slide`, `cube`, `flip` двигают его со слайдом, миниатюрам и печати нужна копия. Файл грузится один раз.
- **Скругления цифр выше линии — так задумано:** круглые знаки шрифт рисует выше, иначе они кажутся мельче.
- **Номер раздела не растёт под название**, иначе цифры плясали от раздела к разделу. `section-number.tsx` после загрузки шрифтов ограничивает название шириной цифр.
- **Одно скругление на все блоки:** `--block-radius` 12 px у кода, картинок, видео, блоков и групп схем, миниатюр и обложек. Панель и редактор — интерфейс, у них свои.
- **Картинки, схемы и код плоские.** Тени давали серую дымку на белом, а блок схемы с тенями выглядел карточкой интерфейса. Блок схемы — одна рамка, фокус — её цвет.
- **Цветной слайд — одно семейство цвета:** текст — глубокий тон цвета слайда (`--text-color-on-color`), приглушённое — он же с прозрачностью. Серый на цветном фоне выглядел грязным.
- **Отметки в таблице сравнения нарисованы CSS:** галочки в загружаемой части Onest нет, браузер взял бы её из другого шрифта.

Висячая пунктуация и код:
- **Код висит, как пунктуация.** Символы — на линии текста, фон и номера — за левым краем. Справа фон кончается на границе области контента: у рваного правого края кода своей линии нет.
- **Висячие знаки ровняются по правому краю.** У звёздочки, номера и `$` разная ширина, по центру зазор до текста плясал бы. Номер рисует `:before`, а не `::marker`: зазор у `::marker` не задать. Кавычки висят вплотную: они часть слова.
- **Номера строк мельче кода:** при размере кода двузначные номера не помещаются в левое поле слайда (64 px) вместе с отступами.
- **Номер строки — псевдоэлемент.** Его нет при копировании, при морфинге он не едет: номер 3 на новом слайде — другая строка.

Переходы и морфинг:
- **View Transitions без запасного пути на JS.** Браузеры — последние две версии Chrome, Edge, Safari, Firefox. Морфинг по словам оборачивает слова в `span` на время перехода: браузер снимает настоящие слова.
- **Морфинг кода — своё решение на View Transitions**, не shiki-magic-move: блоки лежат на разных слайдах.
- **Пары карточек и графиков — по порядку, без имён.** Раньше история «Выручка за год» в демо держалась на 16 атрибутах `morph`.
- **Пара одинаковых текстов морфится по словам:** снимки текста разного размера не совпадают по пропорциям, и число двоилось.
- **Контейнер при морфинге рисует слой перехода.** View Transitions растягивает снимок вместе со скруглением, и углы становились овальными. Поэтому фон, рамка, скругление и тень анимируются на `::view-transition-group`. Картинку слой обрезает своим скруглением.
- **Фон между светлым и тёмным слайдом меняется скачком** на середине, когда старый текст погас, а новый не появился: любая смесь белого и тёмного — серый кадр.
- **Цвет заливает слайд кругом** между двумя слайдами с плоским цветом без общих элементов, за `--color-flood-duration` (1 с). Смешение снимков давало тусклую середину. Если что-то морфится, переход ведёт оно.
- **Переход идёт внутри холста:** иначе на 4:3 в широком окне поля вспыхивали серым. У `slide` и `zoom` слой обрезан по холсту, куб и переворот — нет, им нужна глубина.

Схемы и сцены:
- **ELK лениво и в воркере.** Основной бандл несёт только адрес воркера. Схема просит раскладку за два слайда, остальные — через 5 с простоя. ELK в режиме `INTERACTIVE`, всегда вправо, `down` — поворот координат.
- **Стрелка важнее `column`.** Блок в колонке того, кто на него указывает, движок сдвигает вправо сам, до ELK: иначе ширины колонок считались по старой колонке и схема разъезжалась.
- **Изломы и верх групп правит движок после ELK:** у ELK нет настройки излома посередине. Группу ниже соседней движок растягивает вверх, а не двигает блоки, чтобы не вести стрелки заново.
- **До правой границы схема дотягивается масштабом:** раскладка не знает ширины слайда. 3 % разницы глаз не видит.
- **Сцены на чистом three.js**, без @react-three/fiber. Один WebGL-контекст на все сцены: браузер сбрасывает контексты сверх ~16. Кадр копируется в 2D-холст: Chrome печатает только 2D. Тон-маппинг Neutral: ACES и AgX сдвигают цвета бренда. Живой только текущий слайд.
- **Камера подбирает кадр по точкам объектов**, а не по коробке сцены: так нет лишнего воздуха.
- **Холст сцены в печати непрозрачный, закат демо — WebP:** прозрачное Chrome печатает с мягкой маской.

PowerPoint:
- **Объекты и анимации, а не снимки слайдов:** доклад можно править и показывать по шагам. У Slidev анимаций нет. pptxgenjs анимаций не умеет, поэтому в каждый слайд вставляется `<p:timing>`, объект находится по имени. Строки переносит браузер, PowerPoint их не переносит. Снимки — вдвое больше холста.
- **Шрифты — сразу Arial и Courier New.** Запасной шрифт выбирает программа зрителя, и она бралась за Times. Onest и JetBrains Mono у зрителя почти не бывает, встроить WOFF2 pptxgenjs не умеет. Arial уже Onest на 1–4 %, Courier New по ширине знака как JetBrains Mono.
- **Фон кода в строке — подсветка текста:** фигура по координатам браузера съезжала при другом шрифте. Цена — углы без скругления и `kbd` без рамки.
- **Шаги кода — отдельные слайды:** анимация PowerPoint не прокручивает текст и не меняет яркость строк. Так же у Slidev.

Мемы:
- **memegen, подписи — HTML-текст.** У memegen 211 шаблонов с полями в `config.yml`, MIT, ключ не нужен. Готовую картинку с подписью нельзя править, типографировать и печатать вектором.
- **Другие источники отвергли:** Tenor API закрыт, Klipy запрещает хранить файлы, у Imgflip поиск платный и водяной знак.
- **Шаблоны не лежат в пакете:** 211 картинок весят десятки мегабайт. Картинка — с GitHub memegen, без водяного знака, список — с api.memegen.link. Тесты подменяют их через `SLIDEMACHINA_MEMEGEN_ADDRESS`, GIPHY — через `SLIDEMACHINA_GIPHY_ADDRESS`.
- **`config.yml` читается без библиотеки YAML и только при вставке:** у всех 211 файлов одна плоская форма, своё чтение — около 40 строк. Поля уходят в `data-place` и `style`, файл не хранится.
- **Мем по ссылке, сборка встраивает:** папка не засоряется картинками, а файл всё равно открывается без сети. Файл рядом — галочка в панели или `--local`.
- **Подписи — дочерние элементы, а не проп `text={[…]}`:** тег с текстом правит редактор и обрабатывает типограф.
- **Oswald вместо Impact:** Impact — шрифт Microsoft, его нельзя класть в пакет. Oswald такой же узкий и жирный, под SIL Open Font License. Шрифт memegen по умолчанию кириллицы не знает.
- **GIF из GIPHY — MP4 через `<Video>`:** MP4 в разы легче, у `Video` уже есть пауза и печать. GIPHY — только с ключом, бесплатный ключ даёт 100 запросов в час. Повторный запрос берётся из памяти dev-сервера.
- **Мем встаёт новым слайдом:** в чужую раскладку панель его встроить не может. Поэтому `Slide` получил метку места в исходнике, как блок схемы.
- **GIF печатается первым кадром**, `poster` у `Image` не нужен: Chrome берёт первый кадр сам.

Интерфейс:
- **Мини-карта поверх слайда и выключена по умолчанию.** Когда она сжимала холст, слайд в разработке выглядел не так, как в зале.

Демо:
- **Живая обложка — куб из 27 частей на three.js**, мышь даёт параллакс, клик — ударную волну (на касании — удержание дольше 0,45 с). Сцена в `assembling-cube-stage.ts` грузится через `import()`, основной бандл остаётся без three.js.
- **Земля на слайде `machina-freeform` — один шейдер WebGL 2 без картинок** (около 10 КБ в gzip). Кадр дольше 20 мс уменьшает холст до 0,75. Копии получают неподвижный JPEG: живой WebGL в копиях терял контекст. Каждый запуск эффекта создаёт свой холст: `StrictMode` запускает эффект дважды.
- Надписи на слайдах с Землёй и кубом — обычные `h1` и `machina-lead` на `<Slide cover plain>`.

### Тесты

Помощники — `tests/test-helpers.ts` и `tests/scene-sampling.ts`. Слайды ищутся по заголовку или блоку (`findSlideNumber`), не по номеру. ## Конкуренты

На 27 октября 2026, звёзды GitHub — для масштаба.

- **reveal.js** (72 тыс.) — стандарт HTML-слайдов. В 6.0 есть обёртка `@revealjs/react`.
- **Slidev** (49 тыс.) — Markdown и Vue. Экспорт в PPTX снимками и объектами, MCP-сервер в `slidev dev`.
- **open-slide** (9 тыс., с апреля 2026) — ближе всех: React, `index.tsx`, холст 1920×1080, ставка на агентов.
- Marp, Spectacle, Quarto, presenterm, Touying — нишевые. Быстрее растут навыки для агентов, которые пишут слайды сами: frontend-slides, guizang-ppt-skill.
- mdx-deck, impress.js, remark заброшены. Motion Canvas и Remotion делают видео.

Чего у нас нет, по пользе для доклада разработчика:
1. Указка и рисование поверх слайда (Slidev, Quarto).
2. Навык для агента и MCP-сервер в шаблоне (open-slide, Slidev).
3. Формулы через KaTeX при сборке.
4. Пульт с телефона и показ у зрителей (multiplex у reveal.js, `--remote` у Slidev).
5. Режим чтения прокруткой с шагами (reveal.js 5). У нас только `?print` без анимации.
6. Картинка на весь экран по нажатию (lightbox в reveal.js 5.2).
7. Запуск кода на слайде, запись с камерой, автолистание — польза ниже.

Не берём: вертикальные слайды reveal.js (их заменяют разделы) и Markdown вместо JSX.

В чём мы лучше:
- Морфинг без разметки: общие элементы, слова и куски кода находятся сами. У reveal.js нужны `data-auto-animate` и `data-id`, у Slidev — только код в `magic-move`. Запрос Slidev #1527 открыт с 2024 года.
- Сноски `machina-source` и шаги в таблице — давние открытые запросы reveal.js (#2703, #2191).
- Схемы на ELK со стрелками, которые морфятся. У остальных Mermaid.
- 3D-сцены и типограф для русского и английского.
- Правка на слайде с записью в `index.tsx`. В Slidev редактор — панель с Markdown, в open-slide правит агент по комментарию.
- Один HTML-файл, файл под паролем, PDF по шагам, картинки в WebP.
- Репозиторий докладов с общей темой и списком.

## Ограничения и что осталось

- Тесты нестабильны под нагрузкой полного прогона, отдельно проходят. Шаг навигатора в тесте демо иногда не дожидается ленивой кнопки Agentation (5 с). Тест редактора упавший по таймауту оставляет свой dev-сервер на 5198, и следующий прогон бьётся о чужой сервер — нужен надёжный останов сервера в `finally`. Тест редактора изредка падает: заголовок не успевает остановиться для клика на шаге «E выключает редактор». Отдельно проходит. В логе dev-сервера бывает необработанный `AbortError: Transition was skipped` — прерванный переход, его стоит ловить.
- Имена переменных темы отстали от текстов: `--navigator-background` (теперь «обзор слайдов»), `--frame-*` (теперь «поля слайда»). Переименовать вместе с API, с совместимостью старых имён.

Движок и слайды:
- Заметок нет в печати и PDF. Заметки внутри своего компонента-обёртки не находятся. Синхронизация окон с диска проверена только в Chrome. Файл под паролем может спросить пароль и в окне докладчика. Нет указки, рисования и пульта с телефона.
- Нет морфинга по буквам: «3.14» → «3.15» перетекает словом целиком. Где нет `view-transition-class`, ушедшие и новые слова меняются одновременно.
- У `Code` нет явной пары для морфинга, с обычным `<pre>` он не морфится.
- Элемент с текстом, картинкой или своим фоном внутри морфится снимком, его скругление растягивается.
- Поля окна у слайда со светлой картинкой — цвет слайда под ней, а не средний цвет картинки.
- Верхней полосы нет, только нижняя.
- Тема в `style.css` вне слоёв с `--transition-duration` перебивает `--color-flood-duration`.
- Светлый логотип на насыщенном цветном фоне читается хуже, перекрашивать чужой файл движок не умеет.
- Формат 9:16 не перекомпоновывает слайды: колонки, широкий код и схемы сжимаются.
- `valign` не работает на слайде с `float`: там блочная раскладка.
- Картинка на обложке — только `<Image>` или `<Video>` без `stretch` и подписи.
- `align="right"` рассчитан на текст и обложки, не на код, схемы и сцены.
- Картинка с `float` выше текста в колонке растягивает колонку на свой нижний отступ.
- Блок движка прямо в `machina-columns`, без `<div>`, раскладывается неверно.
- Таблица сравнения не ограничивает число решений: пять и больше колонок сжимаются.
- Колонки обычной таблицы, кроме последней, не переносят текст.
- Источник шириной в картинку — только сразу под `Image`, `Video`, `Meme` или `QR`.
- `<figcaption>` вне `<figure>` не нравится валидатору HTML. Обернуть блок в `<figure>` нельзя: лишний уровень ломает подгонку в `[data-content]`.
- Внутри `machina-freeform` края `machina-pin` меряются от полей слайда, а не от блока.
- Скрытого раздела `<Section hidden>` нет. В репозитории `--hidden` действует на все презентации.
- Заливку цветом, `oklch(from …)` и слои полосы и мини-карты в Safari и Firefox не проверяли.

Типографика:
- Кавычки, разорванные элементом (`"<b>слово</b>"`), typograf не исправит.
- Длинное слово в названии раздела выступает за цифры номера («Режим разработки»).
- Предел строки рядом с `float` считается по наибольшей ширине картинки, 40 %.
- `$` команды в правой колонке висит в зазор между колонками.
- Трёхзначные номера строк не помещаются в левое поле слайда: код сдвигается на 12 px. Номер списка «10.» при размере 40 px висит почти до края слайда.
- Фон кода или клавиши в первой строке выступает над заглавными на свой отступ (около 7 px), в последней — вниз (около 10 px). Висит только фон в начале абзаца, ячейки или подзаголовка.
- Висят символьные ячейки, а не глифы: видимый край кода правее края абзаца на 0–2 px.

Схемы:
- Нет точных координат `x/y` у блоков, двусторонних и пунктирных стрелок, своей `direction` у `Group`.
- Стрелка морфится только целиком при тех же `from` и `to`. `Message` не морфится.
- Подпись стрелки может задеть соседнюю стрелку. ELK может поставить блок ниже соседа, и стрелки войдут не посередине.
- Ошибка ELK видна только в консоли, схема остаётся пустой.
- Текст схемы всегда 28 px. Широкие схемы на 4:3 и 9:16 уменьшаются, направление само не меняется.

3D:
- Нет стекла, точечного света и прожектора. Объекты не морфятся между слайдами. Текст сцены всегда смотрит вдоль оси z и не отбрасывает тень. Потерю WebGL-контекста движок не обрабатывает.
- Грань глянцевого куба под скользящим углом светлая: в ней отражается окружение.
- `Camera` с `position` не подгоняется, в демо кадр подобран числами. Кадр с `orbit` мельче кадра без облёта.
- В колонке сцена держит место под всё, что появится на шагах.
- Сейчас сцена в демо — украшение. Предложения по пользе для докладов: `<Layer>` — стопка слоёв архитектуры со стрелками; `<Bars values={[…]} labels={[…]}>` — объёмный график по шагам; `<Model src="./server.glb">` через GLTFLoader.
- Шейдер демо на слабой видеокарте и ударную волну куба на планшете не проверяли.

Печать:
- Обрезанный код гаснет под полупрозрачными полосами, Chrome пишет их мягкой маской. На тёмном слайде с нестандартным фоном полосы чуть другого цвета.
- Сцена на слайде с картинкой-фоном и SVG с полупрозрачным градиентом печатаются с мягкой маской.

PowerPoint:
- Файл не открывали в самом PowerPoint, только в Quick Look и разбором XML. Нужно проверить: нет окна «восстановить», анимации по щелчку, видео играет, `logo="center"` на месте.
- Зритель с установленным Onest всё равно видит Arial.

Сборка и шаблоны:
- Первый слайд файла — около 375 мс против 180 мс у reveal.js: React строит все слайды при загрузке. Ускорение меняет решение «все слайды в DOM» — отдельная стадия.
- Quick Look по пробелу руками не проверяли, только `qlmanage -t`. Своя `favicon` не доходит до страницы пароля и иконки Apple.
- Выгрузки на Speaker Deck нет: у сервиса нет API. Путь — `--pdf` и загрузка руками.
- Пакеты не опубликованы в npm, `create-slidemachina` ставит `slidemachina@^0.1.0`. Шаблон только на русском.
- Видео и картинки из `url()` в `style.css` не пережимаются. Предел картинок 3840×2160, для вертикальной презентации — 2160 px в высоту.
- Папка сборки открывается только с веб-сервера.
- Номера слайда в редакторе кода нет: TypeScript 7 пока не грузит плагины.
- Новые `style.css` и `theme/style.css` и правки `server-runtime/` требуют перезапуска `slidemachina dev`. Изменённые `lang` и `typography` доходят до слайдов из других файлов после их правки.
- `.tsx` из `theme/` типографируется по правилам английского.
- Удалённые презентации остаются в `dist/`. Презентация в папке `assets` столкнётся со стилями списка.
- Обложкам и PDF нужен Chrome, без него в списке только названия.

Редактор:
- Не правятся строковые пропсы (`title`, `label`, подпись стрелки), текст с вложенной разметкой целиком, видео и части сцены.
- Блок нельзя перенести в другую группу, из группы и левее первой колонки. В колонку блока, который на него указывает, запишется `column`, но блок останется правее.
- Кнопки слайда не двигают слайд внутрь раздела.
- Нет отмены Cmd+Z: отменяет редактор кода или git.
- «Ёлочки» и длинное тире типографа попадают в исходник.
- Перетаскивание на сенсорном экране не проверяли.

Мемы:
- Картинки шаблонов принадлежат авторам: MIT memegen касается кода. В демо только `jd` (автопортрет Жозефа Дюкре, общественное достояние) и `images/memes/orbit.gif` — облёт сцены демо.
- Повёрнутая подпись крутится вокруг центра, у memegen — вокруг угла поля.
- Без сети мемы по ссылке не видны в `slidemachina dev`, сборка с ними останавливается. Панель без сети шаблоны не найдёт.
- Нет оверлеев memegen, таймингов `start` и `stop` у GIF-шаблонов, стилей `default` и `mock`.
- При копировании из PDF буквы подписи удваиваются: обводка — второй проход текста.
- Поиск шаблонов — только по английским названиям.
- GIPHY проверен только на подмене API. «Powered by GIPHY» — текстом, а не логотипом.

Проверки:
- Safari и Firefox руками не проверяли: Cmd+P, сцены, `view-transition-class`.
- Сцена на 4:3 и `full` на тёмном слайде тестом не покрыты. Тест сцены смотрит пиксели холстов печати, а не PDF.

Предложения по API, не применённые: `QR color` дублирует `--qr-color`; `Image full` пересекается со `Slide background`; части схем могли бы принимать и `step`/`effect`, и `data-step`/`data-step-effect`; `SlidemachinaLogo` нужен только демо; тёмный фон по умолчанию для слайда со сценой или видео `full`.

Перенос с reveal.js — без конвертера, агент переносит по одной презентации:
- `class="fragment"` → `data-step`;
- `data-line-numbers` → `lines`;
- Mermaid → `Diagram` или `Sequence`;
- копии слайдов для шагов схемы → один слайд со `step`;
- `data-background-color` → `background`.

Тему `generic-raif.css` переносят в `theme/style.css`, шрифты ALS Hauss и Navigo — в `theme/fonts/`. Шрифты бренда платные и в npm не попадают.

Прочее:
- Имя `slidemachina` в npm не опубликовано. Домен и товарный знак не проверены. Папка проекта называется `presentation-engine`.
- Мотив стопки слайдов есть у Slideshare, название близко к `harmsm/slidemachine`. Если менять знак — менять силуэт, а не цвет.
