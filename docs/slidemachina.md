# slidemachina

Движок HTML-презентаций на React. Заменяет reveal.js 4 в презентациях `~/web/private-presentations` и `~/web/conference-presentations/revealjs`.

В документе итог стадий 1–27. Файлы стадий удалены, их история — в git.

## Что это и для кого

Презентация — один файл `index.tsx` с JSX-разметкой. Рядом `style.css` с темой и папка `images/`.

Движок для тех, кто пишет доклады в редакторе кода и хранит их в git: разработчиков, аналитиков, докладчиков на конференциях. Агент тоже пишет такие презентации: разметка простая, всё в одном файле.

Что умеет:
- разделы, хлебные крошки, навигатор с миниатюрами, полоса прогресса;
- шаги: списки, таблицы, колонки, части схем и сцен появляются по одному;
- переходы и морфинг: общие элементы соседних слайдов перетекают сами, по словам и по кускам кода;
- код с подсветкой Shiki, строки по шагам, код из файла;
- схемы с автораскладкой ELK и диаграммы обмена сообщениями;
- 3D-сцены на three.js;
- печать в PDF, один HTML-файл, папка, zip, файл под паролем;
- типограф для русского и английского;
- тезисы в одну фразу, фон из видео, GIF или веб-страницы, блок поверх вёрстки;
- хуки для своего кода: `useSlide()`, `onEnter`, `onLeave`, `onChange`;
- телефон и планшет: свайп и касание, навигатор на весь экран;
- редактор в браузере: текст, картинки, блоки схем и слайды правятся на слайде и пишутся в `index.tsx`; миникарта слайдов;
- мемы: картинка с подписями-текстом, шаблоны memegen, GIF из GIPHY, вставка по ссылке — с панели, командой или руками;
- репозиторий презентаций с общей темой и списком.

Чего нет: заметок и окна докладчика. В текущих презентациях пользователя нет ни одной заметки.

Название `slidemachina`: в нём есть и слайд, и движок, а через deus ex machina оно связано с театром. На момент выбора имя было свободно в npm и PyPI, на GitHub совпадений не было.

## Как начать

```bash
npm create slidemachina        # спросит: презентация или репозиторий
cd my-talk && npm install
npm run dev                    # то же, что npx slidemachina dev
npm run build                  # то же, что npx slidemachina build: спросит, что собрать
```

Шаблон — 10 слайдов: обложка, раздел, список по шагам, код по шагам, схема, два слайда морфинга, картинка на весь слайд, финал. Тексты шаблона на русском.

### `slidemachina dev`

```bash
slidemachina dev [папка] [--port 5173]
```

- Папка с `index.tsx` — одна презентация на `/`.
- Папка с презентациями — репозиторий: список на `/`, презентация на `/<папка>/`.
- Браузер открывается сам, только если команда запущена в терминале.
- Правка `index.tsx` и любого `.tsx` обновляет слайд без перезагрузки, слайд и шаг остаются прежними.
- Позиция в адресе: `#7` — слайд 7, `#7.2` — слайд 7 после двух шагов.

### `slidemachina build`

Без флагов спрашивает, что собрать. Флаги для CI складываются: `--html --folder --pdf` соберёт три варианта за раз.

| Флаг | Что получится | Файл в `dist/` |
|---|---|---|
| `--html` | Один HTML-файл: скрипты, стили, картинки, шрифты, воркер ELK внутри | `<папка>.html` |
| `--protected` | Тот же файл под паролем | `<папка>-protected.html` |
| `--folder` | Папка для сайта | `<папка>/` |
| `--zip` | Та же папка в zip | `<папка>.zip` |
| `--pdf` | PDF, страница на слайд | `<папка>.pdf` |
| `--steps` | PDF, страница на каждый шаг. Можно без `--pdf` | `<папка>-steps.pdf` |
| `--pptx` | PowerPoint: текст, фигуры, стрелки схем — объекты, шаги — анимации по щелчку | `<папка>.pptx` |
| `--out <папка>` | Куда положить результат, по умолчанию `dist` | |

- Пароль берётся из `SLIDEMACHINA_PASSWORD` или спрашивается в терминале. Флага `--password` нет: пароль в командной строке виден в списке процессов и в истории.
- Папка работает только с веб-сервера. Для просмотра с диска есть один файл.
- Сборка не пишет в папку, где лежит `index.tsx`: такая папка — исходники, сборка остановится.
- Для PDF и обложек нужен установленный Chrome. Без него сборка пишет, что его нужно поставить.

### `slidemachina meme`

```bash
slidemachina meme "this is fine"           # найти шаблоны memegen, а с ключом GIPHY — и GIF
slidemachina meme --template fine [папка]  # разметка мема с картинкой шаблона по ссылке
slidemachina meme --template fine --local  # то же, картинка сохранится в images/memes/fine.jpg
slidemachina meme --template fine --animated
slidemachina meme --gif <id> [папка]       # GIF из GIPHY в MP4
slidemachina meme --url <ссылка> [папка]   # картинка, GIF или видео по ссылке, в том числе со страницы
```

- По умолчанию мем ссылается на картинку в интернете: `src="https://…"`. В `slidemachina dev` браузер берёт её оттуда, сборка скачивает и встраивает. `--local` кладёт файл в `images/memes/` и пишет импорт.

- Команда для агентов и терминала. Каждая находка печатается с командой, которая её берёт.
- С `--local` скачанное ложится в `images/memes/` презентации. Команда печатает строку импорта, если она нужна, и разметку: блок с `<figcaption>` — ссылкой на источник. Имена компонентов — как в `index.tsx`: `Machina.Meme` или `Meme`.
- Поиск шаблонов — по id, английскому названию и ключевым словам memegen. Русский запрос шаблонов не найдёт, но GIPHY ищет и по-русски: кириллица в запросе — `lang=ru`.
- Без `SLIDEMACHINA_GIPHY_KEY` поиска GIF нет, команда так и пишет. С ключом рядом с GIF стоит «Powered by GIPHY», как требует GIPHY.
- Ссылка на страницу, а не на картинку, ведёт к картинке из `og:image` или `twitter:image`. Так работают ссылки на Reddit, Imgur и Know Your Meme.
- Тексты — на языке системы, как у остальных команд. Подпись источника — на языке презентации.

## Разметка

Все компоненты берутся одним импортом: `import * as Machina from "slidemachina"`, дальше `<Machina.Slide>`, `<Machina.Image>` и так далее. В таблицах ниже приставка `Machina.` опущена. Именованный импорт `import { Slide } from "slidemachina"` тоже работает.

```tsx
import * as Machina from "slidemachina";
import logoPicture from "./images/logo.svg";
import logoOnDarkPicture from "./images/logo-on-dark.svg";

export default (
  <Machina.Presentation title="Доклад" lang="ru" logo={{ light: logoPicture, dark: logoOnDarkPicture }}>
    <Machina.Slide cover>
      <h1>Доклад</h1>
    </Machina.Slide>
    <Machina.Section title="Раздел">
      <Machina.Slide>
        <h2>Заголовок</h2>
        <ul data-steps>
          <li>Первый пункт</li>
          <li>Второй пункт: <span data-step data-step-effect="highlight">выделено</span></li>
        </ul>
      </Machina.Slide>
    </Machina.Section>
  </Machina.Presentation>
);
```

`index.tsx` экспортирует готовый элемент, функция-компонент не нужна. Большой слайд можно вынести в свой файл и импортировать: настройки `lang` и `typography` он берёт из `index.tsx` своей презентации.

### Каркас

| Компонент | Пропсы |
|---|---|
| `Presentation` | `title`; `lang` (по умолчанию `en`); `align` (`left`, `center` или `right`, по умолчанию `left`); `logo` — строка, `{ light, dark }` или компонент с пропом `dark`; `transition`; `speed`; `breadcrumbsSeparator` — разделитель раздела и подраздела в крошках и навигаторе, по умолчанию `›`; `typography={false}` выключает типограф; `date` (`"2026-10-16"`) — для списка в репозитории; `aspectRatio` — формат слайдов, по умолчанию `"16:9"`; `progress={false}` убирает полосу прогресса; `onChange` — хук на каждое движение |
| `Section` | `title`; `cover={false}` убирает слайд раздела, `cover={<Slide>…</Slide>}` ставит свой слайд вместо стандартного, крошки и навигатор остаются. Вложенный `Section` — подраздел |
| `Slide` | `align` — `left`, `center`, `right`; `valign` — `top`, `center`, `bottom`; `cover`; `background` — цвет, картинка, GIF, видео или `{ iframe: "https://…" }`; `tone` (`dark` или `light`); `transition`; `speed`; `plain`; `logo` — `false` или место: `"top-right"` (по умолчанию), `"top"`, `"center"` над заголовком, `"bottom"`; `breadcrumbs={false}` или свой текст; `number={false}`; `className`; `onEnter`, `onLeave` — хуки |

- `Section` сам ставит первым слайд раздела: тёмный фон `--section-background`, крупный номер раздела («02», «02.1») и зерно. Номер и фон идут градиентом слева направо, как в логотипе: от фиолетового акцента к зелёному `--second-accent-color`. Цифры стоят по центру своих заглавных, как и название. Номер на всех разделах одного размера, цифры табличные. Название переносится по ширине цифр, слово длиннее выступает за них. `cover={<Slide>…</Slide>}` ставит свой слайд вместо стандартного.
- `<Slide cover>` — обложка: контент по центру, крупный `h1`, без крошек и номера.
- `align` ставит текст по горизонтали, `valign` — по вертикали. Без `valign` обложка и слайд с `align="center"` стоят посередине, остальные — сверху. Обложка снизу слева: `<Slide cover align="left" valign="bottom">`.
- Посередине контент стоит по буквам: от верха заглавных первой строки до базовой линии последней. Середина контента — середина слайда, у обложек, разделов и обычных слайдов одинаково. Если внизу есть крошки, номер или нижний логотип, сверху остаётся такое же поле, как снизу. Если внизу ничего нет, контент сверху вниз занимает рамку.
- Текст справа сверху уходит под логотип: от низа логотипа до заглавных заголовка `--heading-gap`, как под заголовком слайда.
- `<Image>` прямо в обложке занимает половину слайда, текст — другую. Картинка перед текстом в разметке стоит слева, после текста — справа. Зазор между ними `--columns-gap` (96 px), как между колонками. Картинка в натуральную величину, но не больше своей половины. Она прижата к краю рамки и стоит на той же высоте, что и текст: сверху, посередине или снизу. Картинка справа обходит логотип в углу.
- Тон фона движок считает сам по цвету, средней яркости картинки или первому кадру видео. На тёмном слайде светлый текст и логотип `dark`. Если `dark` не задан, светлый логотип белеет фильтром `--logo-filter-on-dark`.
- Сам тёмный слайд держит цвета темы, светлые версии `-on-dark` получают его дети. Поэтому `background="var(--accent-color)"` — акцент темы, а не его версия для тёмного фона.
- Видео в фоне узнаётся по расширению (`.mp4`, `.webm`, `.mov`, `.m4v`, `.ogv`) или `data:video/`. Оно играет без звука по кругу, пока слайд на экране, и грузится за два слайда, как `<Video>`. GIF — обычная картинка.
- `background={{ iframe: "https://…" }}` — страница под контентом. Она не принимает клики и фокус: клавиши остаются у презентации. Тон страницы не измерить: слайд берёт тон своего цвета, иначе задают `tone`. Страница живёт только на экране, в миниатюрах и печати её нет.
- `plain` прячет логотип, крошки и номер сразу. Нужен для мема или фото.
- `logo` у слайда — `false` или место: `"top-right"` (по умолчанию), `"top"`, `"center"` над заголовком, `"bottom"`. Нижний стоит на одной линии с крошками и номером, центральный — в потоке контента высотой 96 px.
- `aspectRatio` — пропорция `ширина:высота`: `"4:3"`, `"16:10"`, `"21:9"`, `"9:16"`, `"32:9"`. Формат один на всю презентацию: навигатор, миникарта, обложка в репозитории, печать и PDF. На экране холст растёт под окно, см. «Сетку». У отдельного слайда своего формата нет. Тип в TypeScript — `` `${number}:${number}` ``, экспортирован как `AspectRatio`.
- Обе части `aspectRatio` — конечные числа больше нуля. Иначе сборка и `slidemachina dev` останавливаются с сообщением: строку в `index.tsx` проверяет плагин исходников, значение из выражения — сам `Presentation`. Слайды под новый формат движок не перекомпоновывает.
- Публичные имена — простые английские слова. Правило «имена от 8 символов» действует только внутри движка.

### Шаги

- Шаг без номера идёт следующим после всех шагов выше. `step={3}` и `data-step={3}` ставят шаг ровно на номер 3.
- Эффекты: `rise` (по умолчанию: появляется и чуть поднимается), `fade`, `scale`, `highlight`, `dim`.
- Шагом становится любой тег с атрибутом `data-step`: `<li data-step>`, `<p data-step={3} data-step-effect="fade">`. Часть строки — `<span data-step>`.
- `data-steps` на `<ul>`, `<ol>`, `<table>` или `<div className="machina-columns">` делает шагом каждый пункт, строку `<tbody>` или колонку. `data-steps={3}` ставит их на шаги 3, 4, 5. `data-step-effect` рядом задаёт эффект всем пунктам, сам список остаётся видимым.
- Свои `data-step` и `data-step-effect` у пункта сильнее, чем у списка. Можно и не ставить `data-steps`, а расставить `data-step` по пунктам руками.
- `data-steps` раскрывает `markReachedSteps` в `slide-steps/step-visibility.ts`: пункты получают обычные `data-step`, поэтому печать, морфинг и схемы ничего не знают о списках. Записанные атрибуты движок помечает `data-sequence-step` и снимает при каждой разметке: правка `data-steps` без перезагрузки не оставляет старых шагов.
- Строчные теги вроде `span`, `b`, `em`, `a` с шагом получают `inline-block`, иначе не работают `rise` и `scale`.
- TypeScript проверяет значение `data-step-effect` и подсказывает эффекты, `data-steps` принимает `true` или номер.
- При возврате на прошлый слайд он открывается на последнем шаге.

### Блоки

Оформление пишется обычными тегами и классами `machina-…`. Компоненты остались только у блоков с поведением: подгонкой, загрузкой, раскладкой, шагами внутри.

```tsx
<Slide>
  <h2>Числа</h2>
  <div className="machina-columns" data-steps>
    <figure className="machina-big-number">
      <p>8</p>
      <figcaption>переходов между слайдами</figcaption>
    </figure>
    <figure className="machina-big-number">
      <p>1</p>
      <figcaption>файл на всю презентацию</figcaption>
    </figure>
  </div>
  <Source>Источник: замер в октябре 2026</Source>
</Slide>
```

| Компонент | Пропсы |
|---|---|
| `Image` | `src`, `alt`, `stretch`, `full`, `fit` (`contain` или `cover`), `float` (`left` или `right`); внутри — `<figcaption>` |
| `Video` | `src`, `poster`, `stretch`, `full`, `fit`, `loop` (по умолчанию `true`), `controls`; внутри — `<figcaption>` |
| `Source` | только текст внутри |
| `QR` | `value` — ссылка или текст; `logo` — картинка в середине; `correction` (`L`, `M`, `Q`, `H`, по умолчанию `M`); `color`; внутри — `<figcaption>` |
| `Meme` | `src`, `alt`, `stretch` (по умолчанию, если нет `float`), `float` (`left` или `right`); внутри — подписи, каждая своим тегом (`<p>`), и `<figcaption>` |

| Разметка | Что это |
|---|---|
| `<ul>`, `<ol>` | Список. Маркер — шестилучевая звёздочка, вырезанная `clip-path: shape()`, размер 0,5 em. Маркеры и номера висят в поле слева. Их правый край в `--hanging-marker-gap` (0,3 em) от текста |
| `<table>` | Таблица. Шапка — `<thead>`, строки — `<tbody>`. Вся таблица одним начертанием и кеглем `--table-text-size`, шапка приглушённым цветом, строки основным |
| `<table className="machina-compare">` | Сравнение двух–четырёх решений. Первая колонка — критерии, решения делят остальное поровну и стоят по центру. Отметки — `<td className="machina-yes" />` (галочка цвета акцента) и `<td className="machina-no" />` (серый прочерк) |
| `<div className="machina-columns">` | Колонки. Каждый прямой потомок — колонка |
| `<figure><blockquote>…</blockquote><figcaption>Автор</figcaption></figure>` | Цитата с автором. `<blockquote>` без `figure` — цитата без автора |
| `<figure className="machina-big-number"><p>42</p><figcaption>…</figcaption></figure>` | Большое число с подписью |
| `<figcaption>` вне `figure` | Подпись блока над ней |
| `<p className="machina-lead">` | Вводная фраза: кегль текста, приглушённый цвет. Сразу под заголовком слайда — подзаголовок: стоит в `--block-gap` от заголовка, а до контента под ним `--heading-gap` |
| `<p>` | Основной текст |
| `<p className="machina-note">` | Пометка мелким шрифтом: кегль и цвет подписи. От текста над ней отступает на `--block-gap` |
| `<p className="machina-thesis">` | Тезис: одна фраза в центре слайда по обеим осям, кеглем `--display-size`, без заголовка. `machina-thesis-small` — кеглем `--heading-size`, для фразы длиннее. Цвет — проп `background` слайда, для тезисов в теме есть мягкие `--accent-soft-color` и `--second-accent-soft-color` |
| `<div className="machina-pin">` | Блок вне потока, поверх контента. `machina-pin-top`, `-bottom`, `-left`, `-right` прижимают его к краю слайда, а не области контента. Сдвиг Tailwind (`translate-x-1/3`) выносит блок за край экрана. Размер от слайда — `cqh` и `cqw`: `h-[50cqh]`. Блок с `machina-pin-bottom`, `-left` и `-right` сразу — полоса: контент встаёт над ней |
| `<code>`, `<kbd>` в тексте | Код и клавиша: плоская плашка вокруг заглавных, кегль текста вокруг, строку не раздвигает. У клавиши ещё тонкая рамка. Плашка в начале строки висит в поле на свой боковой отступ, буквы стоят на линии текста |

- Набор классов взят из старых презентаций: там повторялись подпись (`caption`, 125 раз), источник (`source`, 67), колонки (`two-col`, `raif-columns`), большое число (`bignum`). Кегли — из шкалы темы, новых нет.
- `Image` без пропсов — в натуральную величину, но не больше места на слайде.
- Картинки, видео и мемы плоские: без рамки и тени, как код. На тёмном слайде вокруг них волосяная линия `--media-edge-on-dark`: тёмная картинка не сливается с фоном.
- `stretch` — на всё свободное место под заголовком, по центру. По умолчанию `fit="contain"`: видно целиком, скругление обнимает саму картинку.
- `full` — на весь слайд под текстом и рамкой. По умолчанию `fit="cover"`.
- `float="left"` или `"right"` — текст после картинки обтекает её. Картинка не шире `--float-max-width` (40 %). Верх картинки — на линии заглавных букв первой строки рядом. До текста сбоку `--float-gap` (40 px). Снизу столько же, до заглавных букв следующей строки. Маркеры списка висят в этом зазоре, текст сдвигается на их вынос, как в колонках. Предел строки у текста рядом растёт на ширину картинки и зазор: строки рядом с ней не короче обычных. Блоки после картинки, кроме `p`, `ul`, `ol`, `h3`, встают под неё. Картинка не выше места под блоками сверху: высокая становится уже и кончается на нижней линии контента, а не заходит на крошки и номер.
- `<figcaption>` внутри `Image`, `Video` или `QR` — подпись картинки: сразу под ней, от её левого края. С `stretch` картинка уменьшается, чтобы подпись в одну строку встала на нижнюю линию контента. Под узкой картинкой короткая подпись не переносится, а выступает за неё, но не шире области. На центрированном слайде картинка и подпись стоят по центру.
- `<figcaption>` сразу после `Scene`, `Diagram`, `Sequence`, `Code`, `<table>` или `<figure>` — подпись этого блока: стоит на `--caption-gap` от его края, выровнена по нему. Под сценой подпись по центру: сцена рисует объекты в середине холста.
- `<figcaption>` после другого блока — подпись по левому краю контента. `machina-note` выглядит так же, но не прилипает к блоку над ней.
- `Video` играет без звука и по кругу, пока его слайд на экране. Грузится, когда до слайда два слайда или меньше.
- Колонка — `<div>`, в нём что угодно: несколько блоков встают друг под другом. Один список, абзац или большое число можно ставить колонкой без `<div>`. Блок движка (`Code`, `Diagram`, `Scene`, `QR`, `Image`) кладут в `<div>`: он меряет место по своей колонке. Колонки с `Image stretch`, `Meme`, `Scene` или `QR` растут до низа контента, иначе растянутому блоку негде расти.
- Между колонками `--columns-gap` (96 px), полтора поля: соседние колонки читаются отдельно, и маркер или плашка кода, висящие в зазор, оставляют до соседа целое поле.
- Колонки равной ширины. Свои доли — обычным CSS: `style={{ gridTemplateColumns: "3fr 2fr" }}`. У колонок нет минимальной ширины по содержимому, поэтому длинный код не ломает доли.
- `machina-big-number` занимает всю колонку. Число шире колонки уменьшает кегль, но не ниже 64 px. Подгонку делает слайд: `useBigNumberFitting` в `presentation-core/width-fitting.ts` находит числа по классу. Подпись — в `--caption-gap` под базовой линией числа, шириной в колонку.
- `Source` — сноска к блокам над ним: стоит в `--block-gap` под ними, над ним тонкая линия на всю ширину контента. Сразу под картинкой, мемом или видео сноска шириной в картинку и стоит под ней. Длинная ссылка переносится.
- Таблица начинается заглавными первой строки и кончается базовой линией последней, как текст. В обычной таблице колонки, кроме последней, шириной по содержимому и без переноса, последняя забирает остальное.
- Кавычки у `<blockquote>` ставит CSS по языку страницы: «…» для ru, “…” для en.
- QR и картинку ставят в левую колонку, текст — в правую. Долю колонки с QR подбирают так, чтобы код занял её по ширине, иначе между кодом и текстом остаётся дыра. В демо — `gridTemplateColumns: "3fr 7fr"`: справа код и список, низ подписи QR на базовой линии последнего пункта, колонки одной высоты.
- `QR` занимает всё свободное место, как `Image stretch`, и остаётся квадратным. На слайде с `align="left"` стоит от левого края текста, на центрированном — по центру. Колонка с кодом растёт до низа контента.
- Плотность точек задаёт `correction` — уровень коррекции ошибок. Чем он выше, тем больше точек и тем больше повреждений код переживает. Движок берёт самый маленький код для этого уровня и поднимает коррекцию, пока код не растёт: точки крупные, их видно с дальних рядов.
- С `logo` коррекция всегда `H`. Середина кода под логотипом очищается: около 6 % площади.
- Цвет точек — `color` или `--qr-color` в теме. По умолчанию — цвет текста: на тёмном слайде код светлый. Фон прозрачный, рамки и тени нет.

```tsx
<Meme src={jdPicture} alt="Жозеф Дюкре">
  <p>Извольте вставить мем</p>
  <p data-place="50 80 50 20" style={{ color: "black" }}>не покидая слайдов</p>
  <figcaption>Шаблон: Joseph Ducreux, knowyourmeme.com/memes/joseph-ducreux-archaic-rap</figcaption>
</Meme>
```

- Мем настраивается в теге, файлов настроек нет. Первая подпись встаёт сверху, вторая снизу, остальные посередине: полосы в пятую часть картинки, как у memegen по умолчанию.
- `data-place` на подписи двигает её: `top`, `bottom`, `center` или `"left top width height"` в процентах картинки. Цвет, поворот, регистр и начертание — обычный `style` или классы на подписи.
- Подписи — обычный текст поверх картинки. Их правит редактор (E), проходит типограф, печать оставляет их вектором.
- Кегль подписи — самый крупный, при котором текст влезает в поле, но не больше девятой части высоты картинки (четверти у повёрнутой). Так считает и memegen. Подгонка повторяется при наборе в редакторе, после загрузки шрифта и картинки.
- Шрифт — Oswald 700, капслок, белый, чёрная обводка под заливкой. Толщина обводки — двенадцатая часть кегля, от 1 до 3 пикселей картинки, как в memegen. Тёмная подпись идёт без обводки: цвет читается со страницы.
- Мем занимает свободное место, как `Image stretch`, скругление — как у картинки. С `float` — обтекание, как у картинки. С `stretch={false}` — размер картинки, не шире своего места: так мем ставят в `machina-pin`.
- `src` — импорт файла или адрес в интернете. Адрес сборка скачивает в `~/.cache/slidemachina/remote-media` и встраивает, как любую картинку.

### Код

```tsx
<Code src="./agent.py" lines="10-13 | 27-30" numbers />
<Code lang="ts" title="app.ts">{`const answer = 42;`}</Code>
```

| Проп | Что делает |
|---|---|
| `lang` | Язык. Без него — по расширению файла из `src` |
| `src` | Код из файла. Правка файла обновляет слайд без перезагрузки |
| `lines` | Строки по шагам: `"1 | 3-4 | 6"`. Первая часть видна сразу, каждая следующая — шаг. Пустая часть — все строки без приглушения |
| `numbers` | Номера строк слева от кода |
| `title` | Заголовок над кодом. У кода из файла — имя файла |

- Подсветка — Shiki при сборке, темы `github-light-high-contrast` на светлых слайдах и `github-dark-default` на тёмных. В браузер уходят слова с двумя цветами: `[текст, цвет на светлом, цвет на тёмном]`. Тему из трёх цветов бренда пробовали: код с ней выглядел погашенным, поэтому подсветка полная.
- Метка в комментарии `# [!code highlight]` подсвечивает строку на весь слайд и не съезжает при правке кода.
- Остальные строки приглушены (`--code-dim-opacity`). Длинный код на шаге плавно прокручивается к подсвеченным строкам, края растворяются.
- Длинная строка уменьшает кегль под ширину, но не ниже 20 px. Дальше строки переносятся с отступом. Горизонтальной прокрутки нет.
- Однострочный код без заголовка — крупная команда 40 px без плашки. Строка обрезана по буквам, как абзац: под заголовком ровно `--heading-gap`. У `bash` со знаком `$`, он висит в поле, как маркер списка. Правый край `$` на одной линии с маркерами и номерами списка под командой.
- Номера в `lines` и `numbers` — номера строк исходника. У кода из файла это номера строк файла: файл показывается с первой строки, пустые строки в начале не срезаются. Строка, где была только метка `[!code …]`, пропадает, но номера следующих строк не сдвигаются.
- Номера строк приглушены, у подсвеченных строк — цвет текста. Номера мельче кода: `--code-number-scale` (0,6). Номер рисует CSS (`::before` с `attr(data-code-line)`), поэтому при копировании кода номеров нет. Номер стоит в строке, а не поверх неё: его базовая линия совпадает с кодом при любом кегле.
- Плашка кода висит, как кавычка: её фон и отступ выходят в поле слева, символы кода стоят на линии текста. Правый край плашки — на правой линии рамки. Номера тоже висят в поле. Плашка с номерами стоит в `--code-numbered-edge-gap` (12 px) от края слайда, внутри неё до номеров ещё 12–13 px. От номера до кода `--code-number-gap` (19 px): больше зазора у маркера списка, номера читаются отдельной колонкой. Трёхзначные номера сдвигают код вправо.
- Код задан переменной, а не строкой — плагин его не видит, `Code` покажет текст без цветов.

### Схемы

```tsx
<Diagram>
  <Box id="slides">index.tsx<small>слайды</small></Box>
  <Group id="build" title="Сборка" step>
    <Box id="vite">Vite</Box>
    <Box id="shiki">Shiki</Box>
    <Arrow from="vite" to="shiki" />
  </Group>
  <Arrow from="slides" to="vite" label="HTTP" step />
  <Focus on={["build"]} step />
</Diagram>
```

| Компонент | Пропсы |
|---|---|
| `Diagram` | `direction` (`right` или `down`, по умолчанию `right`) |
| `Box` | `id`, `column`, `first`, `last`, `step`, `effect`; текст внутри, вторая строка — в `<small>` |
| `Group` | `id`, `title`, `step`, `effect`; блоки и стрелки внутри |
| `Arrow` | `from`, `to`, `label`, `id`, `step`, `effect` |
| `Focus` | `on` — список `id`; `step`. Без `on` фокус снимается |

- Раскладку считает ELK в воркере. Порядок блоков в разметке — порядок на схеме. Блок стоит на колонку правее тех, кто на него указывает. `column={n}`, `first`, `last` ставят блок в нужную колонку. В группе колонки считаются от её рамки. Блок не встаёт в колонку блока, который на него указывает: стрелку внутри колонки ELK не рисует. Такой блок уходит на колонку правее.
- Скрытые шаги держат место: раскладка одна на все шаги, блоки не прыгают.
- Стрелка может идти от группы: `from="build"`. Подпись стрелки встаёт над её самым длинным отрезком.
- Блок — белая плашка с тонкой рамкой, без тени. Фокус приглушает остальное. Выбранный блок получает рамку цвета акцента, без кольца и тени. Стрелка горит, если выбрана она или оба её конца.
- Группы, которые стоят рядом, начинаются на одной линии: группа ниже соседней растёт вверх, блоки в ней стоят на месте.
- Излом стрелки стоит посередине промежутка между блоками. ELK ставит его сразу у начала стрелки, движок переносит.
- Схема занимает свободное место: растёт до `--diagram-max-scale` и вписывается по ширине и высоте. Схема, которой до правой линии рамки не хватает до 3 %, дотягивается до неё. Маленькой схеме в колонке слайд даёт расти: `className="[--diagram-max-scale:1.5]"`, так в демо на слайдах «Пишете теги, получаете схему» и «Попробуйте: нажмите E» схема доходит до правой линии.
- Межстрочный интервал текста схемы — `--secondary-line-height`, трекинг как у текста.
- Эффект шага по умолчанию: у блоков `rise`, у групп и стрелок `fade`. Стрелка рисуется от начала, наконечник появляется последним.

### Диаграмма обмена

```tsx
<Sequence>
  <Actor id="vite">Vite</Actor>
  <Actor id="react">React</Actor>
  <Message id="request" from="react" to="vite" label="GET /index.tsx" step />
  <Message from="vite" to="react" label="код" reply step />
  <Focus on={["request"]} step />
</Sequence>
```

| Компонент | Пропсы |
|---|---|
| `Sequence` | только части внутри |
| `Actor` | `id`, `step`, `effect`; имя внутри |
| `Message` | `from`, `to`, `label`, `reply` (пунктир), `id`, `step`, `effect` |

- Участники — колонки, сообщения — строки. ELK здесь не нужен, раскладка на CSS Grid.
- Колонки делят ширину контента: первый участник начинается на левой линии, последний кончается на правой.
- Сообщение самому себе рисуется петлёй высотой в шаг сообщений. У последнего участника петля идёт влево: справа рамка.
- Блок схемы перетекает в участника с тем же `id`.

### 3D-сцены

```tsx
<Scene>
  <Cube id="cube" size={1.3} position={[0, 0.65, 0]} material="glossy" />
  <Sphere size={1.1} position={[1.7, 0.55, 0]} color="#F2B8A0" step />
  <Move on="cube" position={[-1.7, 0.65, 0]} rotation={[0, 70, 0]} step />
  <Camera position={[5.5, 3.2, 6.5]} target={[0, 0.8, 0]} step />
  <Text position={[0, 2.2, 0]} size={0.6} step>Готово</Text>
</Scene>
```

| Компонент | Пропсы |
|---|---|
| `Scene` | `orbit` (`true` или градусы в секунду, по умолчанию 8); `floor={false}` убирает тень на полу; `full` — на весь слайд под текстом |
| `Cube` | `size` — число или `[ширина, высота, глубина]`, по умолчанию 1 |
| `Sphere` | `size` — диаметр, по умолчанию 1 |
| `Text` | `size` — высота шрифта, по умолчанию 0,5; текст внутри |
| `Light` | `position`, `color`, `intensity` (по умолчанию 1,6), `step` |
| `Camera` | `position`, `target`, `fov` (по умолчанию 30), `step` |
| `Move` | `on` — `id` объекта; `position`, `rotation`, `scale`, `color`, `step` |

- Общие пропсы объектов: `id`, `position` (`[x, y, z]`), `rotation` (градусы), `scale`, `color` (любой цвет CSS, в том числе `var(--accent-color)`), `material` (`matte`, `glossy`, `metal`), `spin`, `step`.
- Без `<Light>` в сцене один мягкий свет сверху слева. С `<Light>` — только заданные, тень отбрасывает первый.
- Камера без `position` подбирает кадр сама. В кадр входят все места, где объект бывает на любом шаге, и тени на полу. Объекты заполняют кадр: по ширине стоят по центру, по высоте — от верхнего края, как текст в соседней колонке. Кадр считается по точкам самих объектов, а у текста — по буквам.
- Сцена `full` лежит под текстом, а объекты встают на свободное место под ним, внутри рамки. Если под текстом меньше четверти высоты, объекты занимают всю область контента. Тени полноэкранной сцены могут выйти за рамку: холст на весь слайд, тень не обрезается.
- С `orbit` кадр подобран для всего облёта: объекты не выходят за рамку ни под каким углом.
- `Camera` с `position` ставит камеру точно туда: кадр задаёт автор.
- Объект на своём шаге вырастает из точки сразу своим цветом. Всё, что движется, плавно догоняет цель.
- При уменьшении движения в системе нет вращения и облёта, шаги переключаются сразу.
- three.js грузится отдельным файлом и только если в презентации есть сцена.

### Морфинг

Два элемента соседних слайдов перетекают друг в друга, если совпали:
- атрибут `morph="имя"` на обоих — работает на любом теге;
- тег и текст у `h1–h6, p, li, blockquote, figcaption`;
- `src` у `img, video, iframe`;
- текст `pre`.

Тексты с общими словами (не меньше половины слов более длинного текста) морфятся по словам: общие слова едут на новое место, ушедшие гаснут, новые проявляются. Ушедшее слово едет вместе с ближайшим общим словом: строка движется целиком и не рвётся. Пара одинаковых текстов тоже морфится по словам: каждое слово едет и меняет кегль весь переход, и число не двоится. Блоки `Code` морфятся по кускам кода: сначала совпадают строки, потом куски в изменённых строках. Номера строк не едут, они гаснут и проявляются вместе с остальным текстом блока. Блок схемы морфится в блок или участника с тем же `id`.

Простую фигуру рисует сам слой перехода: фон, рамку, скругление, тень и прозрачность. Так скругление не растягивается вместе со снимком, а плавно меняется от старого к новому. Простая фигура — элемент, у которого всё содержимое морфится своими слоями, например карточка с подписью и столбиками или блок схемы. У картинки и видео содержимое и есть снимок: слой обрезает оба снимка своим скруглением, и углы плавно меняются вместе с размером. Новый блок схемы без пары проявляется на своём месте во второй половине перехода, а не растёт вместе с группой. Остальные элементы морфятся снимком.

## Переходы

`transition` у `Presentation` или `Slide`: `auto` (по умолчанию), `morph`, `slide`, `fade`, `zoom`, `cube`, `flip`, `none`.

- `auto`: если у соседних слайдов есть общие элементы — `morph`, иначе `slide`.
- При листании вперёд берётся переход входящего слайда, назад — уходящего, то есть более позднего из двух.
- `slide`, `zoom`, `cube`, `flip` двигают слайд целиком: с фоном, логотипом, крошками и номером. За слайдами видна сцена `--transition-stage-background`. Сцена занимает только холст: поля по краям окна во время перехода не меняют цвет. `slide` и `zoom` идут внутри холста, как на экране: на 4:3 в широком окне слайд не ждёт в поле и не обрывается на его краю.
- `morph` и `fade` двигают только содержимое. Фон, логотип, крошки и номер стоят на месте. Новый фон с логотипом проявляется поверх старого с 30 до 70 % перехода. Между светлым и тёмным слайдом фон меняется сразу, на середине: смесь белого и тёмного — серый кадр. Номер, крошки и логотип, которых нет на новом слайде, гаснут в первой половине, как содержимое. Новый номер проявляется во второй: цифры двух номеров не накладываются.
- `zoom` уносит старое содержимое к зрителю за первую четверть перехода, новое проявляется после: два текста не видны сквозь друг друга.
- `flip` поворачивает слайд в перспективе 7,4 полуширины слайда: ближний край не выходит за окно.
- Стрелка схемы с `morph="diagram-arrow:from:to"` морфится парой с такой же стрелкой на соседнем слайде. Стрелки без пары гаснут и проявляются отдельно. Слой стрелки — её линия с наконечником и подписью, а не вся схема.
- Шаги внутри слайда идут без перехода.
- `speed` у `Presentation` или `Slide` — скорость переходов и шагов: `fast`, `normal` (по умолчанию) или `slow`. Число — во сколько раз быстрее `normal`: `speed={2}` вдвое быстрее, `speed={0.5}` вдвое медленнее. `fast` — 1,5, `slow` — 0,7.
- Как и с `transition`, при листании вперёд берётся скорость входящего слайда, назад — уходящего. Шаги идут со скоростью своего слайда.
- Длительности при `normal`: `--transition-duration` 0,4 с, `--morph-duration` 0,55 с, `--rotation-duration` 0,6 с для куба и переворота, `--step-duration` 0,3 с. Тема меняет их, `speed` делит.
- Если в системе включено уменьшение движения, перехода нет.
- Быстрые нажатия не теряются: прерванный переход доигрывает свой слайд, следующий начинается с него.

## Клавиши и панель

| Клавиша | Что делает |
|---|---|
| →, ↓, PageDown, пробел | дальше |
| ←, ↑, PageUp, Shift+пробел | назад |
| Home, End | первый и последний слайд |
| Esc или O | навигатор |
| цифры и Enter | слайд с этим номером |
| B или . | пауза: чёрный экран и кнопка «Вернуться к слайду · B» |
| F | полный экран |
| H | спрятать панель |
| E | редактор, только в `slidemachina dev` |
| M | миникарта, только в `slidemachina dev` |
| Cmd+P или Ctrl+P | печать, когда все схемы и сцены готовы |

Адрес с `?overview` открывает презентацию сразу в навигаторе. Так демо работает витриной всех компонентов. Навигатор сам ставит и убирает `?overview` в адресе, когда его открывают и закрывают, так что ссылку на витрину можно просто скопировать.

- Буквы узнаются по физической клавише, поэтому работают в русской раскладке.
- Клавиши с Cmd, Ctrl и Alt движок не трогает, кроме Cmd+P.
- Мышь не листает. На телефоне и планшете листает свайп или касание: левая треть — назад, остальное — дальше. Касание ссылок, кнопок, видео, панели и навигатора работает как обычно, в редакторе касание не листает.
- В паузе любая клавиша листания, свайп и касание только возвращают слайд: зал не видит, как слайд меняется за чёрным экраном. Весь чёрный экран — кнопка возврата.
- Полоса прогресса — линия `--progress-height` (6 px) по нижнему краю холста, градиентом от акцента ко второму акценту. Градиент всегда во всю ширину, видимую часть режет `clip-path`. У полосы и миникарты свои слои перехода поверх слайдов: при `slide`, `cube` и других переходах они не пропадают.
- Хуки для своего кода: `<Presentation onChange={({ slide, step }) => …}>` — после каждого движения и при загрузке, номер слайда с 1, шаг с 0. `<Slide onEnter onLeave>` — слайд пришёл на экран и ушёл. `useSlide()` в своём компоненте — `{ number, step, isCurrent, isCopy }`, на пройденных слайдах `step` — `Infinity`. Миниатюры и печать хуки не вызывают. Компонент можно держать прямо в `index.tsx`, над слайдами: правка рисует новые слайды без перезагрузки, слайд и шаг остаются, а состояние `useState` таких компонентов сбрасывается. Компонент в своём файле сохраняет состояние.
- Enter без набранного номера работает как обычно, например открывает ссылку в фокусе.

Навигатор — сетка миниатюр по разделам на всё окно, поля тоже. На 16:9 шесть колонок по 268 px, на 4:3 — четыре, на 9:16 — три. На маленьком экране колонок меньше: миниатюра не уже 140 px экрана, на телефоне в вертикальном положении навигатор — весь экран. Открытие уменьшает текущий слайд в его миниатюру, закрытие увеличивает выбранную миниатюру в слайд: View Transitions, два снимка и один слой, слайды заново не раскладываются. Миниатюры в формате презентации. Выбранная миниатюра и миниатюра в фокусе клавиатуры обведены `--accent-color-on-dark` толщиной 3 px: навигатор всегда тёмный. При наведении обводка цвета `--hairline-color-on-dark`. У каждой миниатюры волосяной край, тёмный слайд не сливается с фоном. Ряды гаснут у верхнего и нижнего края прокрутки, выбранная миниатюра при прокрутке не заходит в это затухание. Стрелки двигают выбор по экрану, Enter или клик открывает слайд.

Панель управления — тёмная капсула снизу по центру, на нижней линии рамки. Цвет панели, меню и навигатора один: `--dark-background`. Снаружи у капсулы волосяная линия: на светлом слайде её не видно, на тёмном она отделяет панель от фона. Не масштабируется: кнопки по 44 px на любом экране. Наведение — диск 36 px внутри кнопки, фокус клавиатуры — кольцо 2 px цвета `--accent-color-on-dark` вокруг этого диска. Меню печати стоит по центру панели. Переключатель «Раскадровка» и кнопка «Распечатать» — `--accent-color-on-dark`, у кнопки тёмный текст. В интерфейсе одно начертание — обычное. Кнопки:
- «Все презентации» — только у презентации из репозитория;
- навигатор;
- полный экран;
- печать с меню: «Распечатать», «Печатная версия» и переключатель «Раскадровка»;
- в `slidemachina dev`: миникарта, карандаш редактора и его кнопки слайда, смайлик панели «Мем» и кнопка Agentation;
- скрыть панель.

Панель гаснет сама через 2 с без движения мыши и возвращается при движении или касании. Панель не гаснет, пока мышь над ней, открыто меню печати или окно «Мем», пишется заметка. H прячет панель совсем, на её месте остаётся тёмный кружок со стрелкой, без прозрачности и серого ободка. Выбор хранится в `localStorage`.

Agentation гаснет и прячется вместе с панелью: при автоскрытии, после H и в паузе.

Если под холстом есть место для панели (76 px и больше, телефон в вертикальном положении), панель встаёт под слайд, а не на него. Кнопки «Полный экран» нет, где браузер не умеет полный экран для страниц (iPhone).

Миникарта — только в `slidemachina dev`: полоса 168 px со всеми слайдами поверх правого края окна, как миникарта в редакторе кода. По умолчанию выключена, включают кнопка на панели и M, выбор хранится в `localStorage`. В полном экране и под навигатором её нет. Миниатюра рисует копию слайда, только когда она рядом с видимой частью полосы. Текущий слайд прокручивается в середину полосы.

### Agentation

[Agentation](https://www.npmjs.com/package/agentation) работает только в `slidemachina dev`. Кликаешь на элемент слайда, пишешь замечание, оно уходит в Claude Code через MCP-сервер `agentation-mcp` на порту 4747. В заметке есть место в файле: `index.tsx:42:7`.

- Страница один раз спрашивает dev-сервер, отвечает ли порт 4747. Сервера нет — заметки хранятся в браузере.
- Кнопка Agentation живёт вне панели, в корне страницы. Движок ставит её над пустым местом в панели и прячет через `visibility`: `opacity` не доходит до её частей в shadow DOM и верхнем слое.
- `SLIDEMACHINA_AGENTATION=off` выключает Agentation. Так запускаются тесты.
- В сборку Agentation не попадает.

## Печать и PDF

- Cmd+P печатает слайд на страницу. Страница — размер холста: 1920×1080 на 16:9, 1440×1080 на 4:3, 1080×1920 на 9:16. `@page size` пишет `<Presentation>` в свой `<style>`: в CSS-файле переменные в `@page` не работают. Фоны печатаются без галочки «Фон».
- Страница печати изолирована `contain: strict`. Без этого несжатая сцена схемы шире вертикальной страницы, и Chrome уменьшал все страницы PDF под неё.
- Диалог печати открывается, когда схемы разложены, сцены нарисованы, а шрифты и картинки загружены.
- «Раскадровка» в меню печати — страница на каждый шаг. Выбор запоминается и работает для Cmd+P и печатной версии.
- Печатная версия — все страницы столбиком в браузере, как в reveal.js. Открывается из меню печати или по адресу `?print`, с раскадровкой — `?print=steps`. Внизу панель: назад к слайдам (Esc), число страниц, «Раскадровка» и «Распечатать».
- `slidemachina build --pdf` печатает печатную версию через Chrome без окна. `--steps` — страница на шаг.
- Не печатаются панель, навигатор, миникарта, пауза и Agentation.
- В печати нет мягких масок: Preview на macOS рисует их плашками. Холст сцены на слайде одного цвета печатается непрозрачным, залитым цветом слайда. Обрезанный код гаснет под липкими полосами цвета блока кода. Номер раздела — SVG с `linearGradient` на экране и стопка сплошных копий в печати: каждая начинается на полосу правее и закрашена цветом градиента в этой полосе, смешанным с фоном раздела. Просмотрщик PDF в Chrome (PDFium) не умеет градиент на тексте. Звёздочку списка вырезает `clip-path`, а не маска: контур в PDF остаётся векторным. Зерна на слайдах-разделах в печати нет: фон слегка осветлён серым, имитирующим зерно.
- Диалог печати и пункт меню браузера ждут метку `data-print-ready`: схемы разложены, сцены нарисованы, шрифты и картинки загружены. Пункт «Печать» в меню браузера даёт только `beforeprint` и может не дождаться трёхмерных сцен.
- Холсты сцен в печати — `image-rendering: pixelated`, чтобы Chrome печатал готовую картинку, а не стирал фон слайда.
- Градиент слайдов-разделов в печати плотный, без прозрачности. Тема хранит для него переменные: `--section-printed-background`, `--section-glow-start-color`, `--section-glow-end-color`, `--section-glow-direction`, `--section-glow-strength`.
- Однострочная команда не обрезается и не гаснет под полосами: у области без `overflow` нет обрезанных краёв.

## Сборка

- PowerPoint (`--pptx`) собирается из печатной версии в Chrome без окна: обход DOM каждого слайда, файл пишет pptxgenjs. Отдельными объектами становятся текст с переносами как в браузере, заливки и рамки со скруглением, блоки и группы схем, актёры диаграмм обмена, стрелки — кривые PowerPoint. Картинки, 3D-сцены и номер раздела — картинки, MP4 и MOV — видео, GIF остаётся GIF. Маркеры списков, номера строк кода, `$`, градиенты и тени — снимок поверх, свой на каждый шаг. Шаги `rise`, `fade`, `scale` — анимации появления, щелчок на шаг. Слайд с шагами строк кода (`lines`) становится слайдом PowerPoint на каждый шаг, как в печати по шагам: прокрутка и подсветка строк свои на каждом. Плашка `code` и `kbd` в строке — подсветка самого текста, она едет вместе с буквами. Полупрозрачная плашка смешивается с заливкой под ней, а над картинкой или видео — со средним цветом этого места на снимке слайда без плашек. Подписи мема — Impact: он есть в macOS и Windows, а у Arial другие пропорции, подпись не встанет в поле шаблона. Текст псевдоэлементов — разделитель крошек, кавычки цитаты, тире перед автором — становится буквами строки. Шрифт, который страница грузит сама, в файл не пишется: вместо него первый шрифт из списка CSS, иначе Arial, а для кода Courier New. Подпись мема — две копии: снизу с обводкой, сверху белая. Слайд — короткая сторона 7,5 дюйма, 1 px холста — 0,5 pt.
- Один файл: JS и CSS встраивает vite-plugin-singlefile, картинки, шрифты, видео и воркер ELK — data URL.
- Картинки PNG, JPEG и GIF пережимаются в WebP, не больше 3840×2160, качество 82. GIF становится анимированным WebP со всеми кадрами: на GIF демо это 1 МБ → 0,35 МБ. Если WebP вышел больше оригинала, остаётся оригинал. Кэш — `~/.cache/slidemachina/pictures`.
- Видео не пережимается. Сборка пишет размер каждого видео, файл больше 50 МБ получает совет собрать папку или zip.
- Шрифты Onest и JetBrains Mono — только латиница и кириллица. Oswald для подписей мемов попадает только в презентацию с `<Meme>`: его подключает плагин исходников в файл с мемом.
- zip: картинки, видео и шрифты без сжатия, файлы в корне архива.
- Файл под паролем шифрует staticrypt. Страница ввода пароля своя, в цветах движка. Зашифрованный файл вдвое больше обычного. Если пароль короче 14 знаков, сборка предупредит.

## Редактор в браузере

В `slidemachina dev` нажать E или карандаш на панели.

| Что | Как |
|---|---|
| Текст | Нажать на текст и печатать. Enter или уход фокуса сохраняет, Esc отменяет |
| Картинка | Перетащить файл на картинку или нажать на неё и выбрать файл |
| Блок схемы | Тянуть мышью в другую колонку или на другое место в колонке |
| Слайд | Кнопки на панели: новый слайд после текущего, копия, раньше, позже, удалить |
| Выключить | E или карандаш ещё раз |

- Под курсором — контур и плашка «Текст index.tsx:40». Над панелью — строка состояния: подсказка, «Сохраняю…», «Сохранено», ошибка.
- Правится текст без вложенных тегов. В тексте с вложенной разметкой правится каждый вложенный тег с одним текстом внутри, например `<code>` в ячейке.
- Картинка ложится в `images/` своей презентации, имя латиницей: `My Photo.png` → `images/my-photo.png`. До 80 МБ.
- Блок схемы: в файл пишется `column={n}`, строка блока переезжает на нужное место в разметке.
- Слайд меняется местами с соседом того же уровня как текст: оба сохраняют отступ. Слайд перешагивает раздел целиком и в него не заходит. Сервер возвращает новое место слайда, страница переходит к нему. Стандартный слайд раздела и обложку из `cover={<Slide>}` кнопки не меняют.
- Цвет редактора — фиолетовый движка, середина между `--accent-color` и `--accent-color-on-dark`: читается на белом и на тёмном слайде.
- Если файл изменили в редакторе кода, правка не запишется: на экране «Файл изменили в редакторе кода».
- Правки встают в очередь: следующая уходит, когда страница получила файл после предыдущей.
- Редактор не попадает в сборку.

### Панель «Мем»

В `slidemachina dev` — кнопка со смайликом на панели. Над ней открывается окно:
- поиск по шаблонам memegen, вкладки «Шаблоны memegen» и «GIF»;
- без ключа GIPHY вкладка GIF пишет, где взять ключ;
- поле для ссылки на картинку, GIF или страницу с ней.

- Выбранный мем встаёт на новый слайд сразу после текущего. Презентация переходит на него. Источник — `<figcaption>` внутри мема: серая подпись сразу под картинкой, без линии `<Source>`.
- Картинка остаётся по ссылке, сборка встроит её. Галочка «Сохранить картинку в images/memes» кладёт файл рядом со слайдами, выбор хранится в `localStorage`.
- После слайда раздела из `cover={<Slide>}` новый слайд встаёт первым в разделе. На стандартном слайде раздела панель просит открыть обычный слайд.
- Шаблон вставляется с примерами подписей из memegen: по ним видно, какое поле за что отвечает. Поля шаблона из `config.yml` становятся `data-place` и `style` подписей, сам `config.yml` не хранится. Подписи правятся на слайде (E).
- Запись — через тот же endpoint правок, что и у редактора, с проверкой версии файла. Скачивание идёт до записи, после него версия проверяется ещё раз.
- Если в `index.tsx` именованный импорт, недостающие `Meme`, `Image`, `Video`, `Source`, `Slide` добавляются в него.
- Миниатюры шаблонов браузер берёт прямо с api.memegen.link, с их водяным знаком. Поиск идёт через dev-сервер: ключ GIPHY не попадает в браузер, страницы с других адресов искать не могут.

```bash
npm create slidemachina              # в корне репозитория: новая презентация
npx slidemachina dev                 # список всех презентаций
npx slidemachina dev team-sync       # одна презентация с общей темой
npx slidemachina build --html --pdf  # все презентации и список в dist/
```

- Репозиторий — папка без `index.tsx`, где есть `theme/style.css` или папка с `index.tsx`. Папки на `.` и `_`, `node_modules`, `dist`, `theme` в список не идут.
- CSS по порядку: движок, `theme/style.css`, `style.css` презентации.
- Список в разработке: на карточке живой первый слайд в `iframe`. В сборке — картинка `cover.webp` шириной 960 px. Карточка в формате презентации: сервер читает `aspectRatio` из `index.tsx`, Chrome снимает обложку в окне размером с холст.
- Карточка разворачивается в слайд и сворачивается обратно (cross-document View Transitions). С диска переходов нет.
- Список сортируется по `<Presentation date>`: новые первыми, без даты — в конце по названию.
- Язык списка — язык большинства презентаций.
- `--html`, `--protected` и `--folder` в репозитории вместе нельзя: у каждой презентации один `index.html`.
- Под паролем обложки нет, на карточке «Под паролем».
- Список оформлен как навигатор по слайдам: фон `--navigator-background`, поля рамки (сверху 88 px, по бокам 64 px), заголовок кеглем `--heading-size`, число презентаций приглушённым текстом. Обложки скруглены на `--block-radius`, выбранная карточка обведена цветом акцента, как выбранный слайд в навигаторе. Список всегда тёмный, поэтому рамка — `--accent-color-on-dark`: у темы с тёмным акцентом она не пропадает. Цвета списка задаёт `theme/style.css` репозитория. В `examples/` своего акцента у общей темы нет, рамка фиолетовая, как у движка.
- Под названием карточки — дата, формат, если он не 16:9, и папка: «16 октября 2026 · 4:3 · team-sync». Презентацию 4:3 или 9:16 видно до того, как её откроют.

| Флаг | Файл в `dist/` |
|---|---|
| `--html`, `--protected`, `--folder` | `<папка>/index.html`, у папки рядом `assets/` |
| `--zip` | `<папка>/<папка>.zip` |
| `--pdf`, `--steps` | `<папка>/<папка>.pdf`, `<папка>/<папка>-steps.pdf` |
| всегда | `index.html` и `assets/` списка, `<папка>/cover.webp` |

Пример репозитория — сама папка `examples/`: демо и два доклада с общей темой, `team-sync` в формате 4:3. Запуск — `npm run examples`, одно демо — `npm run demo`.

## Тема

Тема — CSS-переменные в `style.css`. Классы Tailwind работают прямо в `index.tsx`: `className="text-(--muted-color)"`.

```css
@import "tailwindcss";

:root {
  --accent-color: #e8574c;
  --section-background: #1c2030;
}
```

Слои CSS: `theme, base, slidemachina, components, utilities`. Стили движка сильнее сброса Tailwind, но слабее его утилит. Обычный CSS из `style.css` сильнее всего.

## Сетка

- Размер холста задаёт `aspectRatio`. Короткая сторона всегда 1080 логических пикселей: 16:9 — 1920×1080, 4:3 — 1440×1080, 16:10 — 1728×1080, 9:16 — 1080×1920. Так кегли и сетка рамки одинаковы в любом формате, в том числе вертикальном: на 9:16 текст 40 px на ширине 1080, как сторис.
- Формат вписывается в окно, а холст растёт по свободной стороне до краёв окна, но не больше чем на треть: 16:9 — до 21:9 в широком окне и до 4:3 в высоком. Фон и блоки у края доходят до края экрана. Короткая сторона формата остаётся 1080: кегли и рамка не меняются, растёт место. `--canvas-width` и `--canvas-height` — холст, в котором раскладывается слайд: на экране живой, в миниатюрах и печати — формат (`--format-width`, `--format-height`).
- Дальше трети по краям поля цвета текущего слайда: слайд выглядит шире, а не в рамке. У тёмной картинки поля `--dark-background`, у навигатора — `--navigator-background`. `--letterbox-background` задаёт один цвет на все слайды. Телефон не переводит горизонтальную презентацию в вертикальную.
- Холст центрируется только через `translate`. Если поставить `left` и `top` в 50 %, Chrome округляет полпикселя, и у края слайда появляется серая линия.
- Поля: бока и низ 64 px, верх 88 px. Поля меряются до видимых знаков: у крошек и у каждого блока контента обрезан интерлиньяж (`text-box: trim-both cap alphabetic`).
- Все отступы меряются до видимого края: заглавных первой строки, базовой линии последней или края плашки. Под заголовком слайда — `--heading-gap`, между блоками — `--block-gap`, между пунктами списка — `--item-gap`, от блока до его подписи — `--caption-gap`. Одно правило для содержимого слайда и колонок: блок обрезан с обеих сторон, поле у него только снизу. Во flex-колонке поля не складываются, у последнего блока любой вложенности поля нет.
- В колонках первый видимый край на одной линии: край плашки кода и заглавные текста.
- Верх заголовка на линии верха логотипа. Крошки и номер стоят базовой линией в 64 px от низа.
- Логотип справа сверху, крошки слева снизу, номер справа снизу. Логотип `slidemachina` — знак со стопкой слайдов и буквой S в просвете, градиент `#7000d1` → `#007a33`. На тёмном слайде концы светлее: `#a779fd` → `#62c378`, контраст с фоном больше 5:1.
- Рамка логотипа — его `viewBox`. У логотипов движка, шаблона и примеров `viewBox` ровно по рисунку, текст переведён в контуры. Поэтому правый край рисунка стоит на линии рамки, верх — на линии верха заголовка. Пустые поля в чужом SVG движок не видит: их убирают в самом файле.
- Текст пунктов списка на линии заголовка, маркеры и номера висят в поле слева. Вложенные списки с отступом.
- Звёздочка, номер списка и `$` команды стоят правым краем на одной линии, в 14 px от текста при кегле 40 px.
- Код тоже на линии заголовка: плашка, её отступ и номера строк висят в поле. На слайде с `align="center"` плашка не висит: линии текста там нет, плашка стоит по центру целиком, номера внутри неё.

## Типограф

Библиотека typograf при сборке: неразрывные пробелы после предлогов и перед тире, тире из дефиса, кавычки, многоточие. Для `lang="ru"` правила `ru` и `en-US`, для остальных — `en-US`.

- Правит текст JSX и строковые пропсы `title`, `label`, `breadcrumbs`.
- Не трогает `Code`, `code`, `pre`, `kbd`, `samp` и строки в `{…}`.
- Не трогает технические слова в обычном тексте: `align="center"`, слова с `?`, `#` или `/` в начале (`?print`, `#3.2`, `/docs`), слова с двоеточием перед цифрой (`index.tsx:42:7`, `12:30`).
- `<code>` и `<kbd>` в начале строки получают `data-hanging-box`: плашка висит в поле, как кавычка. В пункте списка не висит, там маркер.
- Номера строк в файле не сдвигаются.
- В браузер typograf не попадает.
- Висячая пунктуация: открывающие кавычки и скобки в начале строки выходят за левый край текста. Буквы остаются на линии сетки. Работает для «, „, ", ' и (. У знака нулевая ширина, он выступает влево. В пробеле перед ним — невидимая копия знака, она возвращает ширину в середине строки. Маркеры и номера списков тоже висят: у списка отрицательный отступ слева, текст пунктов встаёт на линию заголовка. Так же висят плашка кода, номера строк и `$` команды. Колонка со списком или кодом сдвигает содержимое вправо на самый глубокий вынос: маркера или плашки. Зазор до соседней колонки меряется до маркеров и края плашки. Выключает `--hanging-punctuation: 0` в теме, типограф при этом работает. На одном слайде — `className="[--hanging-punctuation:0]"`: так в демо показано «до» и «после».
- `<Presentation typography={false}>` выключает.

## Архитектура

Репозиторий — npm workspaces:

```
packages/slidemachina/          движок — npm-пакет slidemachina
packages/create-slidemachina/   генератор проектов: npm create slidemachina
examples/                       репозиторий из трёх презентаций с общей темой
  demo-presentation/            демо всех возможностей
  python-news/, team-sync/      два доклада в фирменной теме
  theme/                        общая тема: style.css для всех, yellow-brand.css для докладов
tests/                          интеграционные тесты, их помощники и запись роликов для README
assets/                         логотип для README и аватара репозитория
docs/readme/                    ролики и снимки слайдов для README
.dependency-cruiser.cjs         правила раскладки для npm run check
.oxlintrc.json                  правила Oxlint для npm run check
```

Картинки демо — снимки самого движка: навигатор, список презентаций, печатная версия `?print`, редактор, панель разработчика, панель «Мем», миникарта. Снимки интерфейса — WebP без потерь. После заметной правки вида их переснимают в Playwright. Снимки не повторяются. Общие образцы — `glass-cards.webp` для вёрстки картинок и закат `dusk.webp` для фона.
README показывает слайды демо из `docs/readme/` и снимки инструментов из `images/` демо, без копий. После правки демо их переснимает `npm run readme-media` (`tests/readme-media-recording.ts`), около полутора минут:

- Слайды ищутся по заголовку, а не по номеру: новые слайды в демо список не ломают. Переименовали заголовок — поправьте его в начале скрипта.
- Ролики — анимированный WebP: видео из репозитория GitHub в README не проигрывает. Кадры пишет `Page.startScreencast` по CDP, пока скрипт листает демо. Скрипт оставляет не больше 30 кадров в секунду, `img2webp` склеивает их с настоящими паузами между кадрами.
- Плоские слайды сжимаются без потерь: со сжатием с потерями на ровном фоне и мелком тексте видны артефакты, а без потерь файл не больше мегабайта. 3D-сцена — `-mixed -q 95`, без потерь её градиенты весят слишком много.
- У каждого кадра серая рамка в 1 px: белый слайд не сливается со светлой страницей GitHub.
- Логотип в шапке README переключают метки `#gh-light-mode-only` и `#gh-dark-mode-only`: они следуют теме, выбранной на GitHub. `<picture>` с `prefers-color-scheme` следует теме системы, и при светлом GitHub в тёмной macOS на белой странице оставалась белая надпись.
- Нужен `img2webp` из libwebp (`brew install webp`). Chrome скрипт запускает сам. Адрес в `SLIDEMACHINA_CHROME_ENDPOINT` подключает его к уже запущенному Chrome с `--remote-debugging-port`.
Видео и GIF-мем — облёт одной сцены. Кадры сняты в Playwright с подменой `requestAnimationFrame` и `performance.now`: шаг ровно 1/30 с, круг за 8 с замыкается без скачка. Видео — VP9 с CRF 22, около 1 Мбит/с. В GIF объекты стоят в средней полосе, подписи мема лежат на ровном фоне.
В тексте демо одно правило: имена из кода — атрибуты, пропсы, классы, компоненты, пути, команды — в `<code>`, клавиши — в `<kbd>`. Названия продуктов (Chrome, Agentation, ELK) пишутся текстом.

Пакет движка публикуется исходниками TypeScript, сборки нет: CLI запускает Vite 8, Vite компилирует движок вместе с презентацией. Node 26 запускает .ts напрямую, но Node не стирает типы в node_modules: опубликованному пакету понадобится шаг сборки.

```
    meme-block/                 у мема ещё подгонка подписей и meme-font.css, который подключается только с <Meme>
  diagram-blocks/               <Diagram> с <Box>, <Arrow>, <Group>, <Focus>; <Sequence> с <Actor>, <Message>; ELK в воркере, изломы и верх групп после него
  scene-blocks/                 <Scene> с <Cube>, <Sphere>, <Text>, <Light>, <Camera>, <Move> на three.js
  slide-printing/               страницы печати
  source-editor/                редактор в браузере, его кнопки слайда и панель «Мем» (только dev)
  visual-theme/                 порядок слоёв CSS, сетка, тема по умолчанию, шрифты
server-runtime/                 всё, что работает в Node
  command-line/                 команда slidemachina: разбор аргументов, выбор варианта сборки, тексты CLI
  development-server/           настройки Vite, модули входа, маршруты, зависимости из установки движка,
                                приём, проверка и точечная запись правок редактора, слайды из редактора, сохранение файлов в images/, поиск мемов
  meme-sources/                 memegen, GIPHY и ссылки: поиск, адрес или скачивание в images/memes/, поля из config.yml, разметка мема

  presentation-build/           сборка: один файл, пароль, папка, zip, PDF, картинки, обложки

  presentation-repository/      репозиторий презентаций и страница-список
shared-between-runtimes/        чистый JS без зависимостей: общие константы, выбор ru/en и русские формы чисел, размер холста по aspectRatio,

```

Публичный компонент — файл `<имя>-component.tsx` (`code-component.tsx` — это `<Code>`) и стили `<имя>-component.css` рядом. Своя папка `<имя>-block/` нужна, только когда у компонента есть свои модули и папка группы без неё разрослась бы: так устроены `code-block/` и `qr-block/`. Остальные компоненты и общие модули лежат прямо в папке группы. Папок из одного-двух файлов и папок с единственной подпапкой нет. Индексных файлов в папках нет.

Правила проверяет dependency-cruiser в `npm run check`, конфиг — `.dependency-cruiser.cjs`. Он же запрещает циклы и модули, которые никто не импортирует:
- `browser-runtime` не берёт код из `server-runtime` и модули `node:*`, а `server-runtime` — модули `browser-runtime`;
- `shared-between-runtimes` не зависит ни от остального движка, ни от пакетов;
- `presentation-core` не зависит от блоков;
- блоки (`content-blocks`, `diagram-blocks`, `scene-blocks`) не зависят друг от друга.

### Как всё устроено

1. `server-runtime/command-line/slidemachina.ts` разбирает команду и описание сайта: одна презентация или репозиторий.
2. Vite получает настройки из `server-runtime/development-server/vite-configuration.ts`. Страницы `index.html` на диске нет: плагин `slidemachina` отдаёт её dev-серверу и сборке.
3. Страница грузит виртуальный модуль входа `/@slidemachina/entry.js` (в репозитории — `/@slidemachina/entry/<папка>.js`). Он подключает CSS движка: сначала `engine-layout.css` и `default-theme.css`, потом все `.css` из `browser-runtime/` (сначала мельче по вложенности, внутри — по алфавиту), потом `theme/style.css`, потом `style.css` презентации, потом `index.tsx`. Стили редактора — только в dev.
4. Плагин `slidemachina-slide-source` из `source-transforms/` проходит по каждому `.tsx` сайта до React: подсвечивает `<Code>` Shiki, типографирует текст, в dev ставит метки `data-source-location`. Файл с `<Meme>` получает импорт шрифта Oswald. В сборке `src` и `poster` у `Image`, `Video`, `Meme` и `background` у `Slide` с адресом `https://…` скачиваются в кэш и становятся импортом файла.
5. `mountPresentation` из `presentation-core/presentation-mounting.tsx` рендерит элемент из `index.tsx`. Горячая замена рендерит новый элемент в тот же корень, слайд и шаг остаются.
6. `<Presentation>` разворачивает разделы в плоский список слайдов, рисует все слайды сразу и ведёт позицию в адресе. Неактивные скрыты через `visibility: hidden` и `inert`: так у элементов есть размеры, а шаги можно посчитать по DOM.
7. Шаги — атрибуты `data-step` в DOM. Слайд размечает достигнутые шаги и шлёт событие `slidemachina-steps`. Код, схемы и сцены по нему ставят подсветку, фокус и позы прямо в DOM, без перерисовки React.
8. Переход — View Transitions API. Движок перед снимком старого слайда и внутри обновления раздаёт элементам имена слоёв, после перехода снимает.

Код Node написан на TypeScript без стёртых типов: Node 26 запускает .ts напрямую, `npm run check` проверяет его тем же `tsc`.

### Ключевые решения

- **Vite 8 внутри CLI.** Собирает на Rolldown и Lightning CSS, 793 млн загрузок в месяц на октябрь 2026 — больше, чем у Rspack и Rsbuild. Пользователь не видит ни `index.html`, ни конфигурации Vite.
- **Пакет публикуется исходниками TypeScript.** Все подключают движок через CLI, а значит через Vite. Шага сборки нет, ошибки показывают на исходник. Цена: `tsc` в проекте пользователя проверяет и движок.
- **Одна папка — одна презентация, вся разметка в `index.tsx`.** Структура папок и есть конфигурация. Репозиторий — те же папки рядом и `theme/`.
- **Все слайды в DOM.** Шаги считаются по DOM, схемы меряют текст, миниатюры и страницы печати — копии тех же слайдов.
- **Шаги, фокус, подсветка строк и позы сцены — атрибуты в DOM, а не состояние React.** Иначе View Transitions снимал бы кадр до прокрутки или подсветки.
- **Переходы на View Transitions без запасного пути на JS.** Браузеры — последние две версии Chrome, Edge, Safari, Firefox. Морфинг по словам — обёртки слов в `span` на время перехода: браузер снимает настоящие слова, без копий шрифта и цвета.
- **Морфинг кода — своё решение на View Transitions**, не shiki-magic-move: блоки лежат на разных слайдах.
- **Подсветка кода и типограф — при сборке, в Vite-плагине.** Shiki, грамматики и typograf остаются в Node. Правки через magic-string, карта исходников точная.
- **ELK лениво и в воркере.** Основной бандл несёт только адрес воркера. Схема просит раскладку, когда до её слайда два слайда или меньше; остальные — через 5 с простоя. Порядок и колонки задаёт разметка, ELK работает в режиме `INTERACTIVE`. ELK всегда раскладывает вправо, `down` получается поворотом координат.
- **Сцены на чистом three.js**, без @react-three/fiber. Один WebGL-контекст на все сцены: браузер сбрасывает контексты сверх ~16. Кадр копируется в 2D-холст сцены, не в `bitmaprenderer`: Chrome печатает только 2D. Тон-маппинг Neutral: ACES и AgX сдвигают насыщенные цвета бренда. Живой только текущий слайд, копии получают один кадр.
- **Печать — копии слайдов.** Кнопка и Cmd+P рисуют копии и ждут метку `data-print-ready`. Пункт «Печать» в меню браузера даёт только `beforeprint`, тогда копии рисуются синхронно. Страницы убираются после печати, по первому нажатию. В печатной версии копии видны, а сами слайды скрыты, но остаются в DOM и считают шаги.
- **Редактор пишет точечно.** Сервер разбирает файл тем же парсером и меняет только нужный кусок. Версия файла защищает правки из редактора кода (ответ 409). Endpoint принимает правки только со своей страницы и только в `.tsx` и `.jsx` сайта, не из `node_modules`, путь через `realpath`.
- **Agentation и редактор не попадают в сборку**: условие `import.meta.env.DEV` стоит внутри `lazy`.
- **Стили движка — только CSS-переменные и `data-*`-атрибуты**, без Tailwind внутри.
- **Пароль только на один файл**: staticrypt шифрует HTML, картинки в папке остались бы открытыми.
- **Один TypeScript — 7.** И в репозитории, и в шаблоне. Подсказку номера слайда через плагин tsserver убрали вместе с TypeScript 6: два TypeScript ради одной подсказки не окупались.
- **React Compiler на Rust** (`oxc-transform-react`), для dev и сборки. Версия на Babel заставила бы каждого ставить `@babel/core`. `@vitejs/plugin-react` и `oxc-transform-react` обновляем вместе. Компонент с нарушением правил React компилятор молча пропускает: найти их помогает `react({ compiler: { logDiagnostics: true } })`. `useSlideEnvironments` намеренно исключён через `"use no memo"`: кэш окружений растёт во время рендера.
- **`noUncheckedIndexedAccess` в `tsconfig.json`** вместе с `typescript/no-unnecessary-condition`. Где индекс гарантирован, ставим `!`, иначе проверяем элемент.
- **Оформление — нативные теги и классы `machina-…`, компоненты — только у блоков с поведением.** `List`, `Table`, `Columns`, `Quote`, `BigNumber`, `Caption` убрали: они только рисовали разметку. Подгонку большого числа делает слайд, шаги списков — `data-steps`, правку текста в редакторе и типограф нативные теги получают сами. Цена: колонка с блоком движка требует `<div>`, а доли колонок пишутся CSS.
- **Холст растёт под окно, копии — в формате.** С фиксированным холстом в окне другого формата всё у края слайда обрывалось на полях: блок поверх вёрстки, свечение, картинка во всю ширину, полоса прогресса. Как в reveal.js, фон и блоки у края доходят до края экрана. Миниатюры, обложки и PDF остаются в формате презентации, поэтому автор видит его в навигаторе. Рост ограничен третью: иначе телефон в вертикальном положении растягивал горизонтальный слайд в полосу 1920×4000. `--content-max-width` удалили: на широком холсте он обрывал контент раньше правой линии рамки.
- **Цветной слайд — одно семейство цвета.** На светлом цветном слайде текст — глубокий тон цвета слайда (`--text-color-on-color`), приглушённый текст, крошки, номер и полоса прогресса — тот же цвет с прозрачностью `--muted-share-on-color` (70 %). Свой серый на цветном фоне выглядел грязным и выбивался из надписи. Насыщенные акценты во весь слайд кричат, пастель слишком бледная: мягкие фоны темы выбраны из 16 образцов.
- **Цвет заливает слайд кругом.** Между двумя слайдами с плоским цветом и без общих элементов новый цвет растёт кругом от центра поверх старого, весь переход идёт `--color-flood-duration` (1 с). Смешение снимков давало тусклую середину, а плавное смешение в OKLCH между мягкими цветами почти не видно. Сам слайд становится слоем, его снимок — только фон, логотип, крошки и номер получают свои слои. Если что-то морфится, переход ведёт оно, круг поверх был бы лишним.
- **Логотип на каждом слайде.** Переходы `slide`, `cube`, `flip` двигают его со слайдом, у слайда своё место и тон логотипа, миниатюрам и печати нужна копия. Файл грузится один раз. При `morph` и `fade` логотип и так стоит на месте.
- **Полоса внизу — отступ области контента, а не её граница.** Слайд меряет полосу (`bottom-band-room.ts`) и даёт области нижний внутренний отступ: высота полосы плюс `--heading-gap`. От коробки области считаются проценты и края `machina-pin`, отступ её не меняет, поэтому замер не зацикливается. Верхней полосы нет: её отступ столкнулся бы с отступом под логотип у правых слайдов.
- **Горячая замена рисует синхронно.** Редактор считает правку готовой, когда выполнился новый модуль, а React рисовал его кадром позже: кнопка «Слайд позже» искала слайд в старом DOM. `flushSync` убрал гонку.
- **PowerPoint — объекты и анимации, а не снимки слайдов.** У Slidev два режима: картинка на слайд и `pptx-editable` с фигурами, анимаций нет ни в одном, шаги — отдельные слайды. Мы пишем объекты и анимации появления: доклад можно править и показывать в PowerPoint по шагам. pptxgenjs анимаций не умеет, поэтому после записи в каждый слайд вставляется `<p:timing>`, объект находится по имени. Строки переносит браузер, поле PowerPoint сам не переносит: другой шрифт у зрителя не добавит строку. Абзац с шагом внутри делится на поля по шагам. Повёрнутый блок — одна картинка. Снимки — в два раза больше холста, снимок во весь слайд — в размер холста.
- **Шрифты в PowerPoint — сразу Arial и Courier New.** Списка запасных шрифтов в PowerPoint нет, подмену выбирает программа зрителя, и она бралась за Times. Onest и JetBrains Mono у зрителя почти никогда не стоят, а встроить WOFF2 с переменной насыщенностью pptxgenjs не умеет. Arial уже Onest на 1–4 %, Courier New по ширине знака совпадает с JetBrains Mono.
- **Плашка в строке — подсветка текста.** Фигура по координатам браузера съезжала, как только PowerPoint набирал строку другим шрифтом. Подсветка едет с буквами, цена — углы без скругления и `kbd` без рамки.
- **Шаги кода — отдельные слайды.** Анимация PowerPoint не прокручивает текст в рамке и не меняет яркость строк. Так же делает Slidev.
- **Свой компонент в `index.tsx` — без Fast Refresh.** Fast Refresh обновляет на месте только модуль, где все экспорты — компоненты, а `index.tsx` экспортирует элемент: со своим компонентом страница перезагружалась целиком. plugin-react в `slidemachina dev` не обрабатывает `index.tsx`, правка рисуется в тот же корень синхронно. Обёртка `default` в компонент сохранила бы состояние, но Fast Refresh рисует асинхронно, а редактору нужна синхронная отрисовка. React Compiler в dev `index.tsx` не обрабатывает, в сборке обрабатывает.
- **Скругления цифр выше линии — так и задумано.** Буквы с плоским верхом стоят на линии рамки по пикселям, 0 и 2 выше на 1 px при кегле 112. Круглые знаки шрифт рисует выше, иначе они выглядят мельче.
- **Переход целиком идёт внутри холста.** Раньше сцена заливала всё окно, а `slide` двигал слайд на его ширину. На 4:3 в широком окне поля вспыхивали серым, новый слайд с первого кадра стоял в правом поле, а старый в конце пропадал из левого. Теперь сцена — фон холста, у `slide` и `zoom` слой обрезан по холсту. Куб и переворот не обрезаны: им нужна глубина.
- **Код висит в поле, как пунктуация.** Символы кода — на линии заголовка и абзацев, плашка с отступом и номера — в поле. Справа плашка кончается на линии рамки, а не выходит в поле симметрично: у кода с рваным правым краем нет своей линии справа. Опорой служит рамка, на ней же логотип, номер слайда, широкие картинки и таблицы.
- **Простую фигуру при морфинге рисует слой перехода.** View Transitions растягивает снимок по размеру слоя, и скругление растягивается с ним: у столбика 80 → 300 px углы становились овальными и прыгали при смене снимка. Снимки простой фигуры скрыты, фон, рамка, скругление и тень анимируются на `::view-transition-group` с таймингом браузерного ресайза. Элемент с текстом или картинкой внутри так не нарисовать, он морфится снимком.
- **Отметки в таблице сравнения нарисованы CSS, а не набраны символами.** В Onest галочка лежит в подмножестве символов, движок его не грузит: браузер взял бы галочку из другого шрифта. Рамка, повёрнутая на 45°, и полоска печатаются вектором и одинаковы в любой теме.
- **Висячие знаки ровняются по правому краю.** Звёздочка, номер и `$` разной ширины: по центру зазор до текста плясал бы, а «10.» и «9.» и так стоят правым краем. Номер списка рисует `:before`, а не `::marker`: зазор у `::marker` — ширина пробела шрифта, его не задать. Кавычки висят вплотную, без зазора: они часть слова.
- **Стрелка важнее `column`.** Если `column` ставит блок в колонку того, кто на него указывает, ELK сам сдвигает блок вправо. Ширины блоков в колонке тогда считаются по старой колонке, и схема разъезжается. Поэтому движок сдвигает такой блок сам, до ELK.
- **Номера строк мельче кода.** Двузначные номера кегля кода с зазором занимают 50 px из 64 px поля: на отступ плашки и зазор до края слайда остаётся 14 px. Номера в 0,75 кегля оставляют по 12–14 px на зазор до края, отступ плашки и зазор до кода. Плашка без номеров висит на 32 px, ровно на половину поля.
- **Одно скругление на все блоки.** `--block-radius` 12 px у кода, картинок, видео, блоков и групп схем. Раньше было 16, 20 и 24 px, и скругление менялось от слайда к слайду. Группа схемы и блоки в ней скруглены одинаково: отступ группы 24 px больше радиуса, вложенное скругление «внешний минус отступ» тут не работает. Миниатюры в навигаторе и обложки в списке презентаций — тоже слайды, они скруглены на `--block-radius`. Панель и редактор — интерфейс, у них свои скругления.
- **Номер строки — псевдоэлемент, а не текст.** Его не выделяет мышь, его нет при копировании. При морфинге номер не становится куском кода, который переезжает: номера привязаны к строкам, а не к словам. Номер 3 на новом слайде — другая строка, поэтому номера гаснут и проявляются со всем блоком.
- **Вертикаль — отдельный проп `valign`.** `align` уже значит горизонталь у `Presentation` и `Slide`. Пара `align` + `valign` знакома по HTML и не требует составных значений вроде `"bottom-left"`.
- **Картинку на обложке ставит порядок в разметке, а не проп.** `<Image>` до текста — слева, после — справа: что видно в коде, то видно на слайде. Картинка вынута из потока (`position: absolute` в своей колонке сетки), поэтому не растягивает строки текста.
- **С `float` содержимое слайда переходит в блочную раскладку.** Во flex-колонке `float` не работает. Поля между блоками только нижние, поэтому отступы не меняются.
- **Мемы — memegen, подписи — HTML-текст.** У memegen 211 шаблонов с координатами полей в `config.yml`, код под MIT, ключ не нужен. Готовую картинку с подписью мы не берём: её нельзя править на слайде, типографировать, печатать вектором. Поэтому подписи рисует слайд по полям шаблона.
- **Другие источники отвергли.** Tenor API закрыт 30 июня 2026. Klipy запрещает хранить файлы у себя. У Imgflip поиск платный, а подписи с водяным знаком. Reddit, r/ProgrammerHumor и Мемепедию поддерживает вставка по ссылке, своего поиска по ним нет.
- **Шаблоны не лежат в пакете.** 211 картинок весят десятки мегабайт, а нужны единицы. Шаблон скачивается по запросу в папку презентации и дальше живёт в git вместе со слайдами. Картинка — с GitHub memegen, без водяного знака, список — с api.memegen.link. Тесты подменяют оба адреса через `SLIDEMACHINA_MEMEGEN_ADDRESS`, GIPHY — через `SLIDEMACHINA_GIPHY_ADDRESS`.
- **`config.yml` читается без библиотеки YAML и только при вставке.** У всех 211 файлов одна плоская форма: ключ и список пунктов. Своё чтение — около 40 строк, сверено с PyYAML на всех шаблонах. Поля шаблона уходят в разметку подписей (`data-place`, `style`), а файл не хранится: мем настраивается прямо на слайде, без второго места с настройками.
- **Мем по ссылке, сборка встраивает.** Ссылка не засоряет папку презентации картинками, а один файл всё равно открывается без сети. Кто хочет файл рядом со слайдами, ставит галочку в панели или `--local`.
- **Тезис и блок поверх вёрстки — классы, а не компоненты.** Поведения у них нет, только вид и положение. Центр тезиса держит CSS (`:has` на области контента), края `machina-pin` — отрицательные отступы от рамки.
- **Миникарта поверх слайда и выключена по умолчанию.** Сначала она сжимала холст, но тогда слайд в разработке выглядел не так, как в зале, а выключить её было не видно как. Поверх слайда, с кнопкой на панели — по требованию.
- **Хуков три.** `onChange` для аналитики и синхронизации, `onEnter`/`onLeave` для таймеров и звука, `useSlide()` для своих компонентов. Событий DOM для чужих скриптов не добавляли: есть `slidemachina-steps`.
- **Номер раздела не растёт под название.** Раньше длинное слово увеличивало номер, и цифры плясали от раздела к разделу.
- **Подписи — дочерние элементы, а не проп `text={[…]}`.** Тег с текстом редактор правит сам, типограф обрабатывает, `<figcaption>` рядом работает как у картинки. Строки в массиве не прошли бы ни через то, ни через другое.
- **Oswald вместо Impact.** Impact — шрифт Microsoft, положить его в пакет нельзя. Oswald — такой же узкий и жирный, под SIL Open Font License, есть в `@fontsource-variable`. Шрифт memegen по умолчанию кириллицы не знает.
- **GIF из GIPHY — MP4 через `<Video>`.** MP4 в разы легче GIF, а у `Video` уже есть пауза вне слайда и печать. GIPHY — только с ключом: без него API не отвечает, бесплатный ключ даёт 100 запросов в час. Повторный запрос берётся из памяти dev-сервера.
- **Мем встаёт новым слайдом.** Встроить его в чужую раскладку слайда панель не может, а пустой слайд с мемом сразу выглядит готовым. Поэтому `Slide` получил метку места в исходнике, как блок схемы.
- **GIF печатается первым кадром**, отдельный `poster` у `Image` не делали: Chrome сам берёт первый кадр, этого хватает.
- **Одна шкала типографики.** На слайде — два начертания текста, четыре кегля и три цвета. Таблица одним начертанием, шапка только приглушена: раньше жирные названия, цветные заголовки строк и приглушённая шапка давали три стиля на таблицу. Пометке не дали линию сверху: линия — знак источника, две похожие сноски путались бы. Цитата и большое число берут межстрочный и трекинг заголовка, отступы — из шкалы.
- **Каждый блок обрезан по буквам с обеих сторон, поле только снизу.** Раньше обрезали первый блок, блок после заголовка, последний на центрированном слайде, и правила перебивали друг друга: одиночный абзац терял обрезку сверху, под заголовком выходило 114–128 px вместо 104. Поля сверху у пометки и источника складывались с полем блока над ними: 80 px вместо 40.
- **Пункты списка ближе, чем блоки.** Пункт с полем 0,4 em давал 42 px до заглавных следующего, больше `--block-gap`: абзац под списком читался ещё одним пунктом. `--item-gap` (32 px) больше строки внутри пункта (26 px) и меньше отступа между блоками.
- **Центрированный слайд стоит посередине слайда.** Раньше поле снизу учитывало крошки, а сверху нет: центр обычных слайдов был на 50 px выше, чем у разделов и обложек, и при листании контент прыгал.
- **Номер раздела подстраивается под название в браузере.** Ширину названия CSS не знает. `section-number.tsx` после загрузки шрифтов ограничивает название шириной цифр, а слово длиннее увеличивает номер.
- **Ширину источника под картинкой меряет `Source`.** Картинка с `stretch` сама считает свой размер в рамке, соседу её ширина в CSS недоступна.
- **Картинка при морфинге — снимок, а не простая фигура.** У `img` нет потомков, и проверка «всё содержимое морфится своими слоями» её пропускала: слой рисовал пустую плашку с тенью, и картинка моргала на весь переход.
- **Картинки, схемы и код плоские.** Кольцо и мягкая тень у картинок давали серую дымку на белом, а у блоков схем рамка с двумя тенями выглядела карточкой из набора интерфейса. Блок схемы — одна рамка, фокус — её цвет. Тени не нужны и в печати: там нечего заменять контуром.
- **Изломы и верх групп правит движок после ELK.** Ортогональный маршрутизатор ELK ставит вертикальный отрезок сразу у начала стрелки, настройки для середины у него нет. Отрезки в одном промежутке сдвигаются вместе, к его середине. Группу ниже соседней движок растягивает вверх: если двигать блоки, пришлось бы заново вести стрелки.
- **До правой линии схема дотягивается масштабом, а не шире колонками.** Раскладка не знает ширины слайда и одна на все размеры окна. Разница до 3 % — это 28,8 px текста вместо 28, глаз её не видит.
- **Камера подбирает кадр по точкам объектов.** Углы общей коробки сцены давали около 20 % лишнего воздуха и сдвигали объекты вниз. Точки берутся с каждого объекта, с шагом, не больше 512 на объект; у текста — коробка букв, без запаса текстуры. Подгонка — несколько проходов: перспектива нелинейна.
- **Пара одинаковых текстов морфится по словам.** Снимки одного текста разного кегля не совпадают: у блоков разная ширина и обрезка интерлиньяжа, и при растяжении по высоте «+72%» двоился. Слова — строчные коробки, их пропорции от кегля не зависят.
- **Скругление картинки при морфинге держит слой.** Снимки картинки идут без своих углов, группа слоя обрезает их и меняет радиус с тем же замедлением, что у браузерного движения. Это замедление лежит в ключевом кадре анимации, а не в её таймингах: без него радиус менялся равномерно и опережал размер.
- **Фон между светлым и тёмным слайдом меняется скачком.** Любая смесь белого и тёмного — серый кадр. Скачок стоит на середине, когда старый текст уже погас, а новый ещё не появился.
- **Холст сцены в печати непрозрачный, закат демо — WebP.** Прозрачный холст и SVG с полупрозрачным градиентом Chrome пишет картинкой с мягкой маской. На слайде одного цвета холст заливается этим цветом, а закат стал картинкой без прозрачности.
- **Нативные теги вместо ролей**: навигатор — `<dialog open>`, статус редактора — `<output>`. Навигатор открывается без `showModal()`: верхний слой вышел бы из-под масштаба холста. Esc и O закрывают его своим обработчиком.

### Тесты

Юнит-тестов нет. Четыре интеграционных теста, по одному (`workers: 1`):
- `tests/presentation-core.spec.ts` — демо целиком: листание, шаги, пауза, навигатор, переходы, морфинг, схемы, код, сцены, подписи мема, полоса прогресса, миникарта, тезис, видео в фоне, `useSlide`, панель и Agentation, правка файлов, формат 16:9 по умолчанию и 9:16 с полями, вёрстка демо на 4:3.
- `tests/presentation-build.spec.ts` — все варианты сборки, PDF, что в бандл не попали ELK, three.js, Agentation и редактор, что GIF стал анимированным WebP. PowerPoint: слайдов столько же, сколько в демо, заголовок обложки — текстовое поле, стрелка схемы — кривая, щелчков столько же, сколько шагов.
- `tests/source-editor.spec.ts` — редактор на копии демо: текст, блок схемы, картинка, кнопки слайда. Там же мемы: тест поднимает локальную подмену memegen и страницу с GIF. Панель вставляет шаблон по ссылке, с полями в `data-place` и `style`, и картинку со страницы в папку. Команда `meme` ищет шаблон и печатает разметку с `--local` и без. Сборка в один файл встраивает картинку по ссылке.
- `tests/presentation-repository.spec.ts` — репозиторий на копии `examples/`: список из трёх презентаций, обложки, тема, сборка. `team-sync` в формате 4:3: тест проверяет подпись «4:3» на карточке, обложку 960×720, страницы PDF 1080×810 pt и ошибку сборки на `aspectRatio="4:0"`.

Тесты поднимают свои dev-серверы на копиях во временной папке: 5199 для демо (копию всей папки `examples/` делает `playwright.config.ts`), 5198 для редактора, 5197 для репозитория. Настоящие файлы демо тесты не правят. Общие помощники — `tests/test-helpers.ts` и `tests/scene-sampling.ts`. Слайд демо тесты ищут по заголовку или блоку (`findSlideNumber`), а не по номеру: новые слайды в демо тесты не ломают. Agentation в сборке ищут по следам кода библиотеки (`data-agentation`), а не по слову: демо называет Agentation в тексте слайда. `npm run check` — `tsc --noEmit` с `noUnusedLocals` и `noUnusedParameters`, Oxlint с проверкой по типам и проверка правил раскладки.

## Конкуренты

Сравнение на 27 октября 2026. Звёзды GitHub — для масштаба.

- **reveal.js** (72 тыс.) — стандарт HTML-слайдов. В 6.0 есть обёртка для React `@revealjs/react`.
- **Slidev** (49 тыс.) — Markdown и Vue, релизы каждый месяц. Экспорт в PPTX снимками и объектами, MCP-сервер в `slidev dev`.
- **open-slide** (9 тыс., с апреля 2026) — ближе всех по устройству: React, `index.tsx`, холст 1920×1080, ставка на агентов.
- Marp, Spectacle, Quarto, presenterm, Touying — нишевые. Быстрее движков растут навыки для агентов, которые пишут слайды сами: frontend-slides, guizang-ppt-skill.
- mdx-deck, impress.js, remark заброшены. Motion Canvas и Remotion делают видео, не доклад.

Чего у нас нет, по пользе для доклада разработчика:
1. Заметки и окно докладчика с таймером — есть у всех.
2. Указка и рисование поверх слайда (Slidev, Quarto).
3. Навык для агента и MCP-сервер в шаблоне (open-slide, Slidev).
4. Формулы через KaTeX при сборке.
5. Пульт с телефона и показ у зрителей (multiplex у reveal.js, `--remote` у Slidev).
6. Режим чтения прокруткой с шагами (reveal.js 5). У нас есть только `?print` без анимации.
7. Картинка на весь экран по нажатию (lightbox в reveal.js 5.2).
8. Скрытые и запасные слайды, которые не сбивают номер.
9. Запуск кода на слайде, запись с камерой, автолистание — польза ниже.

Не берём: вертикальные слайды reveal.js (их заменяют разделы) и Markdown вместо JSX.

В чём мы лучше:
- Морфинг без разметки: общие элементы, слова и куски кода находятся сами. У reveal.js нужны `data-auto-animate` и `data-id`, у Slidev — только код в `magic-move`. Запрос Slidev #1527 на такой морфинг открыт с 2024 года.
- Сноски `Source` и шаги в таблице — давние открытые запросы reveal.js (#2703, #2191).
- Схемы на ELK со стрелками, которые морфятся. У остальных Mermaid.
- Встроенные 3D-сцены и типограф для русского и английского.
- Правка прямо на слайде с записью в `index.tsx`. В Slidev редактор — панель с Markdown, в open-slide правит агент по комментарию.
- Сборка в один HTML-файл, под паролем, PDF с раскадровкой по шагам, картинки в WebP.
- Репозиторий докладов с общей темой и списком с обложками.

## Ограничения и что осталось

Движок и слайды:
- Нет заметок и окна докладчика.
- Нет точных координат `x/y` у блоков схемы.
- Нет морфинга по буквам: «3.14» → «3.15» перетекает словом целиком.
- У `Code` нет явной пары для морфинга, `Code` не морфится с обычным `<pre>`.
- У `Group` нет своей `direction`.
- Обрезанный длинный код в печати гаснет под полупрозрачными полосами, Chrome пишет их мягкой маской. В PDFium выглядит верно, но правило «без мягких масок» здесь пока нарушено.
- Поля окна у слайда со светлой картинкой — цвет слайда под картинкой, а не средний цвет картинки.
- Стрелка морфится в стрелку с теми же `from` и `to` целиком: при новом маршруте старая гаснет, новая проявляется. `Message` не морфится.
- Нет двусторонних и пунктирных стрелок в `Diagram`.
- Подпись стрелки может задеть соседнюю стрелку.
- Ошибка ELK видна только в консоли, схема остаётся пустой.
- Схема не растёт больше своего размера: текст в ней всегда 28 px. Широкие схемы на 4:3 и 9:16 уменьшаются, на 9:16 сильно: схема сама не меняет направление на вертикальное.
- Кавычки, разорванные элементом (`"<b>слово</b>"`), typograf не исправит.
- `$` команды в правой колонке висит в зазор между колонками: колонка сдвигается на вынос плашки и маркеров, но не команды.
- Номера строк из трёх цифр не помещаются в поле: код с ними сдвигается вправо от линии текста на 12 px.
- Номер списка из двух цифр при кегле 40 px висит почти до края слайда: «10.» шире поля, до края остаётся около 10 px.
- Плашка кода или клавиши в первой строке выступает над линией заглавных на свой верхний отступ, около 7 px при кегле 40 px. В последней строке выступает вниз на нижний отступ, около 10 px.
- Висит только плашка в начале абзаца, ячейки или подзаголовка. После переноса строки плашка встаёт на линию текста отступом, а не буквами.
- Предел строки рядом с картинкой `float` считается по её наибольшей ширине, 40 %. Узкая картинка оставляет строкам рядом чуть больше 60 знаков.
- Колонки обычной таблицы, кроме последней, не переносят текст. Длинный текст в первой колонке расширит её.
- Источник шириной в картинку только сразу под `Image`, `Video`, `Meme` или `QR`. Под другими блоками линия на всю ширину контента.
- Длинное слово в названии раздела выступает за цифры номера: «Режим разработки», «Много презентаций».
- Висят символьные ячейки, а не глифы. Глифы JetBrains Mono стоят посередине ячейки, поэтому видимый край кода правее видимого края абзаца на 0–2 px, в зависимости от буквы. У заголовка разброс от буквы к букве больше: от 0,5 до 4 px.
- Сцена на слайде с картинкой-фоном печатается прозрачной, с мягкой маской. SVG-картинки с полупрозрачными градиентами — тоже.
- На глянцевом кубе грань под скользящим углом светлая: в ней отражается комната-окружение. Меньше лака и блика не помогает, а матовый материал теряет вид.
- `Camera` с `position` движок не подгоняет. Кадр на шаге «Камера заходит сбоку» в демо подобран числами.
- Кадр сцены с `orbit` рассчитан на весь облёт, поэтому мельче кадра без облёта.
- В колонке сцена держит место под всё, что появится на шагах: пока надпись сверху не показана, над объектами пусто.
- Блок схемы ELK может поставить ниже соседа по колонке, и стрелки войдут в него не посередине.
- 3D: нет стекла, точечного света и прожектора. Объекты сцены не морфятся между слайдами. Текст сцены всегда смотрит вдоль оси z и не отбрасывает тень. Потерю WebGL-контекста движок не обрабатывает.
- Где нет `view-transition-class`, ушедшие и новые слова гаснут и проявляются одновременно.
- Полосы над обрезанным кодом на тёмном слайде считаются от `--dark-background`. На тёмном слайде с другим фоном они чуть другого цвета.
- Вертикальный формат 9:16 не перекомпоновывает слайды: колонки, широкий код и схемы остаются горизонтальными и сжимаются.

- Верхней полосы нет, только нижняя.

3D: сейчас сцена в демо — украшение. Предложение на следующие стадии, по пользе для докладов:
1. Слои архитектуры: `<Layer>` — плоскость с подписью, стопка слоёв (интерфейс, сервис, база) и стрелки между ними, поворот по шагам.

Прочее:
- Имя `slidemachina` не занято в npm публикацией. Домен и товарный знак не проверены у регистратора. Папка проекта называется `presentation-engine`.
- Знак не копия, но мотив стопки слайдов есть у Slideshare, а название близко к `harmsm/slidemachine` (генератор reveal.js). Срочно менять знак не нужно. Для большей самостоятельности менять силуэт, а не цвет.
- `<figcaption>` вне `<figure>` — подпись блока. Браузеры его показывают, но валидатор HTML на него ругается. Обернуть блок в `<figure>` нельзя: блоки растут внутри `[data-content]`, лишний уровень сломает подгонку.
- Картинка с `float` в колонке: если она выше текста, колонка растёт на её нижний отступ. На уровне слайда отступ ничего не раздвигает: высота области контента задана.
- `valign` не работает на слайде с `float`: содержимое там в блочной раскладке.
- Картинка на обложке — только `<Image>` или `<Video>` без `stretch` и подписи. Подпись встанет в колонку текста.
- `align="right"` рассчитан на текст и обложки. Код, схемы и сцены под него не настраивали.
- Элемент с текстом, картинкой или своим фоном внутри морфится снимком: его скругление при морфинге растягивается.
- Таблица сравнения не ограничивает число решений: пять и больше колонок сжимаются.
- Блок движка прямо в `machina-columns`, без `<div>`, раскладывается неверно: код меряет место по родителю, схема и сцена растут во flex-колонке.
