# Стадия 51: чистка кодовой базы и правила оформления

## Что сделали

- В `AGENTS.md` новый раздел «File structure»: в каждом файле один прямой порядок групп — импорты; константы, типы и интерфейсы модуля; главный компонент, хук или функция, давшая файлу имя; локальные хелперы. Группа не возвращается: константа, тип или интерфейс ниже функции не объявляются. Для компонентов: хуки одним блоком (перед хуком — только те plain-колбэки, что он принимает аргументом или использует внутри), затем derived-значения и обработчики одним блоком, затем JSX; декструктурирование пропсов относится к сигнатуре. Внутри блока пустых строк нет, между блоками ровно одна. Также закреплено: один компонент — одна обязанность; комментарий говорит «почему», а не «что»; ясный английский без выдуманных терминов.

- Порядок поправлен в восьми файлах, где группы переплетались: тип `WordMatch` и состояние пульта подняты над функциями (`word-morphing.ts`, `development-feedback.tsx`), очередь правок — в константы (`source-edit-requests.ts`), тип `ListItemAction` и имена списков — в шапку (`source-rewriting.ts`), константы подписей мемов — к остальным константам (`meme-markup.ts`), правила множественного числа — над функциями (`text-language.ts`), тело команды обёрнуто в `runCommandLine()`, чтобы входной скрипт тоже держал порядок «константы — хелперы — главная функция» (`slidemachina.ts`).

- В компонентах убраны вставки derived-значений между хуками: эффект пропорций картинки поднят над derived в меме, `useLetterboxBackground` — в блок хуков слайда, `openSlide` удалён из навигатора (вместо него прямой `closeNavigator`), в окне докладчика хуки собраны в один блок, derived (`nextLabel`, `leadingNoteStep` и остальные) переехали под них, эффект прокрутки к ведущей заметке следует за шагом и слайдом через свои зависимости.

- `presentation-component.tsx`: remote-хостинг (код из панели, хранение в sessionStorage, канал хоста, соединение пульта, описание позиции для пульта) вынесен в хук `useRemoteControlHosting` в новом модуле `remote-control/remote-control-hosting.ts`. Компонент отдаёт хуку готовые входы и получает один объект для панели; тело перегруппировано по новому правилу, дублирующие явные пропсы панели убраны.

- Комментарии: удалён повторяющий код комментарий над `markReachedSteps`, переписаны две корявые формулировки (`describeApartLayers`, `rewordPairedTexts`). Пройдены все файлы с наибольшим числом комментариев — остальные объясняют «почему» и остались.

## Решения

- **Порядок задан заранее и один на все файлы.** Правило читается сверху вниз без вариантов: импорты → константы и типы → главная функция → локальные хелперы. Никаких «сначала типы и консты, потом хуки, потом снова консты». Поиск нарушений — скриптом по объявлениям верхнего уровня, после правок скрипт пуст.

- **Колбэки перед хуком — только те, что хук использует.** Требование «хуки одним блоком» без этой оговорки ломало реальные места: пульт и клавиатура принимают обработчики аргументами, редактор страницы закрывается над стабильным `runPageEdit`. Оговорка записана в правило, а не обойдена молча. Попытка собрать `runSourceEdit` через `useEffectEvent` отклонена линтером: effect event нельзя отдавать в JSX, редактор откатан к прежнему виду.

- **Перестановки не меняют поведение.** Везде либо чистый перенос объявлений, либо замена алиаса прямым вызовом (`closeNavigator` вместо `openSlide`, `slideEnvironment.isSlideDistant` вместо промежуточного деструктурирования между хуками). Единственное изменение зависимостей — эффект прокрутки заметок в окне докладчика: был по `leadingNoteStep`, стал по `slideIndex, stepIndex, slideNotes`; срабатываний больше, но прокрутка к тому же элементу — без эффекта.

- **Комментарии почти не удалились, потому что они объясняют «почему».** Правило «комментарий только когда без него не понять» в проекте уже соблюдено; массовая чистка добилась бы обратного.

## Что осталось
